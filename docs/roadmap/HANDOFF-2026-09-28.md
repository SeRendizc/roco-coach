| 个体层 | `data/roco/owned/owned-pets.json`（48 个示例个体） | **建模数据**：等级一律 60，天分/性格是种子化掷点 |

### 2.2 两处**故意不一致**（别当成 bug 去"修"）

1. **执行域 vs 检索层**：引擎的 `pets.json` / `layer-playable-48/pets.json` 是**冻结的模拟基线**（改它会让 Python
   侧的"默认路径逐比特一致"判据红），所以那 5 只（铠甲虫/音速犬/声波缇塔/十字蝌蚪/深渊蛙）与图鉴层**不同值**。
   **回答数值读图鉴层，模拟读执行域** —— 逐值登记在 `tests/roco-hke-layer.test.js` ⑥。
2. **抓包 4000 段的首领条目**：35 条里 30 条与同图鉴号的基础形态不同、5 条相同（风暴战犬就是后者）——
   "与基础形态同值"**不是**数据错误的证据（我曾据此误判过一轮，已在 §C6.327 推翻）。

### 2.3 判据的读法

- `test:unit` 是**手写清单**（`package.json`），新增判据文件**必须登记**，否则 `structure-contract` 会红。
- 判据分两层：**正向**（真产物必须过）+ **必红反证**（把产物/代码改坏，判据必须红）。改判据时**意图不许变**：
  回到最初的人类原话重写，别把数字从 A 改成 B 就算完（§C6.328b 有两次实例）。

### 2.4 派生数据的重建顺序（错一步就一堆"看着像数据错"的红）

```
npm run roco:rebuild            # 18 步，顺序写在 scripts/roco/rebuild-derived.mjs 里，每步都注明"为什么排这一位"
```

依赖：`full-catalog → 对账报告 → {别名表, 数据包 → {就绪报告, 语料}} → 个体层 → 按需 → 机制 → 队伍榜 → RAG → 先验 → RC 报告 → 轨迹 → SFT → 覆盖切片 → 奖励`
**引擎六维一变，轨迹里的回执 hash 就变** ⇒ 后面那四步必须跟着重建。
