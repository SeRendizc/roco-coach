# UI / UX 重设计规格

> 目标：**像一个能玩的策略训练场，而不是工程调试页。** 不追求官方美术，优先信息层级、可操作性、Coach 融入感。

## 1. 总体导航

从当前“选 3 只直接开战”的主结构升级为：

```text
┌──────────────────────────────────────────────────────────────┐
│ 小芽 · Roco Coach                         [小芽] [设置] [关于]│
├──────────────────────────────────────────────────────────────┤
│ 训练营      精灵盒子      阵容工坊      模拟对战      复盘馆 │
└──────────────────────────────────────────────────────────────┘
```

默认进入训练营。工程信息全部放“关于/开发者”抽屉，不在首页显示 digest/state_version/coverage JSON。

## 3. 精灵盒子

```text
┌──────────────────────────────────────────────────────────────────┐
│ 精灵盒子         [我的 86] [全图鉴 622]                           │
├──────────────┬──────────────────────────────┬────────────────────┤
│ 搜索/筛选     │ 精灵网格                     │ 当前个体            │
│              │                              │                    │
│ 属性          │ [迪莫] [迪莫] [罗隐] ...    │ 迪莫 #A014          │
│ 角色          │                              │ 光                  │
│ 性格          │ 每卡只显示：                 │ 性格：胆小           │
│ 特长          │ 名字 / 属性 / 个体标签       │ 资质：…              │
│ 可模拟程度    │                              │ 特长：…              │
│ 收藏          │ 不显示一坨六维数字           │ 血脉：…              │
│              │                              │ [查看培养建议]       │
│              │                              │ [锁定到阵容]         │
├──────────────┴──────────────────────────────┴────────────────────┤
│ 小芽：这两只迪莫里，A 更适合你当前高速 Build；原因是…            │
└──────────────────────────────────────────────────────────────────┘
```

第一层卡片只显示头像/自制符号、名字、属性、关键标签；展开才看六维、技能、数据来源。

“可模拟程度”来自当前 build 的 capability compiler，不是物种永久标签：同一只精灵换一个未知机制技能后，可能从“可模拟”变为“部分支持”。全图鉴 621/622 条始终可查看；知识、阵容与战斗三层状态分开展示。

当玩家选中暂不可精确模拟的 build 时，不直接禁用整只精灵。界面依次提供：

1. 查看缺失机制；
2. 切到同一精灵的兼容配招；
3. 仅做静态阵容比较；
4. 选择填补相同队伍缺口的可模拟替代。

## 9. 小芽人格位置

默认右下角 `✦ 小芽`；主动提示用两行以内浮条；主动聊天点开侧边抽屉；记忆单独管理且可纠正/删除。

## 10. 移动端

优先顺序：

```text
场上状态
→ Coach 短提示
→ 行动按钮
→ 后备
→ 本回合记录
```

触控目标最小 44px；重要状态采用颜色 + 图标 + 文字三重信号。

## 11. 现有验收迁移纪律

- 保留必要 `data-roco-*` 验收 hook；
- DOM 可重构，但 product-level selectors 先迁移；
- stale plan discard 必须保留；
- hidden-state guard 必须保留；
- 开发者抽屉默认关闭；
- 不因美化把真实事件文本换成模型编的动画文案。
- 已完成的多动作比较、未来后果、stale plan、RAG 证据和 48 只宿主覆盖是迁移基线，不得因重设计退化。

## 12. UI 优先级

### P0
导航、训练营、精灵盒子、阵容工坊、战斗信息层级、Coach 浮条、移动端。

### P1
养成变化预览、对比面板、局末时间线、图表、动效。

### P2
复杂形象、音效、大量装饰、仿官方美术。
