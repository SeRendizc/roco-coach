### 1.3 挖到一个之前「未知」的关键换算（本轮最重要的技术发现）

M1 把「等级→面板换算」登记为 `unknown`，这是对的。但我在社区快照里发现它
**同时存了 `base_*`（种族）与 `stat_*`（实算面板）**，452 条记录上可以精确拟合：

```
生命面板 = 1.70 × 种族 + 221      最大误差 0.00  ← 精确
物攻面板 = 1.10 × 种族 +  60      最大误差 0.00  ← 精确
物防面板 = 1.10 × 种族 +  60      最大误差 0.00  ← 精确
魔防/魔攻/速度                      有残差（个体值/性格，快照没记）
```

**为什么这件事重要**：在此之前我把站点快照的 `stats` 当面板值直接喂进伤害公式，
结果是「60 威力打 120 血」——伤害量级完全失真。修正后：425 血吃一发克制 60 威力
约 130 伤害，**整局能打 13 回合、22 次伤害**，量级才正常。

**它仍然不是官方公式**，是社区数据反推的，属可替换的假设，已在代码里标注。

### 1.4 伤害公式的处置

手游官方伤害公式没有公开来源。我把社区实现（`NRC_AI`，MIT 覆盖其代码）
做成一个**具名、可替换的假设** `COMMUNITY_HYPOTHESIS_V1`：

- 带来源、许可说明、`verified=False`
- **每个伤害事件都带 `formula_verified: false`**，上层能对玩家说明这个数字未核验
- 换掉它只需要替换一个函数

它里面三个任意选择（向下取整、最小 1、本系 1.5 倍）正是 microcase MC-010/011
存在的意义。

### 又挖到一个「未知」变「已知」

子 agent 对拍发现：`types.json` 里有 **102 条显式双属性行**，而我的加载器**把它们跳过**、
改用「两条单属性相乘」代替。两者不等价——对拍 1836 组后 **41 处不符，
全部是相乘得 4.0 而快照封顶 3.0**（例：`光系|地系` 受草系是 3 不是 4）。

**这和我把种族值当面板值是同一类错误：用推断盖住了数据本来有的答案。**
已改为以快照显式行为准，并把「相乘」降级为具名 fallback（调用方必须显式选择并标注）。

### 还修了一个客户端缺陷

桥的 `_normalize` 只透传固定字段，把服务端展开的端点专有字段**全丢了**——
最要紧的是 `limitations`（它说明这个结果**不声称**什么，例如不声称胜率）。
**丢了免责声明却留着数字，是最糟的一半。** 已改为透传未知顶层键。
