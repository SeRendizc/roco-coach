# 社区源可取性更正（2026-09-25）

> **这是对 `AGENT-TECH-INSTALL-TABLE.md` §1.1d（c）/（d）的更正件，不改历史台账原文。**
> 台账里那一版是 2026-09-21 用**单一通道**（只有 URL、不能设 header 的 `web_fetch`）测出来的，
> 结论「取不到」在**那个通道下成立**；换成能设 UA / 带 cookie / 跟跳转的通道后，
> 其中三条**可以直接取到**。逐条登记如下，每条都给了可复跑命令。

## 1. 逐条取证

### 1.1 B 站：`api.bilibili.com` 免鉴权，被挡的只有搜索

```bash
node scripts/sources/bili.mjs video BV1sdQwB5EjC --comments 30 --danmaku 200
# → status=ok 《洛克王国：世界》新生速成，无痛入门闪耀大赛！
#   洛克王国世界 | 200 条弹幕 | 30 条评论 | 字幕 none
```

实测四个读接口全部 200：

| 接口 | 结果 | 拿到了什么 |
|---|---|---|
| `/x/web-interface/view` | 200 | 标题、**desc 简介全文**、`dynamic` 动态、分P、所属合集 |
| `/x/tag/archive/tags` | 200 | 标签（`闪耀大赛` / `洛个明白` / `教程攻略` …） |
| `/x/v1/dm/list.so` | 200 | **弹幕**（观众对机制的真实反应，带视频内时间戳） |
| `/x/v2/reply` | 200 | **评论 3 087 条**（规则争议大量在评论区） |
| `/x/polymer/web-space/seasons_archives_list` | 200 | **官方 UP「洛个明白」合集全部 15 集** |
| `/x/web-interface/search/type` | **412** | 风控点在这里；加匿名 `buvid3` cookie → **200** |

台账说「`bilibili.com/opus/...` 返回验证码」——那是对的，但**那是网页版**；
读数据根本不需要走网页版。`bili.mjs` 走 api 域，并默认自带匿名 `buvid3`。

**新发现的证据**：官方账号合集里有一条 **「《洛克王国：世界》新生速成，无痛入门闪耀大赛！」**
（`BV1sdQwB5EjC`，2026-04-10，mid 626796832 = 官方号），
这比台账里那三条**用户投稿**更靠近一手——**建议按官方一手重新登记**。

### 1.3 百度百科：403 的只有网页入口

```bash
node scripts/sources/baike.mjs lemma '闪耀大赛' --sections --refs
# → status=ok  闪耀大赛  6 节  14 条引用
#   目录: 赛事介绍 / 参与方式 / 赛事规则 / 奖励系统 / 玩法策略 / 更新历史
```

| 入口 | 结果 |
|---|---|
| `baike.baidu.com/item/闪耀大赛/67778610` | **403 百度安全验证**（桌面 UA、移动 UA 都拦）——台账记的就是这个 |
| `baike.baidu.com/api/openapi/BaikeLemmaCardApi` | **200** 摘要 + 目录 |
| `wapbaike.baidu.com/item/闪耀大赛` | **200**，95KB SSR，全文在 `__NEXT_DATA__` |

所以**引用清单是白送的**——14 条来源里 17173 × 5、游侠网 × 2、三鼎梦 × 2、

### 1.4 维持「取不到」的三条，各自的真实原因

| 源 | 台账说法 | 复核补充 |
|---|---|---|
| 小红书 | 搜索页 200 无 SSR 正文 | 复现。且 `/explore` 会 302 到 `/login`。`edith.xiaohongshu.com` 的 `api/sns/web/*` 全要 `x-s`/`x-t` 签名 —— **不是「没有接口」，是「要签名 + 登录」** |
| NGA | 403 访客不能直接访问 | 复现（GBK 编码页，`ERROR: 15`）。**新发现**：`app_api.php` 返回 `{"code":2,"msg":"未定义服务"}` 而不是 403 ⇒ **接口是活的，只是服务名不对/要 App 签名**，这条路没堵死 |
| 小黑盒 | `/search` 404、API「请升级到最新版本」 | 复现，并补两点：① `/search` 的 **404 是路由不存在**（`404 page not found` 纯文本，不是风控）；② 首页 `www.xiaoheihe.cn` 是 SPA（`static.max-c.com` 的 JS 包），说明**网页版存在**，只是数据走 XHR + 签名。App UA、`os_type=android`、`app=1.3.x` 三种伪装都试过，仍拒 |

## 2. 为什么会有这轮差异（方法论）

不是站点在这几天变了，是**通道能力**不同：

| 能力 | `web_fetch`（台账那轮） | `scripts/sources/*`（本轮） |
|---|---|---|
| 设 User-Agent | ❌ | ✅ **贴吧的 SSR 开关就是 UA** |
| 带 cookie | ❌ | ✅ **B 站搜索 412 靠匿名 `buvid3` 解** |
| 跟跳转 / 看每跳 | 部分 | ✅ 抖音、黑盒短链 |
| 选编码 | ❌ | ✅ NGA 是 GBK |
| 落原始证据 | ❌ | ✅ `data/roco/raw/community/` + sha256 |

⇒ **教训**：把「取不到」记成**站点属性**之前，先确认通道是否具备「UA / cookie / 跳转 / 编码」四项能力。
本仓库后续登记来源可用性时，请连同**用了什么通道**一起记，否则结论不可复现。

## 3. 对规则口径的影响（谨慎，别越界）

`baike.mjs lemma '闪耀大赛'` 的「赛事规则」节原文含：

> 玩家最多可携带 **6 只随机精灵**进行对战，**每个系别最多携带 1 只**……
> **携带随机精灵获胜可获得额外星级加成**；若对战双方均携带随机精灵，则**只有数量多的一方按多出数量获得加成**。

- 这条**支持**人类口径「6 只 = 自己配队；随机是自愿的星级增益，不是强制 6 只随机」。
- 但**全文没有出现「魔力」二字**（实测 `grep 魔力` = 0 次）。
  ⇒ 「**4 魔力**」这一半**仍未坐实**，不许拿百科替它背书。
- 且百科本身是**社区级**来源（引用 17173/游侠/百家号等），按 `DATA-CONFLICTS.md` 标可信度，
  **不等于官方规则条文**。
