> 人类 2026-09-28 亲口点的题：「能不能吧现有 500 多只全做出来，难度多大」。
> **这份是评估，不是开工。** 按任务书 §4 的格式交付。
>

> （命令与输出都在文里），没有估算、没有百分比、没有"大约几天"。

> 配套**四份**明细（都是只读侦察的产物）：

## ① 一句话结论

**能做，但有两处必须先定，否则做出来是错的。**
547 只里 **542 只可以脚本直接生成**，**5 只**（多形态首领）需要你拍一句"按哪一条算"；
真正的成本不在数据组装（实测 **120.6 毫秒**、产出 159,380 字节），而在这三件：

1. **技能石那一桶不能直接用抓包**：抓包的 `machine` 桶是 wiki `skill_stones` 的**真子集**，
   按全 540 只口径会**少给 187 只**的技能石（314 条槽位 / 102 个名字）；
2. **抓包给 7 只灌了通用填充池**（那 7 只的技能池整组是别人的），字段校验查不出来；
3. **执行引擎只认一个写死的目录名**（改它要动禁区）⇒ 只能往现有目录里灌，
   而仓库里有 6 个测试文件把"48 只"钉死了，扩到 547 会顶红它们。

## ④ 数据源：等级信息在哪、现有 48 只为什么是空的

这一节回答任务书 §2 的第 1、2 问。

**现有 48 条是两条链拼的**（A 文档 §A-1 实测，两边 pet_id 不重叠，12 + 36 = 48）：

| 那 48 条 | 条数 | 生成脚本 | 直接输入 |
|---|---:|---|---|
| 基线 | 12 | `scripts/roco/import-snapshot.mjs` | wiki 快照的 Lua，**保留 level/stage/blood** |
| 叠加层 | 36 | `scripts/roco/build-roster-48-engine-inputs.mjs` | `tmp/roco-full-catalog.json`，**等级被裁掉了** |

**等级为 null 的根因不在源头，在导出那一步**：`scripts/roco/export-full-catalog.mjs:53-55` 只取了
`x.skill`，把 Lua 里真实存在的 `level` / `stage` / `blood` 丢掉了。上游 Lua 里是有的，实测原文：

```
learnset_5ccca003e3ca={blood_skills={{blood="普通",level=15,skill="skill_000287"},{blood="草",level=15,...
```

**所以"扩到 547 要不要重新抓数据"这个问题，答案是不用。** 本次实测（`scripts/roco/recon-547-cost.mjs`）：

| 量什么 | 实测 |
|---|---|
| 抓包 547 个 id 能接上 wiki 学招表的 | **547 / 547**（522 走 `game_id` 直连 + 20 走唯一名字 + 5 走别名表取首条） |
| 组装出来的 `native` 条目 | 7,735 条，**7,735 条全带 level** |
| 抓包 `level` 桶的技能名能换成 `skill_id` 的 | **7,718 / 7,718（100%）** |
| 组装的 learnset 去重后实际解析份数 | 262 份（wiki 里共 312 份学招表） |

**等级这条路是通的，而且源头就在仓库里**：`data/roco/raw/extracted/rocom-wiki-data/wiki_modules/Pets/data/{Catalog,Learnsets}.lua`
（739,313 字节 / 526,540 字节），压缩包 `data/roco/raw/rocom-wiki-data.tar.gz`（860,689 字节）。

**合法性口径（任务书第 2 问）**：引擎的 `is_learnable` 定义在 `roco/src/roco_env/data.py:362-364`，
口径是 `Learnset.all_skill_ids`（`data.py:133-135`）= **固有 ∪ 血脉 ∪ 技能石**，构造在 `data.py:533-540`
（**不读 level**）。生成脚本的技能池 `poolOf`（`build-roster-48-engine-inputs.mjs:109-113`）是**同一个口径** ——
所以"扩层"不需要动合法性判据，只需要把数据喂进去。**Python 那两个 pet 文件一个字都没改**（只读点名：
`roco/src/roco_env/data.py`、`service.py`；调用点 `roco/src/roco_env/env.py:481`、`team.py:90`）。

**读入路径（任务书第 2 问要的那条）**：

```
data.py:22   LAYER_DIRNAME = "layer-playable-48"        ← 目录名写死，只有一个
data.py:413-426  _layer_files(base)                     ← 只会去这一个目录里找三份文件
data.py:419      layer_dir = os.path.join(base, LAYER_DIRNAME)
data.py:464-477  读入 + 校验
data.py:488-489  与基线合并（同 id 重复即抛错，data.py:443-448）
data.py:533-540  建 Learnset
```

⇒ **结构性卡点在这里**：`_layer_files` 只认一个目录名，但它**会读该目录里的全部内容**。
所以"扩到 547"有两条路：

| 路 | 做法 | 代价 |
|---|---|---|
| 甲 | 往现有 `layer-playable-48/` 目录里直接灌 547 只 | **不动 Python（守住红线）**；但 6 个测试文件里"正好 48 只"的断言会红 |
| 乙 | 新开一个目录（如 `layer-playable-547/`） | 要改 `data.py:22` —— **踩红线，否决** |

⇒ **结论：只能走甲路。**

### 7.4 技能石这一桶：不能直接用抓包（子代理 D 实测）

这一条是本节最要紧的新发现，直接决定 B 层能不能"全自动"：

| 量什么 | 实测 |
|---|---|
| 可对照组数（48 只里能对上抓包的） | **39 组** |
| 抓包 `machine` 与 wiki `skill_stones` **完全相等** | **22 组** |
| 其中 `machine ⊊ stones`（抓包**少给**） | **16 组** |
| 交叉（两边各有对方没有的） | 1 组（4084 祭礼巨像，就是那个填充池） |
| 反向：抓包**多给**的 | **0 条**（剔掉 4084 之后，其余 38 组抓包一条都不多给） |
| 少给多少（按 48 只口径） | **44 条槽位 / 35 个名字 / 17 只** |
| 少给多少（按全 540 只口径） | **314 条 / 102 个名字 / 187 只** |
| 那 35 个名字里，抓包**全库 547 只三桶一次都没出现**的 | **13 个**（掠影 / 引力偏转 / 离魂术 / 惊鸿一瞥 / 信息素 / 仰望夜空 / 暴打 / 广播 / 量子涨落 / 分光 / 迁飞扩散 / 拖拉机 / 月影交错） |

⇒ **两条结论**：
① **不能**拿抓包 `machine` 当技能石用（会少给，且少给的 187 只是实打实的）；
② 少给的那 13 个名字**在抓包里根本不存在** ⇒ 疑似版本差，但**没有版本号可证 ⇒ 记「未确认」**，
   不许写成"抓包漏收"。`skills.json` 的 `category` 只有「特性/攻击/状态/防御」四种，
   **不区分技能石与技能机** ⇒ 也没法从技能表反推。
③ 顺带查清：`SkillStoneTopics.lua` **不是**第二张可学清单（479 行 = `skill_stones` 并集，
   双向差集 0；每行只登记"做哪个课题开这颗石"）⇒ **补不了配招**。

### 7.3 一个必须记下来的数据坑（不是我们编的，是抓包那边的）

抓包把**同一个通用技能池复制给了 7 只互不同族的精灵**：
`4083 黑猫密探 / 4084 祭礼巨像 / 4085 雪影冰灵 / 4086 棋契陛下 / 4087 奇梦咪 / 4101 暮风隐者 / 4102 淤泥乌泽`
（C 文档实测：它们那套 48 条技能**与绿翼鸟线 3276/3277/3278 逐字相同**，而这 7 只在图鉴里各有自己的配招，
与抓包 `level` 桶**交集只有 0–5 条**）。
⇒ **这不是"抓错了一只"，是抓包侧发了一个填充池**；而且**光靠字段校验查不出来**（身份字段全对）。
C 文档给的两步检测（跨族同池 + wiki 复核）扫全 547 只命中 2 组，第二组经复核是误报，
**所以污染面确定为 7 只**。
