### D. 题目集本身（人类质疑：质量一般、要不要再出）

- 人类原话：「**这个题质量也一般般，是不是该再出点，有的应该优化，这是用来训练模型的还是干啥的**」。
- **它现在的用途（如实）**：`scripts/eval-live-s04.js` 的 49 例是**评测/回归集**，用来量
  「工具选择正确率 / 该查没查 / 不该查却查 / 答复有据」四项指标，并用来做**提示词与政策的 A/B 取舍**
  ——**不是训练集**。
- **训练/轨迹是另一条线**：`tests/evals/agent-trajectories-v1.jsonl`（6048 条、7 个规则 arm）+
  `…-model-v1.jsonl`（4B 模型臂），走回放判据；训练数据由 `scripts/roco/build-trajectories.py` 一类产出。
  而且人类已定：**不加训，用检索 + 工具补**。
- **我的建议（待人类定）**：
  1. 这 49 条**升级而不是废弃**：每题按人类口径补三个标签（**问模型几次 / 问引擎几次 / 该检索什么**），
     并把 C3 那类"题目过时"的归档；
  2. **再出一批**（人类说"该再出点"）：重点覆盖 ① 规则知识库检索（c21 那一大类）、② 博弈/不完全信息
     （不许知道对手动作）、③ 600 只规模下的检索（图鉴/学习表/相性）、④ 跨页面（养成）与"该说不知道"的边界；
  3. 出题时**先写清"这题考什么"**（考检索触发？考不编？考博弈边界？），否则又会变成一批质量一般的题。

## 3. **c21 重点**：把「规则知识库预制进 RAG」（人类点名）

人类原话：「这一大类规则类问题建议问模型，并**预制相关规则知识库进 RAG**，快速查询判断」。

**这意味着什么（我的理解，待人类确认）**：
1. **规则类问题**（机制、术语、相性、消耗/威力/优先级、判定细节…）**不该靠模型记忆**，也不该逐句问引擎等人算；
   应当有**一份预先建好的规则知识库**放在检索端（RAG），问的时候**先检索、再由模型判断与解释**。
2. 「**快速**」是硬要求：检索要快（本地、预建索引），不能每次都现算。
3. 这与"不加训、用检索+工具"一脉相承。

**现状盘点（我下一步要做成清单）**：
- 已有的规则知识源：引擎**术语表 54 条**（`data.terms_*`）、**相性表**（type chart）、
  **tactic/rule 知识卡**（`search_rules` 的来源）、图鉴/学习表（622 只，`query_rules`）。
- 待盘点：这些各有多少条、覆盖哪些机制、**缺哪些**（例：谁能"最全地解释一条机制"）、
  检索延迟多少、能不能**预建索引**（而不是每次问引擎现算）。

**判据（我建议这样钉）**：
- 正向：一批**规则类问句**必须走"检索 → 模型解释"，且答案里的每个规则事实都能**回指到知识库条目**；
- 反证：把知识库里某条规则删掉/改掉，对应答案必须变（证明它真在检索，而不是模型记忆）。

## 4. Agent 技术工作清单（**人类点名要做，交给下一个对话，不许跳**）

> 来源：这轮对话 + 目标书。带 ★ 的是人类**这一轮明确点名**的。

1. ★ **模型 + RAG 成为主形态**：多数题目"先检索再判断/解释"，而不是"从包里读"或"只让引擎算"。
2. ★ **预制规则知识库进 RAG**（c21）：见第 3 节，含"快"的要求与判据。
3. ★ **PVP 公平/博弈**：不许预知对手动作、不许读对手非公开数据；写成显式规则 + 判据（B1/B2/B3）。
4. ★ **小模型快速响应**：决策题问模型，但**4B 级就够、要保证速度**（c05）⇒ 与"3 秒响应"目标一致。
5. ★ **两栏计量**：评测按「问模型几次 / 问引擎几次 / 检索什么」标注（A3、D 节建议）。
6. ★ **题目集升级 + 再出一批**（D 节），并先写清"这题考什么"。
7. **判定回路**（目标书交付 1）：`ROCO_JUDGE=shadow` 只记录不改行为 → 把 (甲)/(乙) 之争变成一个数 → 按实测收敛。
   现状：已量化；欠调用 16 条中 13 条经证实是"旧标准答案过期"、0 条是编。
8. **自我纠错**（目标书交付 3）：agent 循环里"错一次给一次纠正"已在；后续要扩到多步任务的纠错。
9. **跨工具多步**（唯一未开工项）：c25/c27 那类"一句话问两件事"，只许针对性试，且必须回归 49 例确认不抬高不该查率。
10. **上下文边界**（c09）：养成/跨页面问题要么补资料，要么明确"不在对局上下文答"。
11. **全量 agent 技术调研 + memory/RAG 分开做的专章** → 见 `docs/roadmap/AGENT-TECH-SURVEY.md`（含本仓现状 file:line、缺口、落地判据与反证；§4 是"先做哪三件"）。
