## 3. 多 RAG 库设计（口径 4）

### 3.1 库清单（按**真源**分，不按数据类型分）

> 凡是"真源不同"或"谁能改它"不同的，就必须分开——否则 debug 时无法判断是哪一侧错了。

| 库 | 名字 | 真源（唯一） | 内容 | 更新方式 | 独立性（凭什么能单独 debug） |
|---|---|---|---|---|---|

### 3.2 每个库的「单库 debug 方法」（口径 4 的核心要求）

**统一入口**（建议加到 `package.json` 的 scripts，**不改现有脚本**）：

```bash
node scripts/roco/rag-debug.mjs --lib rules   --q "换宠要花一个回合吗"   # 只查 L1
node scripts/roco/rag-debug.mjs --lib catalog --q "喵喵的种族值"          # 只查 L2
node scripts/roco/rag-debug.mjs --lib typechart --check                  # L3 全组合对照引擎
node scripts/roco/rag-debug.mjs --lib tactics --explain                  # L4 每条卡的 authority/inspiration 来源
node scripts/roco/rag-debug.mjs --all --q "..." --trace                  # 跨库（§3.4）
```

每个库**必须能单独回答这四问**（缺一个就不算"可 debug"）：

| 问 | 输出字段 |
|---|---|
| 这个库里**有多少条**？ | `count`（按 `record_kind` 分解） |
| 每条**从哪来**？ | `source_id` + `pointer` + `confidence`（L1 才有） |
| 这次查询**命中了哪几条、为什么**？ | `hits[]`，每条带 `score` + `matched_fields`（名字/别名/正文，对应 `src/coach/rag-index.js:170` 的字段级 BM25） |
| **没命中时是"没有"还是"我不知道"**？ | `abstain_reason`（`src/coach/rag-index.js:76-80` 的三种理由之一）——**这一条最重要**：`NO_MATCH` 与 `UNRESOLVED_IDENTITY_CONFLICT` 是完全不同的两件事 |

**L3 的特别要求**：属性相性库是**穷举可验证**的（6 属性 × 6 属性），所以它的 debug 不是抽样而是**全矩阵对照引擎**。任何一格不一致都是硬错误。现在这份对照**未找到**（`grep` 未找到"全矩阵对照引擎"的判据）——**这是一个可以直接补的空白**。

### 3.3 边界红线（写进 `libs.json`，由 T7 的判据守住）

1. **L7（对局历史）与 L8（玩家个体）不进"规则检索"路径。** 它们可以被**别的通道**读（陪练的账本、阵容评估），但**规则问句的检索结果里不许出现**。
2. **L4（战术卡）与 L1（规则）必须能区分。** 战术卡是**本仓自己写的**（`authority: engine.js`），它**不是洛手规则**。引用时必须能看出这是"本仓的解释"还是"游戏的规则"。
3. **L1 内部的置信度不许在合并时被抹平。** 一条 `ENGINE_HYPOTHESIS` 的规则和一条 `RECORDED_IN_GAME` 的规则**即使文本一样，也必须能区分**——输出里必须带 `confidence`。
4. **玩家能改的只有 L8 和 Memory；L1–L6 只有人类/台账能改。**（对应 §3.1 的"谁能改它"那一列。）

### 3.4 跨库检索策略（先查哪个 / 怎么合并 / 怎么给引用）

**先查哪个 —— 不要引入新的路由，复用已有的两套顺序：**

| 顺序来源 | 位置 | 作用 |
|---|---|---|
| `policyFor` 的硬政策 | `src/coach/runtime.js:257-294` | 决定**第一个**要查什么（图鉴 `:264-265`、术语 `:268`、学习表 `:270-271`、对比 `:273-276`、换人 `:279`、相性 `:280`、战术 `:281,293`） |
| `evidenceNeeds` 的来源族 | `src/coach/runtime.js:785-794` | 决定**要几个**来源（`EVIDENCE_FAMILIES`，`:756-762`）——一句话问两件事时靠它 |

**建议的库查询优先级（写进 `libs.json`，可配置）**：
`rules(L1) → catalog(L2) → term(L5) → typechart(L3) → tactics(L4) → conflict(L6)`
**理由**：规则与图鉴是"事实"，术语与相性是"语义"，战术卡是"解释"，冲突库是"弃答闸门"——**把冲突库放最后是因为它的作用是"否决"而不是"补充"。**

**怎么合并（三条纪律）：**
1. **不跨库混排成一条列表。** 输出按 `lib_id` **分栏**（`results: {rules: [...], catalog: [...]}`），**每一栏内部**才排序。理由：跨库打分不可比——L1 的 BM25 分和 L4 的卡片分不是同一个尺度，混排会让"分数高的来源"变成噪声放大器（这与 `src/coach/rag-index.js:12-14` 已经写下的教训同源："**绝不允许把不相关但等级高的记录顶上来**"）。
2. **同一库内**才用 RRF/加权融合（`src/server/semantic-server.js` 已有的 RRF 形状，`k=60`）。
3. **冲突即弃答**：L1 与 L6 结论冲突时，按 `ABSTAIN_REASONS.UNRESOLVED_IDENTITY_CONFLICT`（`src/coach/rag-index.js:78`）如实弃答，**不许挑一个更顺眼的**。

**怎么给引用（每条结果必须能这样打印）：**
```
[L1/rules] EV-PVP-STANDARD-TEAM-SIZE · RECORDED_IN_GAME · pack.json#/… · 命中字段: name
[L2/catalog] pet::pet_000225 · pack.json#/pets/225 · 命中字段: alias(喵喵)
[L4/tactics] tactic:switch-turn · knowledge/tactics.json#/… · authority: engine.js（本仓解释，非游戏规则）
```
⇒ 三个字段缺一不可：**库 id + 真源出处 + 置信/权威级别**。

## 4. Memory 三类规格（人类补充二）

#### 第 2 类 · 玩家操作习惯与水平

| 项 | 规格 |
|---|---|
| **记什么** | **习惯（habits）**：可数、可复算的**倾向**，例如"残血时选择攻击 vs 换宠的比例""是否常忽略防御回能""平均每局用几次道具""是否在提示后才改变选择"。**每条习惯必须带 `n`（样本数）与 `evidenceIds[]`**。<br>**水平（skill）**：**分维度的读数**，而不是一个总分——建议至少四维：**机制理解**（quiz 维度，`src/coach/memory.js:409-410` 已有 `QUIZ_MASTERY`）、**迁移能力**（`src/coach/memory.js:174` `transferAssessment`）、**课程进度**（`src/coach/teacher-review.js:725` `checkLearningProgress`）、**决策质量**（`journal` 的 `decision.reasonable` 比例，`src/coach/memory.js:62`）。每一维**必须带证据 id 与样本数**。 |
| **真源** | **玩家自己的操作**（`journal` 的 `decision` / `hint` / `dismiss` 行，`src/coach/memory.js:55,62`；游戏侧的合法行动与结果来自 `src/coach/game-adapter.js` 的对局事件）。**显式排除**：模型对玩家的印象、外部攻略、规则库。 |
| **生命周期 / 过期** | **习惯**：滚动窗口（建议**最近 20 局或 30 天**，两者取先到），**样本数不足（建议 n < 5）时不许对外断言**——这一条要写死，否则就是"用两次操作给玩家贴标签"。<br>**水平**：**只许随新证据更新，不许随时间衰减**（学会的东西不会因为一周没玩就忘——这条与"情绪假设"的 TTL 逻辑刻意相反，必须在代码里写明理由）。 |
| **谁能改** | 玩家：**能删依据**（删掉某条 `decision` 行 ⇒ 由它算出的习惯/水平必须一起失效，这正是 `purgeDerived`（`src/coach/memory.js:421`）已有的语义）。<br>**玩家不能直接改读数**——因为它是**派生量**，不是玩家说的话（`correctMemoryItem`（`:467`）的规矩原话："**只能纠正玩家自己说过的条目**"）。 |
| **失败模式** | ① **样本太少就下结论**（最严重：两局就贴"他喜欢硬刚"）；② **过拟合最近一局**（只用最后 1 局）；③ **把"被提示后的正确"算成"会了"**（本仓已经防住：`src/coach/memory.js:139` 的 `basis` 明说"只统计**没被提示的独立行动**"，`src/coach/teacher-review.js:850` 的 `check.improved === null` 时**不记**）；④ **把水平当事实对外宣称**（现在 `memory.js:139` 的 label 是"教过但没学会"，**这是推断不是事实**，必须带 `confidence`）。 |
| **怎么验证"真的记住了"** | **正向**：给同一类局面喂 N 次相同选择 ⇒ 习惯读数**必须收敛到那个方向**，且 `n` 与 `evidenceIds` 对得上。<br>**反证 ①**：把 N 次里的证据删掉一半 ⇒ 读数**必须变**（证明它真在算，不是在缓存一个标签）。<br>**反证 ②**：把样本数阈值从 5 改成 1 ⇒ **必须**出现"用一次操作就断言习惯"的用例被抓住（证明阈值不是装饰）。 |
| **怎么验证"该记没记"** | 造一批**明确的操作模式**（如连续 8 次在残血时选择换宠），断言习惯读数**必须**出现这一条；**没出现就是"该记没记"**。 |
| **⭐ 是否适合用 agentic RL / 策略学习？** | **⚠️ 这一格已被人类口径更正（见 §1.1c）：训练/RL 是允许且要做的，"不加训"作废。** 以下是**更正后**的判断，**护栏见 §5**。<br>**适合，但要分两半做：**<br>① **"习惯"这一半适合做策略学习 / 行为建模**——它本质就是**从交互轨迹里学一个偏好模型**，`journal` 的 `decision` 行（`src/coach/memory.js:62`）与 `tests/evals/agent-trajectories-v1.jsonl`（6048 条轨迹 / 288 题 / 7 臂）**已经是现成的数据底座**。<br>**但有一条硬门槛（§5 第 1 条）：每个输出必须能回指到原始事件**——所以**不能**只丢一个不透明模型出来，必须是"模型打分 + 可回指的统计特征"，**删掉依据 ⇒ 结论必须变**（`src/coach/memory.js:421` `purgeDerived` 的语义）。<br>② **"水平"这一半不适合直接上 RL，应该继续用可解释统计**——因为"水平"要**对外说话**（"你这块还不熟"），而**唯一可靠的奖励是对局结果，它混淆了"习惯"与"水平"**（赢了不等于这个习惯好）。用 RL 学一个"水平"读数，会得到一个**说不出理由的分数**，**直接撞 §5 第 7 条红线（禁止无出处的综合评分）**。<br>③ **最稳的路径是"先数据、后训练"**：先把轨迹导出成带标签的数据集（§5 第 3 条），用**引擎真值**（事件/判定/规则）当标签，**再**考虑训一个小的判定模型（比如"该不该调工具"这类判定问题——本仓已有 `ROCO_JUDGE=shadow` 的量化回路，`src/coach/runtime.js:811-829`，**它天然产出带标签的样本**）。<br>**⇒ 结论：现在就可以开始做，但第一节必须是"把数据做出来 + 把评测立起来"（§5 第 2、3 条），不是直接开训。** |

| 项 | 规格 |

### 4.2 三类共同的判据（一个文件就能钉住，零依赖）

新建 `tests/roco-memory-three-classes.test.js`，至少含：

5. **三档时长不许被统一**：`REFUSAL_TTL_MS`(6h) / dismiss 窗口(7天) / `MOOD_TTL_MS`(30min) **必须互不相等**，且各自有独立判据。**反证**：把三者改成同一个值 ⇒ 红（**这条判据存在的理由**：统一时长是这类系统最常见的静默退化）。

## 5. 训练 / RL 的护栏（人类要求：**尽可能避免缺点**）

> **口径（§1.1c）**：训练 / agentic RL **是允许且要做的**；附加要求是「**尽可能避免缺点的情形下做**」。
> **这一节不是劝退，是准入门槛**：**过不了这九条门槛的训练，不进产品。**
> 每条都写成「**护栏** → **本仓现状（file:line）** → **判据（含反证）**」。

### 5.1 九条护栏

#### 护栏 1 · 奖励 / 标签必须来自**引擎真值**，不许用模型自己的输出当监督

| 项 | 内容 |
|---|---|
| **为什么** | 用模型输出当监督 = **自我强化幻觉**：错误会被固化、还会被放大。这是"缺点"里最贵的一种。 |
| **本仓现状** | ✅ **底子很好**：引擎是**纯确定性规则机**（`roco/src/roco_env/env.py` / `effects.py` / `plan.py`），伤害/胜负/合法性都由它算；轨迹集的纪律第 2 条原话——"正文只用回执里**真的出现过**的字段生成，**不从任务期望抄答案**"（`tests/evals/agent-trajectories-v1.manifest.json` 的 `disciplines`）；回执里带 `state_version` 与 `latency_ms`（`src/coach/toolbox.js:653`）。<br>⚠️ **风险点已定位**：`src/coach/runtime.js:1191` 的 `facts` 白名单把 `textFacts` / `publicState` / `toolTrace` 一起放行，**如果拿"模型输出过守卫"当正样本，就会把"守卫没抓到"当成"正确"**——守卫自己的 scope 写得很清楚：`'Narrow numeric/citation/certainty guard; **not a proof of all natural language correctness**'`（`src/coach/runtime.js:1241`）。 |
| **判据（含反证）** | **正向**：训练数据的每条标签都能追到①引擎事件（`roco/src/roco_env/events_text.py` 的事件文本 / `service.py` 的回执字段）②台账条目（`data/roco/evidence/rule-evidence-ledger.json`）③人类实机报告（`data/roco/evidence/user-in-game-reports.json`）三者之一。<br>**反证 ①**：把任意一条样本的标签替换成"模型自己的回答" ⇒ 数据构建**必须红**。<br>**反证 ②**：把 `checkGroundedAnswer` 短路成 `{valid:true}` 后重新生成标签 ⇒ 标签集合**必须发生变化**（如果不变，说明标签根本不是守卫产出的，这条护栏就是空话）。 |

#### 护栏 2 · **评测先行**：训练前先有 held-out 判据与回归集，训练前后都要量数字

| 项 | 内容 |
|---|---|
| **为什么** | "感觉变好了"不是证据。人类要求"避免缺点"，而**缺点只有在数字上才看得见**。 |
| **本仓现状** | ✅ **现成的评测资产很厚**：49 例金标（`scripts/eval-live-s04.js:149` 起，c01/c21/c25/c27 分别在 `:149,:171,:177,:179`）；轨迹回放 **6048 条 / 288 题 / 23 world / 7 臂 / 11 条 checkable**，且**反证臂真的会红**（`stop_now` **0.667**、`stubborn` **0.75**、`no_rules` **0.75** —— `tests/evals/agent-trajectories-v1.manifest.json` 的 `arms_summary`）；RAG 侧 45 条 held-out + 13 判据 + 6 必红反证（`tests/roco-rag-eval.test.js:1-25`）；判定回路 `ROCO_JUDGE=shadow`（`src/coach/runtime.js:811-829`）。<br>⚠️ **缺口**：**没有"训练前后对照"的固定产物**；且金标正在被人类重做（§2 行 T8），**在 T8 落地前，任何训练都不该启动**（否则在拟合一份没人认过的答案）。 |
| **判据（含反证）** | **正向**：每次训练必须产出一份 `reports/roco/train/<run-id>.json`，含 `{before, after}` 两组数字，覆盖：49 例、轨迹 `replay`/`stop_now`/`no_rules` 三臂、RAG 45 条 held-out、**以及 `docs/roadmap/AGENT-TECH-SURVEY.md` §6 那九条取证命令全绿**。<br>**反证 ①**：`before` 缺失 ⇒ **必须红**（没有基线就没有"变好"这回事）。<br>**反证 ②**：把 `replay` 臂的判定短路 ⇒ `after` 的通过率会上升 ⇒ **判据必须能发现这个上升是假的**（做法：同时报告 `replay` 臂与 `stop_now` 臂，**假的提升会表现为两臂同时上升**——真提升只会在 `stop_now`/`no_rules` 这类"该会"的臂上出现）。<br>**反证 ③**：`before`/`after` 用**同一份**评测脚本（不许各写一份），脚本 digest 必须写进产物。 |

#### 护栏 3 · 数据源只用**可回查的记录**，每条样本能追到原始事件

| 项 | 内容 |
|---|---|
| **为什么** | 追不回去的样本 = 无法审计 = 无法发现"缺点"。 |
| **本仓现状** | ✅ `tests/evals/agent-trajectories-v1.manifest.json` 的 `disciplines` 已定四条：①轨迹只记公开输入与**回执摘要**、全文不落盘、摘要**剔除延迟**；②正文只用回执真出现过的字段；③**失败轨迹原样保留**（`stopped` 记明原因），不做"重试到成功"的清洗；④**产物确定性**（无时间戳、无 HEAD、无随机）。<br>✅ Memory 侧已有级联删除语义（`src/coach/memory.js:421` `purgeDerived`，`:149` `deleteMemoryEvidence`）。 |
| **判据（含反证）** | **正向**：每条训练样本带 `{sample_id, source: 'trajectory'\|'match'\|'ledger', source_id, rulesVersion}`，且 `source_id` 能在对应产物里查到。<br>**反证 ①**：造一条 `source_id` 不存在的样本 ⇒ 构建**必须红**。<br>**反证 ②**：删掉源轨迹里的一条 ⇒ 由它派生的训练样本**必须一起消失**（级联）。把 `purgeDerived` 短路 ⇒ 红。<br>**反证 ③**：产物里出现挂钟时间戳/随机数 ⇒ **必须红**（照 `GATE_DEFINITIONS.no_clock` 的既有做法）。 |

#### 护栏 4 · **红线不动**：伤害/胜负永远引擎算，模型只解释

| 项 | 内容 |
|---|---|
| **为什么** | 这是本仓最不能碰的一条。模型一旦"自己算结论"，就从"教练"退化成"会编的解说员"。 |
| **本仓现状** | ✅ 引擎是唯一计算源（`roco/src/roco_env/env.py` 的 `step` / `plan.py`）；服务端守卫 `src/coach/runtime.js:1186-1241` 已经在**代码层**判"数字有没有出处"；线上竞技 PVP 赛中**不提供**战术分析（`src/coach/runtime.js:106`）。 |
| **判据（含反证）** | **正向**：产品路径上**没有任何**由模型产出的伤害数/胜负数（只有转述引擎回执）。<br>**反证 ①**：把 `checkGroundedAnswer` 短路 ⇒ `unsupported-number` 那一族用例**必须红**（现有落点：`tests/roco-server-side-guard.test.js`、`tests/evals/claim-honesty.test.js`）。<br>**反证 ②（训练专属）**：训练目标里若出现"让模型直接输出伤害值"的样本 ⇒ **数据构建必须红**。 |

#### 护栏 5 · 训练**不得**产出胜率/评分这类编造数字

| 项 | 内容 |
|---|---|
| **为什么** | 胜率/综合评分是**最容易被玩家当真的编造数字**，而且本仓明确不给。 |
| **本仓现状** | ✅ 已有的判据形状：轨迹 `checkable` 里有 **`must_not_claim_winrate`**（`tests/evals/agent-trajectories-v1.manifest.json`）；`tactic:confidence` 卡的原则原话——"枚举给出的是在特定对手行动集合与权重下的**局面评分，不是胜率**"；`src/coach/team-compare.mjs:1995` 与 `src/coach/opponent-belief.mjs:1221` 都写着"**只重排已有字段，不新增任何数值、不写胜率**"。 |
| **判据（含反证）** | **正向**：训练产出的**任何**面向玩家的文案里，`胜率/赢面/%` 这类词**零出现**（除非来自引擎已登记字段）。<br>**反证**：把 `must_not_claim_winrate` 的判定短路 ⇒ 该族用例**必须红**；**训练后重跑，若这一族通过率下降 ⇒ 该次训练不许合并**。 |

#### 护栏 6 · **灰度 + 回滚**：模型更新要有版本号与开关，能一键退回上一版

| 项 | 内容 |
|---|---|
| **为什么** | 训完直接换 = 没有退路。人类要"避免缺点"，**回滚能力本身就是避免缺点的一部分**。 |
| **本仓现状** | ✅ **开关文化已经很成熟**：`ROCO_LOCAL_MODEL`（`src/coach/local-model.js:88`）、`ROCO_JUDGE`（`src/coach/runtime.js:811`）、`ROCO_CODEX_LOOKUP`（`:738`）、`ROCO_COVERAGE_FORCE`（`:797-799`）；**模型身份有判据**（`tests/evals/roco/model-arm-identity.test.js`、`tests/roco-model-wiring-honesty.test.js`）；适配器带版本目录（`.models/adapters/qwen35-4b-tool-v1 … v4`）；云臂可回放（`src/coach/cloud-replay.mjs:36-38,89`）。<br>⚠️ **缺口**：没有"**训练版本号 + 一键回滚**"的单一开关（现在是路径/目录层面区分，没有面向"这次训练"的版本语义）。 |
| **判据（含反证）** | **正向**：每个训练产物带 `{run_id, base_model_digest, adapter_digest, trained_at, eval_report}`；切换用一个开关（建议 `ROCO_COACH_MODEL=<run_id>`）。<br>**反证 ①**：把开关设成一个不存在的 `run_id` ⇒ **必须报错并停用模型**（fail closed），**不许静默回落到某个默认版本**。<br>**反证 ②**：回滚到上一版后，`replay` 臂必须回到回滚前的数字（证明回滚是真的）。 |

#### 护栏 7 · **不许拿训练替代工程**

| 项 | 内容 |
|---|---|
| **为什么** | 人类原话骂的是"开倒车"，不是"不许训"。**该做的检索、工具、守卫、判定回路，用"训一下"糊过去就是开倒车。** |
| **本仓现状** | ✅ 分工已经很清楚：**规则查询走工具**（`src/coach/toolbox.js:779-786` `query_rules` → 引擎）；**战术检索走 RAG**（`src/coach/toolbox.js:440` → `src/coach/strategist.js:66`，待接 `rag-index`）；**该不该调由代码判**（`src/coach/runtime.js:255-294` `policyFor`，注释写明"模型『该不该调』**只有 50%**"）；**事实守卫在代码层**（`:1186`）；**判定回路已成数**（`:811`）。 |
| **判据（含反证）** | **正向**：任何"训一下试试"的提案，必须**逐条说明它替代不了 §2 表里的哪一项**；且**训练不得修改** `policyFor` / 守卫 / 检索的判据。<br>**反证**：把某条硬政策（如 `policyFor` 的一条正则）删掉、指望模型学会 ⇒ 对应的 `tests/roco-ask-coverage.test.js` 用例**必须红**。<br>**分工原则（写死）**：**能用代码判的永远用代码判**；模型负责**解释、措辞、判断边界**这三件事；**训练只改模型的判断，不改系统的判据**。 |

#### 护栏 8 · **玩家画像（水平/习惯）**：每个输出必须能回指原始事件，**禁止**无出处的胜率/综合评分

| 项 | 内容 |
|---|---|
| **为什么** | 这正是 §4 第 2 类与 RL 的交汇点，也是最容易出"缺点"的地方（给玩家贴标签）。 |
| **本仓现状** | ✅ 可回指的基础已有：`src/coach/memory.js:449` `memoryItems` 每条带 `source`/`time`/`derived`/`evidenceIds`；`:421` `purgeDerived` 级联；`:139` 的 `basis` 明说"**不等于真正掌握**"；`:409-410` `QUIZ_MASTERY = {minIndependent:3, minVariants:2}`（**已有最小样本数概念**）。<br>⚠️ 缺口：**"习惯"这一层还没有**（§4.1 第 2 类已详述）。 |
| **判据（含反证）** | **正向**：每个画像输出带 `{value, sampleN, evidenceIds[], method: 'stats'\|'model'}`；`sampleN < 阈值`（建议 5）时**必须** `insufficient: true` 且**不出数**。<br>**反证 ①**：清空 `evidenceIds` ⇒ 输出**必须消失**（或变成 `insufficient`）。<br>**反证 ②**：把阈值改成 1 ⇒ 必须出现"用 1 个样本贴标签"的用例被抓住。<br>**反证 ③**：输出里出现"综合评分 / 胜率 / 强度分"这类**无单一出处**的数字 ⇒ **必须红**（与护栏 5 同源）。 |

#### 护栏 9 · **成本 / 延迟**：训练与推理都要报成本，别把 3 秒级响应丢掉

| 项 | 内容 |
|---|---|
| **为什么** | 人类点名"4B 级就够、要保证速度"（`docs/roadmap/HUMAN-RULINGS-2026-09-25.md:135,138`）。训一个更大的模型把延迟打爆，就是"缺点"。 |
| **本仓现状** | ✅ 有明确的延迟闸门：`src/coach/local-model.js:74` `DEFAULT_TIMEOUT_MS = 3000`、`:75` `DEFAULT_MAX_TOKENS = 256`、`:76-77` `DEFAULT_MAX_CONCURRENCY = 1`（注释："单机统一内存，跑两个 4B 推理会互相拖慢"）；逐工具延迟已进回执（`src/coach/toolbox.js:653`）。<br>⚠️ **缺口**：**"3 秒"没有端到端数字**——`docs/roadmap/MODEL-ROUTING-PLAN.md:172` 自己写着 3.1 的实测"**完全不含 LLM**"。 |
| **判据（含反证）** | **正向**：每次训练产物报 `{train_cost: {gpu_hours \| token_count}, inference: {p50_ms, p95_ms, mem_gb}}`；**`p95_ms ≤ 3000` 是硬门槛，超了不许进产品**。<br>**反证 ①**：把 `DEFAULT_TIMEOUT_MS` 调到 300 ⇒ 必须出现**可分类的**超时降级（而不是静默变慢）。<br>**反证 ②**：`after` 的 `p95_ms` 比 `before` 高 >20% ⇒ **该次训练必须进人工复核**（不许只看质量数字）。 |

## 6. RAG 正确性核验（口径 3：反复核验，一定不能给错的）

### 4.1 五道闸门（可执行流程，按顺序跑）

### 4.2 「反复」是什么意思（三条机制）

1. **每次语料变更都重跑 G1–G4**，产物进 `reports/roco/rag/corpus-verification.json`（**确定性**：同输入两次逐字节相同，无挂钟时间戳——照 `reports/roco/rag/rag-eval.json` 的 `metadata.determinism` 与 `GATE_DEFINITIONS.no_clock`）。
2. **每次人类实机更新（`user-in-game-reports.json` 追加）都触发 L1 重建 + G1–G4**。这个触发**必须是自动的**（否则就退化成"记得就核"）。
3. **声明的"反复"次数要留痕**：产物里记 `verification_runs[]`（每次的输入摘要 sha256 + 结果），**同一输入重复跑的结果必须一致**——不一致说明核验本身不确定，那比不核验更坏。

### 4.3 三条必须在判据里写死的反证

| 反证 | 做法 | 期望 |
|---|---|---|
| **跳级反证** | 把一条 `COMMUNITY_CURRENT` 标成 `RECORDED_IN_GAME` | **必须红**（这是台账 `confidence_levels_note` 的硬要求："只有前两级能直接成为 current 规则"） |
| **删条反证** | 删掉语料里某条规则 | **答案必须变**（人类原话形状） |
| **空库反证** | 让某个库指向一个不存在的路径 | **必须红**，**不许**静默降级成空库——空库会让"我不知道"伪装成"没有这条规则"（这是错答案里最坏的一类） |

### 4.4 现在就存在的四处「核验已经漏掉」的证据（**先修这四条**）

这四条是我在做本次只读调研时**实查发现的**，不是推测，**它们正好证明了为什么口径 3 是必要的**：

1. `data/roco/evidence/rule-evidence-ledger.json` 的 `source_markers[recorded_gameplay].definition` 说"本轮**尚无任何来源取此值**"，但实际有 **4 条**条目的 `sources[].marker` 是 `recorded_gameplay`。⇒ **标记说明与数据自相矛盾。**
2. `docs/roco/RULE-EVIDENCE-LEDGER.md:29` 写"逐条台账（**20 条**）"，JSON 里是 **23 条**。
3. `reports/roco/rag/rag-eval.json` 的 `metrics.baseline_searchKnowledge.note` 说"**90 张**战术/参考卡"，实际是 **93**（49 + 44，`src/game/content.js`）。
4. （附）`src/coach/rag-index.js:23-26` 说"**没有本地嵌入模型**"，但 `.models/hub/models--sentence-transformers--paraphrase-multilingual-MiniLM-L12-v2` 与 `.venv-agent` 里的 `sentence_transformers 5.1.2` 都在，且 `src/server/index.js:722` 已经 `semantic: true`。

⇒ **修法**：这四处都是**文档/注释与产物的口径漂移**。按本仓纪律"**改钉不删**"（`docs/roadmap/HUMAN-RULINGS-2026-09-25.md:158`），把注释与说明改成与产物一致，并在产物里记下这次修正的时间与依据。**建议把"文档里的数字必须能从产物复算"加进 G1。**
