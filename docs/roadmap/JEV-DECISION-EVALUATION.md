# Jev 决策层：候选评测，不进入当前主线

状态：待评测；2026-09-22 立项记录。此文件不是已实现声明，也不改变 `PLAYER-LOOP-CHECKLIST.md` 的 P0 优先级。

## 定位与边界

Jev 是 TypeSafe AI 托管的快速结构化决策模型，公开接口返回预定义选项、概率与置信信息，不生成小芽文案。未发现官方公开权重或本地部署方案；第三方 `open-jev` 自称从原理重建、未提供原版权重或等效性能，不能作为 Jev 的本地替代。

在产品里只考虑两处：
1. **介入门控**：在规则和权限门控之后，从 `silent`、`brief_hint`、`expandable_hint` 中选择。规则引擎仍负责合法行动、伤害和胜负事实；正式 PVP 权限先于模型；用户静默偏好和频控是硬约束，模型不可覆盖。
2. **问题路由**：在六宠只读工具契约完成后，辅助选择阵容、培养、战况、复盘或陪练路由。自由聊天与自然语言解释仍由现有 LLM 负责，工具回执和事实校验不变。

开发流程可选：用 Jev 为提示样例标记“有用、重复、打扰、证据不足”，只作抽样审阅和分歧挖掘；不代替真机 E2E、负向测试、人工盲评，也不以 Jev 输出作为训练本地模型的标签。先核对 TypeSafe 服务条款对输出训练/蒸馏的限制。

## 进入评测的前置条件

- P0 玩家闭环真实可玩：六宠组队、战斗、结算、教学；桌面/手机关键操作可见。
- D1–D3 六宠工具与契约落地；当前规则、权限和证据边界可追踪。
- 已有介入策略形成基线，不为了接新模型改写规则事实源。
- 可用经脱敏的对局与多轮问答样本；不上传原始玩家聊天、身份信息或密钥。

## 最小对照（满足前置条件后再做）

同一份冻结样本同时跑：现有规则/学习策略、Jev、必要时本地 Qwen 路由。至少覆盖关键提醒、应沉默、用户明确静默、连续多轮、未知机制、网络超时与服务不可用。记录每组：关键提醒漏报率、无用打扰率、工具路由正确率、置信分桶校准、端到端 p50/p95（从中国网络实测）、每千局成本。用户侧采用 3–5 人盲评，问题措辞与展示频率保持一致。

仅当 Jev 在核心指标上有稳定收益、没有增加打扰和延迟，且失败可安全回退时，才增加一个可关闭的 `decision_provider=jev` 适配器。离线、超时、低置信度时退回现有策略，不阻塞游戏回合；不得让 Jev 生成游戏事实或绕过权限。
