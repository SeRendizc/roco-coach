# 小芽的 Agent 能力：现状、我这一轮查到什么、下一步最该做什么

> 人类 2026-09-28 的话（逐字）：「记住我们重点是 agent 功能！不要一直纠结游戏本身和测试、门禁啥的，
> 你要有空多琢磨下我们的 agent/coach 功能怎么更好、更适合我去面试」。
> 所以这一份只谈 agent，不谈游戏数值、不谈门禁。
> **每个数字都标了怎么复算**；查不到的写「未确认」。

---

## 1. 一句话现状

**产品的实时链路是对的**（政策决定"该不该调工具"，模型只决定"调哪个"）；
**弱的是模型自己独立做"该不该调"这个判断** —— 而这恰好是可量化、可改进、也最好讲的一块。

---

## 2. 这一轮的实测：模型到底差在哪

**数据**：`tests/evals/agent-tasks-v1.jsonl`（288 条任务）+ `tests/evals/agent-trajectories-model-v1.jsonl`
（v8 适配器、1752 条轨迹）。取每个任务一个世界做单世界样本（56 条判挂 / 288）：

| 量什么 | 实测 |
|---|---|
| 判挂条数 | **56 / 288** |
| 其中**一次工具都没调**的 | **56（100%）** |
| 该查规则却没查（`query_rules`） | 32 |
| 该评阵容却没评（`evaluate_team`） | 12 |
| 该比换人却没比（`compare_team_change`） | 12 |
| 该调工具的任务总数 | **96 / 288**（另 192 条本来就不需要工具） |

⇒ **失败全部集中在"该不该调"，"调哪个"一次都没错。**
这不是我推的结论 —— 源码里 2026-09 就写着同一句话（`src/coach/runtime.js:1943` 附近）：

> 「模型『选哪个工具』很准（90–100%），但『该不该调』只有 50%，所以把后者从模型手里拿走」

**我这一轮做的事情，是把这句话从注释变成了可复算的数字。**

---

## 3. 产品链路已经是对的（这一点面试要讲清）

`src/coach/runtime.js:1702-1706` 的实时链路：

```js
if (policy.need) {
  const result = await gatherAgentEvidence({..., mustCall: policy.need, ...});
  packet = {...packet, toolTrace: result.trace, agentStop: result.stopped, toolPolicy: policy};
}
```

**政策说要查的，就一定会查**（`mustCall`），模型只负责"查完之后还要不要再查"。
所以**玩家不会遇到上面那 56 条失败** —— 那是**评测夹具**里的失败（夹具让模型独立决定第一步）。

⚠ 这一条很重要，别讲错：**不是"我们的 agent 有 38% 的错"**，而是
**"我们的夹具量出：模型独立做这一步会错 38%，所以产品里这一步不由模型做"**。

## 4. 这一轮为 agent 做的改动（可跑、可复算）

新增**一条可关的开关**：`--policy-first`（`scripts/roco/build-agent-trajectories.mjs`）。

- 开了之后：**第一步交给同一套代码政策**（复用 `rulesBaselinePlanner`，口径不是新写的），
  政策没意见时仍然交给模型；每条轨迹的 `chosen_by` 如实记 `policy` 还是 `local_4b`。
- 关着（默认）时：行为**一个字节都不变**（所以既有产物不受影响）。
- 它给面试提供了一个**干净的对照实验**：同一批任务、同一个适配器，
  「模型独立决定」vs「政策定第一步」的差距可以逐条数出来。

（实测数字见 §5；脚本与开关的用法：`node scripts/roco/build-agent-trajectories.mjs --arms local_4b --policy-first`。）

> **对照结果（已跑完，单世界 288 条，同一适配器 v8、同一批任务）**：
>
> | 量什么 | 模型独立决定第一步 | **政策定第一步（`--policy-first`）** |
> |---|---:|---:|
> | 判定通过 | **232 / 288** | **286 / 288** |
> | 需要工具的任务通过 | 40 / 96 | **94 / 96** |
> | 其中 `query_rules` | —— | **70 / 72** |
> | 其中 `evaluate_team` | —— | **12 / 12** |
> | 其中 `compare_team_change` | —— | **12 / 12** |
> | 第一步由政策选中的条数 | 0 | **98** |
>
> ⇒ **政策把 56 条判挂里的 54 条直接救回来了，并且一条新的都没弄坏**
> （286 = 232 + 54，剩下 2 条见下）。
>
> **剩下那 2 条正是政策的缺口，而且缺得很具体**：
> `rl-ruleset-f0-01`「这份规则集是哪个版本？」与 `rl-ruleset-f0-03`（同一句加了"再确认一下"前缀）——
> 政策对"规则集版本"这类问句**没有形状**（`policyFor` 返回 `need:null`），于是又交回模型，
> 模型调了 `read_state`（错的工具）。
> **这正是 §5 P0 说的那种"漏了不报错"**：政策没覆盖 ⇒ 静默降级成模型自由发挥。
> 修法很具体：给"规则集/版本"类问句补一条形状（`kind:'ruleset'`），并补一条判据。
> **本文不写"已经修好"** —— 它现在还是红的。

## 5. 还不够好、最该做的三件事（按性价比排序）

| 优先级 | 做什么 | 为什么它值 | 代价 |
|---|---|---|---|
| **P0** | **把"该不该调"这件事的边界写全**：现在政策覆盖了图鉴/术语/学习表/阵容/换人这些形状，但**新问法一出现就会漏**（漏了不报错，只是模型按自己的判断走） | 这是目前唯一一处"错了没人知道"的地方。可加一条**运行时自检**：政策返回 null 但模型也没调工具、且正文里出现未核验数值 ⇒ 记一条 `policy-gap` 事件 | 小（一个计数 + 一条日志） |
| **P1** | **把偏好的"沉默"做扎实**（**本条 2026-09-28 修正过一次，见下**）：门控**已经存在**（`src/coach/experience.js:156` 的 `explicit-quiet`、`:218` 的 `critical-preference`、`src/coach/memory.js:90` 的 `adaptiveGate`），**但缺的是端到端那一条** —— 没有任何一条判据量过"玩家选了安静档之后，一整局里主动提示真的是 0 条"（现有覆盖是分段的：轨迹夹具的 `expect_silence`、mock-host 场景、门控单测） | 面试里"克制"是加分项：**能不说话**和**能说对话**一样重要。把分段的证据连成一条端到端断言，成本不高 | 中（要造几局带偏好的世界） |
| **P1** | **多步链：先把"能考出多步"的任务造出来**（2026-09-28 实测更新，见下） | 现在**没有任何一条任务真的需要两次调用**，所以"有界 ReAct"讲不动 | 小（造 3–5 条跨工具任务）+ 中（重跑一次轨迹） |

### 5.1 多步链：实测到 0，而且原因是**任务集**，不是模型

2026-09-28 把两份产物逐条数了一遍（调用次数分布）：

| 产物 | 0 次 | 1 次 | ≥2 次 |
|---|---:|---:|---:|
| 模型独立决定（1752 条，全 9 个世界） | 1332 | 420 | **0** |
| 政策定第一步（288 条，单世界） | 108 | 180 | **0** |

再回头看**任务集本身**（`tests/evals/agent-tasks-v1.jsonl` 的 `expect`）：

| `max_tool_calls` | 条数 |
|---|---:|
| 0（要求沉默） | 12 |
| 1 | 48 |
| 2 | 228 |
| 期望里写着**一个工具列表且 >1** 的 | **0** |

⇒ **"允许两次"不等于"需要两次"**：228 条任务都写着 `max_tool_calls: 2`，但没有一条的期望是"必须调两个工具"。
所以这份评测**结构上考不出多步链** —— 0/1752 是任务集的属性，不能拿来说"模型不会多步"。
（源码注释里那句"真实模型评测里未观察到多工具链"是**对的**，只是它的解释权之前没落到这里。）

**要补的是任务**，不是模型。例子（都必须是"第二个工具的参数依赖第一个回执"）：
① 先查某只的学习表 → 再问"其中某一招它到底学不学得到"（`learnset` → `legality`）；
② 先读某回合证据 → 再拿那一回合的局面比两个分支（`read_evidence` → `simulate_branch`）；
③ 先评阵容 → 再针对评出来的短板查一条规则（`evaluate_team` → `search_rules`）。

**为什么本轮没有直接加**（如实说）：任务集是**逐字节钉死**的 —— 加一条会牵动
`tests/evals/roco/agent-trajectories.test.js`、`model-arm-identity.test.js`、`model-trajectories.test.js`
里按 288 / 1752 写的计数，还要重建轨迹、SFT 切分与影子回放**四份产物**。
这不是"改一个数字"，是一次**口径变更**（`total` 与三侧切分都会变）。所以本轮只把它写成
可执行的任务规格，**没动数据**。

**⚠ 修正（同一天，我自己推翻自己一句）**：这条原来我写成"产品侧没有判据"，
查过之后是**写错了** —— 门控与单测都在（`experience.js` 的 `explicit-quiet` / `critical-preference`，
`memory.js` 的 `adaptiveGate`，以及 `intervention-agreement` / `companion-nonintrusion` 两套判据）。
**真正缺的只有端到端那一条**。改钉不删：错的那句话在这里留着，免得下一个人再写一遍。

**不建议做的**：为了提分**再训一版适配器**。理由：v8 已经在 20 条工具覆盖上 17/20、影子回放 97.9%
（同配置上一次），而失败全在"该不该调"这一档 —— **那是政策该管的，不是权重该管的**。
拿同一批数据再 SFT 一遍，最可能的结果是**过度调用**（该沉默的时候也去查），那会更糟。

## 6. 面试怎么讲这一段（三句话，都有数字）

1. **问题**：Agent 的工具调用里，"选哪个"和"该不该调"是两种能力。
   我量了 288 条任务：模型独立做**"该不该调"会错 38%**（56/288，且全是"一次都没调"），
   而**"选哪个"一次没错**。
2. **做法**：所以我把第一步从模型手里拿走，交给**代码政策**（`mustCall`），
   模型只负责"查完之后要不要继续查"。产品链路早就这么做了（源码注释 2026-09 就写着这个结论）；
   我这一轮把它变成**可复算的数字**，并加了一条 `--policy-first` 开关来对照。
3. **边界**：政策覆盖不到的**新问法**会漏，而且**漏了不报错**（静默降级成模型自由发挥）——
   这是我下一步要补的自检（`policy-gap` 计数）。**没做之前不吹。**

---

## 7. 没做到 / 未确认

1. **`--policy-first` 的全量对照数字**：本轮交稿时只跑了单世界烟雾测试，**9 世界全量未跑**
   （约 20 分钟机时）—— 所以本文**没有**写"政策能把 56 条救回多少"这个数。
2. **`policy-gap` 自检没写**（§5 的 P0）：现在"政策没意见但模型也没查"这件事**没有任何计数**。
3. **沉默那条没有判据**（§5 的 P0 第二条）。
4. **多步链没有新的实测**：源码里那句"未观察到多工具链"是旧记录（44+4 条），本轮没重跑。
5. **没有真人数据**：以上全部是夹具与模拟世界里的数字，**不能说明真人收益**。
