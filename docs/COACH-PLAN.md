# 小芽 AI Coach 整体方案

更新日期：2026-09-16。面向腾讯 IEG 的宠物对战 LLM Agent 面试题。

## 1 项目要解决的问题

玩家通常不会离开游戏去问 AI。小芽应在游戏事件发生后自主观察、选择工具、识别有价值的风险或机会，只在值得占用注意力时给出简短帮助。玩家决定行动；小芽根据实际过程反馈，并在后续相似局面检查是否学会。

主展示链路：实时观察 → 判断需不需要帮助 → 有依据的提示 → 玩家行动 → 关键复盘 → 后续迁移验证。军师负责实时帮助，老师形成学习闭环，陪练通过具体而克制的回应和持续记忆建立关系。三种角色不必对应三个独立 Agent。

核心原则：就算玩家从不打开聊天，小芽也应有用。随着玩家熟练，提示减少可以是成功。游戏需要有值得探索的战术，但不能故意隐藏规则或制造操作障碍来证明 AI 有用。

## 3 玩家看到的体验

### 对战中

小芽在固定边缘位置显示短句，不改变页面高度、不遮挡技能、不抢焦点、不强制暂停。默认不弹聊天框、不展开解释。正常操作不要求额外确认；不能为了猜测玩家意图而强加一个提交步骤。

提示包含当前最有用的事实，例如“它有先制，光比速度还不够”。只有计算与适用条件支持时才能说具体收尾或承伤结论。详细依据通过可选入口查看，内部工具过程不展示成推理流水账。

触发源包括回合开始、对手换宠、状态和能量变化、玩家明确查看某个动作、用户委托的提醒条件、回合结算。停留时长只是弱信号，不把停留等同不会玩。玩家已经正确处理风险时取消提示。

每次候选提示都评估重要性、置信度、是否仍可行动、新颖性、玩家是否已注意、近期打扰量。沉默、延后、轻提示都是合法决策。同一风险去重，较重要的新信息替换旧信息，不排队播报已经过期的建议。当前每局两次模型解释是原型限制，不是最终干预策略。

### 语音和静默

支持短语音与可读字幕，语音可独立关闭。语音本身也占注意力，不能把所有文本转成语音当作解决方案。动画、玩家语音交流和重要系统播报期间适当抑制；需要有明确的开关与能力边界，未接入的语音活动检测不能假装已存在。

三个偏好：适度提醒、仅关键风险、关闭主动提醒。关闭主动提醒必须完全遵守，不以“模型认为必要”越权。关键风险限定为有较高把握且仍能采取措施的重大损失；普通属性劣势不自动等同关键风险。用户关闭一条提示和关闭全部主动提醒是不同操作。

明确偏好立即生效，行为推断只能逐步调整。没点击不等于没看见、没受益。用户可随时撤回、修改偏好。

### 复盘和培养

复盘最多主动提供一个关键片段入口，不自动给整份报告。区分当时公开信息下的合理性与实际分支的结果；不以输赢倒推对错。反事实必须注明固定了哪些对手行动、是否只覆盖一回合。

培养页原位提供目标相关建议：读取选中宠物、预算、关卡、目标对位；展示加点前后伤害、生存或先手阈值变化。允许建议保留资源，不一律催促加点。阵容建议尊重明确的本命宠和玩法目标，提供可解释取舍。

学习验证优先采用换参数、换对手的相似局面，后续撤去直接提示再观察。选择题是辅助，答对一次不等于永久掌握。失败后不强行安慰；肯定应指出实际做好的选择，不生成空泛鼓励。

## 4 Agent 架构

游戏事件 → 可见状态投影 → 候选任务与快路径检查 → 干预策略 → 有界 ReAct 与工具 → 证据及有效期校验 → 展示或沉默 → 行动结果与记忆。

### 快路径与 ReAct

快速路径负责合法性、明确机制、确定性数值、消息取消和简单风险。复杂局面由 Agent 判断缺什么信息、选择工具、读取结果、决定是否继续分析或停止。固定调用所有工具再润色不宣称是完整 ReAct。

建议工具：get_visible_state、search_rules、compare_actions、simulate_branches、read_player_memory、register_watch、cancel_watch、read_turn_evidence、create_practice。通过结构化 schema、参数校验、调用预算和超时限制工具行为。关键可见状态与权限由宿主提供，模型不能自行扩大读取范围。

LLM 承担目标理解、按需工具决策、检索问题改写、取舍解释、条件委托解析、针对证据的教学和反思。伤害与合法性由引擎确定。单一 Coach Agent 起步，复杂后台复盘可另做工作流；不为角色数量堆多 Agent。MCP 作为以后跨游戏工具接口预留，不以接入 MCP 代替功能完成。

### 条件委托

玩家可选择常用条件，也可说“能收尾时提醒我，其他时候少说”。Agent 将其转成受支持的结构化条件，展示简短理解回执；有歧义才澄清。不执行模型生成的任意脚本。提醒有范围、有效期、一次性或持续语义，支持查看与取消。该功能是额外入口，不作为自动帮助的使用前提。

### 模拟与动作比较

复用游戏结算器，分析公开信息下多个对手分支。第一版做有界一至两回合搜索；较深搜索仅针对筛选后候选。保留假设、收益定义和不确定性，不把启发式分数当校准后的胜率。

判断相近的行动允许并列合理；不因排序第一不同就认定玩家错。宠物池、配招和环境扩大后，给搜索设时间与分支预算，超时返回较保守结论。

## 5 异步有效性与玩家自主权

任务保存 match_id、state_version、decision_id、rules_version、evidence_ids、valid_until、cancel_reason。模型请求、展示卡片、语音队列使用同一失效条件。

玩家提交动作、目标切换、离开对战、权限或偏好改变时，检查相关任务并取消；即使远端请求无法终止，也阻止过期结果展示。不阻塞玩家，不自动补发“你做对了”。仅在重新验证后仍成立的信息才可继续使用。复盘作为独立任务重新读取事实，不能把过期建议改名复盘直接播出。

可在动画期间准备下一决策，但每次发布前校验最终状态。并发请求合并、事件去重、每场成本预算和后台任务优先级独立于用户提示频率。

## 6 RAG 与证据

知识库覆盖版本规则、技能、特性、培养、携带物、关卡与战术案例。原子规则带 rule_id、版本、来源、适用条件、生效时间。动态血量和能量不走文档检索。

采用结构化过滤与关键词/语义检索组合，版本过滤在生成前完成。检索结果控制长度，关键条件不能从切块中消失。对比纯关键词基线，验证语义检索是否确实带来收益。

建议保存引用证据 ID、工具输入摘要和计算结果。引用存在不代表推导正确：额外检查引用是否支持结论，尤其是“保证收尾”“一定先手”。知识文档是数据，不能作为工具权限指令。没有可回查证据时降级回答，不编造。

## 7 玩家记忆与学习

分开存储四类信息：交流和提示偏好；按知识点的掌握程度；明确玩法目标；当前会话状态。不能用一个水平分数同时决定所有策略。

Memory Stream 保存关键观察、行动、提示、关闭反馈和练习事件。Reflection 对多次证据提出暂定解释，并带来源、时间和置信度。既反思玩家可能遗漏什么，也反思小芽是否重复、迟到或判断错误。

掌握情况至少区分未知、有提示下成功、无提示下重复成功，需要支持遗忘和版本变化。使用提示后的正确行动不能直接当作独立掌握证据。用户可查看、修正、删除记忆；删除需覆盖索引、摘要和后续引用，不只清空聊天框。

## 8 在 200K 工作预算下工作

> **口径更正（2026-09-17）**：本节原标题是「在 **32K** 上下文下工作」，正文写「示例 **32K** 预算」。**32K 是项目早期按字节估算的保守值，已经作废**：官方文档确认 `deepseek-flash` 容量 1M，项目把工作预算改为 **200000（`WORKING_CONTEXT`）**，输出预留 `OUTPUT_RESERVE=4096`（`src/coach/runtime.js:179-186`）；服务端精确计数侧是 `window=200000, output=320, reserve=1024`（`src/server/token-budget-server.js:11-16`）。这与上文第 2 节的「32K 上下文压缩验收**已被取代**……工作预算改为 200K」一致。下面保留原文，只把预算数字换成现值；括号里是当时的旧值。

原始事件保存在外部持久存储；上下文仅装当前任务材料。记录按 match_id/turn_id/event_id 可回查，知识库按规则版本匹配。摘要用于索引和导航，不替代原文。

预算按所用模型 tokenizer 计数，包含系统说明、工具 schema、输入、工具结果、输出及安全余量。示例 200K（旧文写 32K）预算：指令与工具 4K、当前状态与任务 5K、相关规则和历史证据 8K、偏好与摘要 3K、工具返回预留 4K、输出预留 4K、安全余量约 4K——**这套分项是设计示意，不是代码里的实际切分**；代码里浏览器侧实际预留 `output 4096 + system 4096 + tools 2048`，其余是可用预算，服务端再按真实 token 精裁。仅为设计上限，短提示通常远低于此值。

超预算先移除重复和无关内容，再缩减检索范围、压缩旧经历，最后拆分问题。不可裁掉当前状态、强制偏好、规则适用条件和关键证据关系。大型回合记录用工具分页读取。反复摘要必须保留原始来源，不允许“摘要的摘要”成为唯一事实。

压缩前后验证偏好保留、数值一致、未完成委托、证据可回查、版本正确。证据缺失时标明不足。大上下文是容量选择，不是可靠性保证。

## 9 Agentic RL 与评测反馈

必做真实小实验：训练教练的干预策略，动作包括沉默、风险线索、行动建议、延后教学。状态由风险、行动收益差、掌握证据、打扰历史和偏好组成。偏好禁令与 PVP 限制是不可被奖励覆盖的硬约束。

采集含状态、动作、工具结果、玩家后续行为的轨迹；设计奖励并实际更新策略参数，保存配置、随机种子、检查点和训练曲线。只有打分或反思不算参数 RL。小策略训练应准确命名为 Agent 干预策略 RL，不冒充 DeepSeek 权重训练。

奖励考虑正确性、相对基线的决策改善、无提示迁移表现、重复干扰、过期提示和成本。不只看胜率、点击率、采纳率。先用多类型模拟玩家训练，在未见种子、队伍和行为模式上测试；模拟结果不代表真实玩家学习效果。

基线：不提示、固定规则提示、未经 RL 的 Agent、RL 干预策略。完整对局与相似局面不能跨训练测试集泄漏。记录失败和无提升结果，不先承诺 RL 一定有效。

另行评估开源 LLM 的工具决策 RL：第一天确认算力、可训练模型、框架兼容与预算。Agent Lightning 是候选连接方案，不是训练本身。若无法开展，明确该层仍为设计，保留数据协议与复现实验计划；不能以普通 DeepSeek API 请求声称更新其权重。未经授权不租算力或开始付费训练。

## 10 公平性与安全边界

PVE 开放战术、培养和教学。正式 PVP 赛中关闭战术分析与带战术信息的教学/条件提醒，只保留被允许的中性陪伴；赛后仅根据允许保存的公开信息复盘。限制放在模型调用前与服务端能力层，不只隐藏按钮。

现有客户端快照是本地 Demo 数据，不是可信竞技服务端状态。原型阶段演示权限隔离，不声称线上反作弊已经完成。密钥不进入前端持久存储、日志、报告或模型上下文；保留本机加密录入与 HTTPS 上游，清楚说明其不等于公网部署的完整安全设计。

## 11 验收与面试演示

无聊天演示：普通游玩触发一次有用提示，用户自主行动，后续可选复盘与相似场景验证。另一段演示高手自行处理时小芽沉默。

故障演示：人为延迟模型，玩家先出招，旧文本和语音都不出现；32K 预算下回查早期证据；删除证据后不再假装记得；PVP 限制无法被提示词绕过。

指标：规则事实准确率、建议合法率、引用支持率、检索命中、过期展示次数、重复打扰、真实用户主观有用性、无提示迁移表现、延迟分位数和单局成本。先制定测试集和口径，再填写结果。合法性、强制偏好和旧消息隔离等确定性回归目标为零违规；真实学习增益不预设数字。

## 12 排期与交付

按照三天执行窗口建议：第一天确认场景和训练资源，完成事件/证据协议、RAG 与工具 Agent；第二天完成实时干预、偏好记忆、教学及轨迹采集；第三天完成小型 RL 实验、模型联调、独立评测、报告与演示。估计需要按实际剩余时间调整，不代表同时承诺全部游戏扩展和大模型训练能在三天完成。

最终交付：可运行 Demo；有来源的调研；实现与难点说明；训练与评测记录；演示脚本/录像；Word 或 PDF 提交稿。当前保存的是执行方案，不是这些最终交付已经完成。
