# 小芽：可验证的 Coach 闭环

> **历史稿（v0.7 前后）**：本文描述当时的状态，多条已与当前实现不符——例如「当前 Demo 只有 PVE」（已有本地对战）、「没有实现向量 RAG」（已有混合检索）、「不是 Agentic RL」（已有两条真实 RL 实验）。当前状态以 `docs/IMPLEMENTATION-STATUS.md` 与 `docs/CHECKLIST.md` 为准。

## 定位
面试主线是「有依据的随场军师，带出一个教学闭环」。游戏是产生可重现局面和行为记录的环境，不是主角。

## 现在可体验
1. 普通训练开局，无需聊天，操作区出现小芽的一句候选行动提示；解释默认收起。
2. 展开依据，查看双方公开数值、条件伤害和分析边界。规则工具枚举合法行动，通过与游戏相同的结算器比较一回合收益；不读取电脑待执行动作。
3. 玩家自行行动。通过「回合回顾」展开是否选择了候选行动和真实回合日志；不能把一次胜败等同于决策好坏。
4. 点击「练一个知识点」，依据刚才的动作选择灼烧追击、防御节奏、换宠承伤或先制与速度题；答对后保存学习记录。
5. 回营地或刷新后，「回顾上一回合」仍可读取最近真实回合。开始另一场新训练则隔离上一场数据。

## LLM 的职责及边界
- 配置 DeepSeek 后，开局与关键风险变更自动请求短解释，每局最多两次；实时规则建议不等待模型。
- 模型输入是工具产生的事实包、玩家问题、有限对话和明确偏好；模型负责把比较结果解释成玩家能理解的取舍。
- 推荐标题和可展开数值由工具生成；自然语言模型解释仍可能出错，不宣称模型事实准确率已达到生产标准。
- 超长模型文本回退到工具结论；聊天默认180字预览，其余可展开，正文支持安全的基础 Markdown。
- 超时保留规则建议；玩家已行动或退出后丢弃旧局面回复。
- PVP 赛中在调用模型前阻断战术与教学。当前 Demo 只有 PVE，不能据此宣称具备线上反作弊能力。

## 与直接接入聊天模型的区别
游戏事件主动驱动 → 工具读取真实状态、合法行动和共享结算器 → 有预算的模型解释 → 玩家选择 → 实际事件反馈 → 动作相关练习与学习记录。聊天是扩展说明入口。

## 已修复的根因
- 回营地清空 game 导致历史消失：独立持久化最后完成回合，预制体验不覆盖。
- 只在胜负和倒下时出现气泡：每回合后台评估，只有开局或间隔至少两回合的风险变化才出现短提示；其余通过回合回顾主动查看。
- 大段文本挤压输入框：固定面板控件，仅消息区滚动，长内容折叠，安全 Markdown。
- 日志倒序：按回合分组倒序，组内仍保持事件发生顺序。

## 后续面试应如实讨论
目前是确定性工具编排与轻量记忆，不是 Agentic RL，也没有实现向量 RAG。固定游戏规则用结构化工具读取更可靠。应补充模型评测集、反事实讲解准确率、干预采纳率、误打扰率，以及玩家后续相似决策是否改善；答对一道题仅说明当前题目理解，不能证明长期掌握。

## 验证范围
自动测试覆盖状态、回合归档、PVP前置限制、长输出回退、Markdown转义、回合排序和核心游戏规则。浏览器另验证普通开局提示、真实出招反馈、刷新后复盘和聊天布局。DeepSeek真实端到端解释需在服务升级后重新录入密钥验证，模拟上游测试不等同真实模型评测。
