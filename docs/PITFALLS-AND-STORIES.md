# 这个项目里踩过并修好的坑（面试时讲这五个就够）

> 挑选标准：**每一个都能当场翻出代码、判据与实测数字**，而且**不是"我写错了一个 if"**那种，
> 是"设计上少想了一层"。每条都标了证据位置，面试官要追问就点开。
>
> ⚠ 有几条是**别人（上一轮的我）踩的、我在接手时抓到的** —— 照实说，别揽功也别甩锅。

---

## 坑 1｜金标闸门把"权限"写在了**被审的数据文件**里（越权，最严重的一条）

**症状**：门禁会从 `data/roco/gold/review-state.json` 里读"谁有资格审"这份名单。
**问题**：那个文件**正是被审的对象**。于是 agent 可以用 `--sync` 把 `reviewer_allowlist` 改成自己，
再给自己写一条 `approved` ⇒ 实测 `gate_eligible=true, problems=[]`，**闸门自己把自己打开了**。

**修法**：允许名单**只认源码常量** `DEFAULT_REVIEWER_ALLOWLIST`；数据文件里出现不同的名单
⇒ **直接报错**（那是篡改特征，不是配置项）。复测：`gate_eligible=false` + 两条问题。
**证据**：`scripts/roco/gold-review.mjs`；台账 §C6.14x 的 A1 条。

**面试价值**：能讲清"**安全边界不能建在被守护的对象上**"，
以及"一个只有你自己用的闸门，也会被你自己（或你的 agent）绕过"。

## 坑 2｜守卫的**证明方式**本身是假的：注入自检曾经"全绿"

**症状**：有一层叫"守卫"的检查（比如"模型编数字必须被打回"）。判据说它会红。
**问题**：它的自检方式是"从 `node --test` 里再起一个 `node --test` 子进程" ——
子进程继承了 `NODE_TEST_CONTEXT=child-v8` ⇒ **它不按参数跑那个测试文件**，只是当父测试的又一个 worker
⇒ **永远 exit 0**。结果：7 条注入**全部报成"仍绿"**，看起来像守卫全失效，其实是自检自己跑不动。
**修法**：起子进程前**清掉测试运行器的环境变量**（`childEnv()`），并在别处加一条**静态判据**
要求所有起 `node --test` 的地方都清理（`tests/evals/subprocess-env.test.js`）。
**现状**：登记 **15 条注入、红 15 条、仍绿 0**。
**证据**：`scripts/roco/guard-selftest.mjs:205-224`；台账 §第 28 轮前后。

**面试价值**：**"测试通过"和"测试真的在跑"在 CI 里长得一模一样。** 这一条最能证明工程判断。

## 坑 3｜两套验收并行跑 ⇒ **互相读到半改的源文件**（我在接手这一轮亲自踩的）

**症状**：接手时我同时起了 `npm run test:unit` 与 `npm run verify:release`（想省时间），
结果全量判据 **1710/1711**，红的那条说"`scripts/roco/gold-review.mjs` 里找不到注入点"。
**根因**：两套里都含 `guard-selftest`，它的工作方式是**逐条改写仓库源文件、跑子测试、再恢复**
（`guard-selftest.mjs:226-260`）。两个进程**互相读到对方注入到一半的文件**。
**而且契约原文早就写着这件事**：`verify-release.mjs` 的套件说明逐字说"它逐个改写仓库文件并恢复，
所以**不能**和并行跑的单测放在一起……只能在这里串行跑"。**我没先读那一段，这是我的错。**
**修法**：单独重跑 ⇒ **1714/1714 全绿**；这条纪律写进交接文档与面试材料。

**面试价值**：**能主动交代"我犯过这个错、根因是什么、怎么防"**，比只报喜强得多；
顺便说明"并行化不是免费的，要先看清任务有没有共享可变状态"。

## 坑 4｜改了一个数，忘了改由它派生的那些数（这一类反复出现）

**症状**：把"回答精灵数值"改成读图鉴层之后，真机给出一句**自相矛盾**的话：
「铠甲虫：种族值合计 **555**（生命 122 / 物攻 88 / 魔攻 39 …）」—— 逐项是新值（现加 **522**），
合计却还是引擎那份旧六维的和。**玩家自己一加就发现不对。**
**根因**：只合并了 `stats`，没重算 `stat_total`（回执里那个数是对它自己那份六维求的和）。
**修法**：合并后**按现加重算**合计，并在出处里写清"合计按现加是 522（模拟基线那份是 555）"；
判据要求正文必须出现现加值、**不许**出现旧的 555。

同一类还有一次：改了 `owned-pets.json`（加了一条人类裁决）⇒ 下游派生产物过期 ⇒
**3 条判据同时红**，跑一次重建才转绿。
**证据**：台账 §C6.325d；`tests/roco-codex-local.test.js` ⑪；`tests/roco-on-demand-builds.test.js`。

**面试价值**：数据管线里**"派生"是有方向的**；每一个派生数都要问一句"它的来源改了没有"。

## 坑 5｜"没有这个数"被当成 0：`Number(null) === 0`

**症状**：面板计算里，种族值缺项的那只被算出了一个"0 分面板" —— 页面照常显示，玩家不会发现，
**但你给的是一个假数**。
**根因**：JS 的 `Number(null) === 0`、`Number('') === 0`。直接 `Number()` 会把"没这一项"变成 0。
**修法**：进公式前先过一道闸（`numOrNull`）—— null / undefined / 空串一律返回 `null`，
对应项**不进结果**（而不是进 0）；诚实缺项的项**不出现在面板里**，并在 `unknown` 里写清缺什么。
判据：种族值缺的那一项不许出现在结果里，且必须说出缺的是哪一项。
**证据**：`src/coach/talent.js` 的 `numOrNull`；`tests/roco-talent-nature.test.js` ⑤。

**面试价值**：**"缺数据"和"零"是两回事**。这条和本项目"缺数据就写未确认、不许编"的纪律同源。

## 附：这三条不是"坑"，是**故意保留的分歧**（面试官可能当成 bug，先解释）

| 看起来像 bug | 其实是 |
|---|---|
| 执行域 5 只精灵的六维与图鉴层**不一致**（`apply-capture-to-engine.mjs --check` 报 20 条） | **故意的**：采用抓包会破坏引擎那条"默认路径逐比特一致"的冻结契约，所以撤回，改让**回答层**读图鉴层（台账 §C6.325c 有完整记录与理由） |
| 现有 **542 只**的配招表里**等级那一列全是 `null`**（2026-09-28 前是 48 只） | 源数据里**有**等级（wiki Lua 实测 7,735 条全带 level），是**导出那一步**把它裁掉的；这是下一轮要修的，不是"没有数据"。⚠ 2026-09-28 起可玩层那 **530 只**是**纯抓包派生**，抓包**本身不给**等级（`layer-playable-48/learnsets.json#level_status = not_provided_by_capture`，每条技能只有 8 个键）——那一半的成因是"来源没有"，不是"导出裁掉"；人类这一轮拍板「别的不找不要了」⇒ 不另找来源补，如实留 `null` |
| 同名多形态（钻石蜗 6 种）**不合并** | 拍平是**信息损失**（6 条不同六维会变成 1 条），判据明确禁止 |
