## 为什么借鉴宝可梦

宝可梦官方对战指南讨论了速度与特殊先手、主动换宠的行动成本、治疗时机以及队伍属性覆盖。这些适合借鉴为“先问哪些问题”的战术思路。其具体倍率、双属性、特性及逃跑规则不能沿用到小兽训练场。

来源：[宝可梦官方对战指南](https://diamondpearl.pokemon.com/en-gb/trainersguide/fundamentals/battling/)，访问日期 2026-09-16。没有整篇搬运攻略；本地战术卡自行编写，数值依据 src/game/engine.js / src/game/progression.js。外部来源仅作为思路出处，不作为本地规则权威。

## 接入后的 Agent 怎么工作

以“狐面对已灼烧的残血鹿”为例：

1. 事件产生任务，绑定 battleId、decisionId、stateVersion、rulesVersion、deadline。
2. 快速模块先判断是否有提示价值。玩家已掌握该知识点、无明显风险时允许保持沉默。
3. Agent 查当前可见状态，按需要检索“灼烧联动”“够用的伤害”，而非每次灌入整本攻略。
4. Agent 调比较工具，必要时模拟防御、治疗、换宠等候选分支。工具报告假设与范围，不暴露敌方已选动作。
5. 检查当前状态仍有效、建议可执行、数字可追溯；再决定是否呈现一句话或继续观察。
6. 记录玩家实际选择与结果，复盘时再讨论原因。没采纳不自动算差评，也不自动判玩家不懂。

例如同一目标 50 HP，一级狐对灼烧鹿，火花直接伤害52、追猎75，都耗2能量。两者都满足未防御且未治疗的击倒条件。只有进一步比较对手分支才可能说明某招更稳；不能仅因75大于52提醒玩家“打错了”。这会作为重要的反例评测。

## 游戏数值优化方向

优先让现有宠物产生可解释的选择，暂不堆种类。狐承担快速铺状态与收尾，狮承担破防与爆发；评价二者不能只看生命和攻击总和。检查同等培养预算下，谁擅长哪些局面、付出什么代价、对手如何反制。

首批平衡场景：满血/残血、快/慢、防御/不防御、低/高能量、药品有/无、可换宠/最后一只。统计支配动作、双方存活、资源消耗和回合长度，并查看具体失败轨迹。少量种子不当平衡结论。

培养以跨阈值为目标：速度从落后到平速与超过是两种结果；加攻击是否少打一回合；加生命是否多承受一次攻击。先按这些结果调整数值，再更新教学案例。

新增宠物、属性、配招与天气继续按 GAME-EXPANSION-PROPOSAL 分阶段讨论。每引入一种机制，都要同时有可用战术、反制方法、知识卡、计算支持和测试案例。关闭小芽后游戏仍需可理解，不能靠故意难懂来证明AI有用。

## 优先级

下一步优先把“事件触发 → 有界工具调用 → 证据核验 → 克制提示 → 本回合结果复盘”接成一个真实闭环，然后补个性化和训练实验。检索工具只是其中一环；不以知识卡数量作为Agent完成度。
