# 小芽：产品与后续 Agent 接口

## 当前已实现（本地规则演示）

- 顶部入口、培养页快捷入口、聊天面板、快捷问题。
- 首次宠物倒下、对战结束触发有限的短气泡；玩家无需先打开聊天。
- 每局最多两次，普通事件间隔至少三回合；结果事件可绕过回合间隔但不能绕过次数上限。
- 九秒收起、关闭后本局不再主动出现、安静模式持久保存。
- 不把连败或停顿当作真实情绪标签，不写入推断人格。
- 当前回复是本地文本匹配，不是假装已接入 LLM。界面明确标注“本地演示 · 未接模型”。

## 根据用户反馈调整

PVE 作为当前主要场景，可开放实时辅助；正式 PVP 赛中限制战术分析。以后做联网时由服务端模式信息授权，不能依赖客户端传入 mode。当前未实现真实 PVP。

情绪陪伴无需用户主动抱怨才能出现。以可观察事件提供温和回应，但不宣称知道玩家感受。例如首次倒下提醒仍有队友；结束时提供继续、复盘或休息的空间。未来比较展示频率、关闭率和玩家可选反馈，不能用采纳率或停留时长直接代替体验质量。

## 计划中的 Agent 流程，尚未实现

游戏事件/玩家消息 → 场景权限 → 触发判断与频控 → 可见状态和偏好 → 工具与检索 → DeepSeek → 输出校验 → 气泡或展开回答。

先由确定性策略决定是否允许打扰，再让模型决定怎样表达。LLM 不应该收到每次鼠标移动，也不能自行突破频控。

推荐后端接口 `POST /api/coach`：

```json
{
  "event": "user_message | battle_end | cultivation_question",
  "message": "怎么培养这只狐狸？",
  "battleId": "server-owned-id",
  "stateVersion": 12,
  "petId": "fox"
}
```

后端自行读取有效状态与玩家偏好，不信任客户端上传的战况作为唯一事实。响应可包含 `text`、`evidenceIds`、`suggestedQuestions`、`stateVersion`。对状态版本落后的战术建议应丢弃。

预期工具：查询宠物规则、读取可见战况、比较合法行动、读取成长与可用资源、读取明确偏好。第一版不开放模型直接执行加点、使用物品或控制玩家行动。

服务端从环境变量读取 DeepSeek key，配置模型、超时和预算；密钥不进入浏览器。超时保留已有游戏体验，气泡可静默失败，主动提问则给可重试反馈。工具调用轨迹与模型生成内容分开记录。

## 小范围闭环候选

培养页：说明当前宠物职责 → 比较生命/攻击/速度的取舍 → 玩家确认加点 → PVE 试战 → 用实际对战记录解释培养是否达到了目标。

当前成长和训练场可运行，但这条闭环的 LLM 教学和自动复盘尚未完成。
