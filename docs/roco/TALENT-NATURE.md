## 二、个体与抽屉（同一只精灵多个个体）

- 数据：`owned` 从「一种一只」改成「一只精灵 → 若干**个体**」：
  `{individual_id, species_id, level(默认 100), talent{六项 0–10}, nature, refreshes{nature:3, talent:3}, history[]}`；
  **同一个 `species_id` 允许出现多次**（性格/天分不同），排序与筛选都按种类聚合。
- 界面：伙伴页 = **按种类分组的抽屉**（一行一种：名字 + 系别 + 个体数 + 该种类里最好的那一只的摘要）；
  点开一行才看到这一种的各个个体（性格 / 天分 / 面板差 / 剩余刷新次数）。
- **选宠/培养的默认视图不许塞满**：默认只显示"当前队伍 + 最近用过的几种"，其余按名字/系别搜索；
  选中一个种类后，**再**选具体个体（默认选面板最好的那个，并显示"你还有 N 个同种个体"）。

## 三、刷新（代替加点）

- 两个按钮**分开**：`刷新性格` / `刷新天分`；每个个体**各 3 次**（两个计数器独立）。
- **可复现**：随机数由 `seed = hash(individual_id, kind, 第几次)` 决定（同一个体同一格刷新结果固定），
  界面与日志都能复算；`history[]` 记下 `{kind, before, after, at}`。
- 刷完不给"更好的那个"下结论：教练只说**变化**与**取舍**（哪一项变了、对速度线/输出意味着什么），
  不替玩家判断"这个性格好不好"。

## 四、coach 适配（防纯机器算 + 防过拟合）

- **数字只从 `src/coach/talent.js` 来**（它自己从数据层读），答案层不许再算一遍、更不许编。
- **防纯机器算**：凡是性格/天分的问题，答案必须包含「变化 + 取舍 + 与你这支队的关系」三件事；
  只回一串面板数字视为不合格（判据里用"必须有取舍句"钉住）。
- **防过拟合**：判据用**生成的**用例（随机种族值/天分/性格组合 + 留出的种类），
  不许出现"针对某只精灵/某句原话"的硬编码答案；任何按名字分支的写法判红。

## 七、培养 = 刷新天分（2026-09-26 人类口述改口径）

**原版没有「加点」** —— 所以这一档的「培养」就是**刷新天分**，不是分配培养格。

| 规则 | 值 | 来源 |
|---|---|---|
| 天分刷新是**分级**的 | 一/二/三级，各一次 | 人类口述（RECORDED_IN_GAME） |
| 每级 | **随机挑一个还没被加过的属性，+10** | 同上 |
| 限制 | ①**次数上限 3**（与级数一致）②**落点不重复**（加过的项不会再被抽到）③**可以回滚上一次**：一次只退**一步**、不能连着退（再刷一次之后才能再退）；**次数不消耗也不返还** | 由 ①② 推出；③ 见 2026-09-27 两条更正 |
| 随机性在哪 | **只有落点在随机**；幅度（+10）与次数（3）都是定死的 | 同上 |
| 性格刷新 | 仍然是 30 条等概率，3 次，与天分刷新**互不消耗** | 性格掷点仍是建模的（本仓没有官方概率） |

**为什么这样限制**（人类问「最好有个限制机制？你想想咋弄」）：
1. **次数 = 级数**：三次之后这一只的加法定格 —— 想要别的组合就得**再抓一只同种个体**（这正是"可重复拥有"的意义），
   而不是把一只刷到完美。配队复杂度因此来自"个体之间怎么选"，不是"一只刷多久"。
2. **落点不重复**：三次一定落在**三个不同**的属性上，不会出现"三次全加同一项"这种退化结果，
   玩家也不会因为运气差拿到一只"只加了一项"的废个体。
3. **幅度与次数定死**：只有落点随机 ⇒ 同一只个体在任何机器上刷出来的**级数与数值完全一样**（可复现），
   差别只在"加在哪几项"，这正是玩家能拿去比、教练能拿去讲的那个变量。
4. **不做**：道具/代价类限制（原版的刷新材料本仓没有数据）—— 等小黑盒或实机口径来了再挂上去，
   现在**不编一个代价**。

### 2026-09-27 更正：回滚**可以做**，而且回滚后重刷会换落点

上面那张表原来写着「**不可重掷/不可回退**」，而同日已实现 `undoLastRefresh`（抽屉里就有「回滚上一次」），
**文档与实现自相矛盾**。同时发现另一处：种子原来只由「个体 + 种类 + 第几次」决定 ⇒
回滚再刷**必然回到同一个落点**，而教练文案却说「回滚换一个落点可能更值」。

两处一起改：① 这张表改成「可以回滚上一次（次数归还）」；② 种子把「这一类回滚过几次」算进去
（`refresh()` 里的 `undone`），于是**回滚之后重刷真的会落到另一项** —— 教练那句话这才成立。
实测：第一次落点 `def` → 回滚 → 重刷落点 `spa`（确实换了）。

## 八、两档的关系：**练习引擎那一档**与**手游那一档**（2026-09-27 收口，审计 ①）

审计 ① 的原话：「`/nurture.html` 与营地页的『伙伴培养』仍在玩家可见路径上使用旧『训练点/培养格/加点』，
与新口径『培养 = 刷新天分』直接矛盾，且两套各有 localStorage 键、互不相通。」这一节把**关系**写死，
判据在 `tests/roco-nurture-page.test.js` ⑤（含"跨档读对方的键"必红的反证）。

| | 练习引擎那一档（营地 / 训练场 / 「练习养成（三只）」） | 手游那一档（622 图鉴 / 标准 PVP / 我的盒子） |
|---|---|---|
| 培养是什么 | 训练点 + 培养格 + **加点**（这一档引擎**自己的**规则） | **刷新性格 / 刷新天分**（原版没有加点） |
| 存档键 | `pet-coach-growth-v1`（`src/game/progression.js` 的 `PROFILE_STORAGE_KEY`） | `roco.box.individuals.v1`（`src/client/box-individuals.js`） |
| 「培养」入口 | roco.html / xiaoya.html 的导航按钮「✦ 练习养成（三只）」 | 营地页首页「培养」按钮、局末「培养」——都指向 `/box.html` |
| 数字从哪来 | `src/game/*` 的规则常量与本机存档 | `src/coach/talent.js`（种族值读归一化图鉴） |

**明确决定（不是"暂时这样"）**

1. **不迁移、也不合并两个存档键。** 它们是两个不同东西的进度（三只自研宠 vs 622 图鉴里的个体），
   任何"把培养格换算成天分"的自动迁移都是编事实。两端各读各的键；
   **跨档读对方的键 = 判据判红**。
2. **玩家路径上「培养」= 刷新天分。** 营地页首页那个「培养」按钮与局末的「培养」一律指向 `/box.html`；
   练习那一档只能从 roco.html / xiaoya.html 上写着「三只」的那个按钮进去。
3. **分档说明必须在页面上看得见**（三处）：`nurture.html` 顶部的横幅、nurture 页规则区的来源句、
   营地页「伙伴培养」那一段。三处都说同一件事：这一档是练习引擎的规则，手游那一档没有加点。

**为什么不做"退役"而是"说清档位"**：练习那一档是 KEEP（红线：不许重写老页面），
它的加点是它自己规则的产物；真正要禁的是**把它当成《洛克王国：世界》的培养**。
所以这里做的是"入口改道 + 分档说明 + 跨档读取判红"，而不是把老页面删掉或改功能。

### 2026-09-27 第二次更正：回滚**不是"只许一次"**，而是"只退一步、次数不退"

上一节那条更正里，我替产品写了一句「**每人只许回滚一次**」（理由是"回滚会归还次数 ⇒ 三次限制被架空"）。
人类 2026-09-27 把口径说清楚了（逐字）：

> 「不是这个意思，我意思是，只能回滚只能回上一个状态，**不能回前两个状态**你懂吗？**不是回一次**，
> 还是三次刷新次数，回滚的话**不消耗也不返还**次数。」

所以规则改成三条，代码与文案都按这个来（`src/coach/individuals.js`）：

| 条 | 规则 | 判据 |
|---|---|---|
| ① | **一次只退一步**：永远只撤销"最近那一次刷新"（不能退回到两步之前） | `canUndo()` = 历史里**最近一条记录是刷新** |
| ② | **不能连着退**：刚退完时最近一条是 `undo` ⇒ 再退就是退两步 ⇒ 拒绝；**再刷一次之后又能退** | `undoLastRefresh()` 抛 `already-undone`（文案说清"一次只能退一步"） |
| ③ | **次数不退**：退掉的那一次刷新不还给你，回滚自己也不消耗次数 | `undoLastRefresh()` 不动 `refreshes` |

**后果（如实写）**：三次刷新是**总预算** —— 退一步之后再刷，用的还是剩下的次数（例：3 次预算，
刷 1 次（剩 2）→ 退（还是剩 2）→ 再刷（剩 1）…）。所以"退到满意"是做不到的：
三次用完就定格，想要别的落点只能**再养一只同种个体**（这正是"可重复拥有"的意义）。

真机实测（`browser-box-acceptance.mjs` 的 28 号，真鼠标点）：
`0级/3次 → 1级/2次「加到物防」 → 回滚 0级/2次（次数不动、按钮消失） → 重刷「加到魔防」（第 2 级）——
回滚之后重刷的，换掉了原来的「物防」`。整套 29/29 + 反证 11/11。

## 2026-09-28 复核：性格幅度的主源（人类要求"再查一下"）

小破站 WIKI 的 [`Module:NatureDex`](https://wiki.biligame.com/rocom/Module:NatureDex?action=raw) 头部把口径写全了
（数值取自游戏 UI 反编译 `UMG_PetCharacter_PopUp_C.lua:103-104`，突破阶段按 `BREAK_NUMBER_CONF`）：

```
负面 = −negative_effect_proportion//100 %              （固定）
正面 = (positive_effect_proportion + positive_effect_grow×(突破阶段−1))//100 %
突破阶段 1~6  ← 20/30/40/50/60 级
当前 30 种玩家性格数值完全一致：负面 −10%，正面 +10% 起每次突破 +2%、满突破 +20%
```

**结论：默认（零突破）＝ +10% / −10%**（人类 2026-09-28：「好像默认是一个+10%一个-10%」—— 对）。
本仓每一处的档位：`natureFactor` 缺省 0 突破 ⇒ 1.1/0.9；面板问句 0 突破 ⇒ 1.1/0.9；
性格建议 0 突破 ⇒ 1.1/0.9；**只有 `pvpPanelOf`（PVP 归一化）取满突破 ⇒ 1.2/0.9**
（那一档必须 1.2 才对得上公布的 PVP 一速榜 9/9）。
