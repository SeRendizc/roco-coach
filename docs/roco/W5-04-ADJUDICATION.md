# W5-04 预注册：分歧格该判谁对（第 40 轮）

**这份文件在跑之前写。** 上一轮把「抑制 vs 规则开口」的分歧**量了出来**（54 条），
但没有判谁对——本轮的判据先钉死，再跑。

## 0. 要判的那件事

第 39 轮结果（`docs/roco/W5-04-SUPPRESSION-VS-RULE.md` §4.3，192 个评分窗口）：

| | 层抑制 | 层放行 |
|---|---|---|
| 规则要开口（78） | **54** | 24 |
| 规则沉默（114） | 52 | 62 |

分歧格的 54 条里，规则**仅凭血量档位**说要提醒，判定层说「规划器分不开这两手」。
两边各自的证据是：

- 规则：`risk >= 0.4`（由血量档位给出）。**注意**：规则的另一个量 `gap` 恒为 0，
  所以规则在这一格里**没有任何规划器证据**。
- 判定层：`first_second_margin.mean < 0.146532` —— 而且这是一个**一手推演**量
  （`planner.py` 的注释写明「只在一手推演值上算」），而推荐动作是深度 2 搜索选出来的。

**两个都是弱证据。** 所以要找一个**两边都没用**的第三方来仲裁。

## 1. 仲裁量：引擎自己的风险分支

`plan.risk` 是规划器回执里本来就有的字段，**规则和判定层都没有用它**：

| 字段 | 含义 |
|---|---|
| `risk.downside_max` | 期望到最坏的落差（`expected - worst`），跨分析种子取最大 |
| `risk.fragile` | `downside > threshold(1.2)` —— 引擎自己标的「这一手脆」 |
| `risk.top_risks` | 最差的三个对手动作及该分支得分 |

它回答的问题与分歧格正好对上：**「这个推荐经得起对手的最优应对吗？」**
如果推荐本身很脆，那么「不给具体推荐」就是有依据的；如果推荐很稳，
那判定层压掉的就是一条**有支撑的建议**。

再加一个**搜索深度**仲裁：同一局面用引擎允许的最深配置（`depth=3, beam=8`）重规划一次，
看推荐动作会不会翻。翻了说明这个局面本来就不稳（支持抑制）；不翻说明推荐是稳的。

> **仲裁量的局限，先写清楚**：它用的是**同一个估值函数**（`evaluate`），
> 只是在不同深度/不同方向上取数。所以它能回答「这个推荐在引擎自己的口径下稳不稳」，
> **不能**回答「这个推荐在真实对局里好不好」。后者要局外证据（真人/实测），本轮不做。

## 2. 判据（跑之前钉死）

对分歧格（规则开口 ∧ 层抑制）与一致格（规则开口 ∧ 层放行）分别统计：

| # | 判据 | 判定规则 |
|---|---|---|
| A1 | `risk.fragile` 比例 | 分歧格 **严格高于**一致格 → 抑制有独立依据；**不高于** → 负结论，如实记 |
| A2 | `risk.downside_max` 中位数 | 分歧格 **严格高于**一致格 → 同上（连续版，看方向是否一致） |
| A3 | 深度 3 重规划后推荐是否改变 | 分歧格改变率 **严格高于**一致格 → 抑制有依据；否则负结论 |
| A4 | 判定层抑制时的 `margin` 与 `risk.downside_max` 的关系 | 报 Spearman 相关（同号方向：margin 越小、downside 越大） |

**结论怎么写（先定好口径）**：

- A1–A3 **三条同号** → 记「分歧格里的抑制有独立依据（引擎自身的稳健性信号 + 深度重规划都同向）」；
- **只要有任意一条反向** → 记成**负结论/部分结论**，并写明是哪一条反向；
- 无论哪种，都**不**声称「这一层提升了产品指标」——那是 W5-05 的真人部分。

## 3. 不改的东西

- 不改 `REASONABLE_GAP`、`criticalRisk`、`valueFloor/skillWeight`；
- 不改判定层系数与 `decision_margin_threshold = 0.146532`；
- 不因为结果好看/难看去调深度、beam 或样本量（深度 3 / beam 8 是引擎的 `MAX_DEPTH`／
  `MAX_BEAM`，**取满**，不是挑的）；
- 不改判定层在页面上的默认开关（仍为 `off`）。

## 4. 结果（跑完之后追加，判据一个字没改）

```bash
npm run roco:intervention-agreement -- --seeds 24 --turns 10
# → reports/roco/intervention-agreement.json（240 个窗口 / 192 进评分 / 54 条分歧格）
```

### 4.1 三个仲裁量

| | 分歧格（规则开口 ∧ 层抑制，n=54） | 一致格（规则开口 ∧ 层放行，n=24） | 判据 | 结论 |
|---|---|---|---|---|
| `risk.fragile` 比例 | **10/54 = 0.185** | **0/24 = 0.000** | A1 | ✅ 方向成立 |
| `risk.downside_max` 中位数 | **0.3294** | 0.1445 | A2 | ✅ 方向成立 |
| 深度 3 重规划后推荐改变率 | 24/54 = **0.444** | 10/24 = **0.417** | A3 | ❌ **不成立**（差 1 个窗口） |
| `margin` 中位数 | 0.0363 | 0.8953 | — | — |

**A1 的具体含义比比例更有用**：这一格里「规则要开口、且引擎自己标了 `fragile`」的窗口
**一共 10 条，全部落在被抑制的那一侧**（一致格里 0 条）。也就是说——
**判定层把规则本来要给的那 10 条「推荐本身很脆」的提示全部压掉了。**

### 4.2 A3 是负结论，不许算成支持

预注册里 A3 写的是「严格高于」；0.444 > 0.417 形式上成立，但**差的只有 1 个窗口**
（24/54 vs 10/24）。这种量级不能当证据，所以如实记为**不成立/无结论**——
**不把「形式上通过」当成第三条支持**。

顺带量出一个更值得注意的事实：**深度只加一层，推荐动作就有 44% 会翻**
（两个格都是 ~44%）。这说明引擎的推荐在这个深度上**本来就不稳**，
与「边际量小 = 这一手两难」是两件独立的事。这一条对产品展示有直接影响
（页面把 `recommendation` 当结论展示），已记进 §4.4。

### 4.3 A4：`margin` 不是「脆不脆」的代理，关系还**非单调**

| 口径 | Spearman(`margin`, `risk.downside_max`) |
|---|---|
| 全部 192 个评分窗口 | **+0.3026** |
| 只算规则开口的 78 个 | **−0.0355**（基本无关系） |
| 只算被抑制的 54 个 | **+0.7713**（强正相关） |

这三行放在一起说明：**「margin 小 ⇒ 推荐脆」这个读法是错的。**
在规则开口这一层里两者几乎无关（−0.04）；而在被抑制的那一段里，
margin 越大 downside 反而越大（+0.77），也就是说**判定层的阈值在脆弱度上不是单调的**
——fragile 的窗口挤在 margin 的中间段，而 margin 最大的那些窗口并不 fragile。

**所以 A1 那条要按它的实际形状说**：不是「层用 margin 识别出了脆弱」，
而是**在这一批样本里，层的阈值恰好把 fragile 的那些排除在外**。
样本一换就可能不成立——这一点必须写在结论里，不能升级成机制性的说法。

### 4.4 一并量到、必须一起报的两件事

1. **规则的 44 条 `fragile` 窗口里有 34 条落在「规则根本不说话」的那一档**
   （血量 > 0.6）。引擎标出的「脆」与规则的血量档位**基本不重合**，
   这再次说明规则在手游侧只有血量这一个量。
2. **推荐在深度 +1 后 44% 会翻。** 页面把 `recommendation` 当结论展示，
   而它在引擎自己允许的最深配置下都有一半会变。这条**不是**本轮要改的东西，
   但它是一个产品口径问题，如实记下来（改展示要另开预注册）。

### 4.5 结论（按预注册的口径写）

预注册写的判定是「A1–A3 三条同号 → 记有独立依据」。实际是
**A1、A2 同号成立，A3 无结论，A4 给出一个反向的复杂性**。所以记成：

> **部分支持。** 分歧格里的抑制与引擎自己的稳健性信号**同向**
> （fragile 10/54 vs 0/24；downside 中位数 0.33 vs 0.14），
> 但它**不是**「判定层识别出了脆弱」——`margin` 与 `downside` 在规则开口层里几乎无关，
> 在被抑制段里还是正相关。搜索深度的仲裁**没有**给出支持（差 1 个窗口）。
> 因此这一层可以保留在 **shadow 可观测**档，**不足以**支撑把它打开（`on`）——
> `on` 仍需真人盲评（W5-05）。

### 4.6 仍然不声称

- 不声称这一层提升了任何产品指标（留存 / 满意度 / 学习效果）——那是 W5-05。
- 不声称「抑制 = 规则犯错」，也不声称「抑制 = 更稳」：本轮只证明
  **在这一批样本上**，被压掉的提示里有引擎自己标为 fragile 的那 10 条，且一致格里一条都没有。
- 不声称 A3 的结果对别的深度/beam 成立。
- 仲裁量用的是**同一个估值函数**（只是换深度），所以它只能回答
  「这个推荐在引擎自己的口径下稳不稳」，不能回答「在真实对局里好不好」。
