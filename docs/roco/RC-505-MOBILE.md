# RC-505 移动端验收（五个页面、两档窄屏、同一把尺子）

> 脚本：`scripts/roco/browser-mobile-sweep.mjs`（`npm run roco:mobile-sweep`）
> 产物：`reports/roco/rc505/mobile-sweep.json` + 10 张截图
> 门禁：第 **20** 个套件 `mobile-sweep`

## 为什么需要它

窄屏判据此前**散在四个脚本里**：`roco.html` 在 UX 验收（390px 三条）、工坊模块在工坊验收
（390px 四条）、盒子页在盒子验收、营地页在 M0 验收。散着量有两个问题：

1. **没有任何一处**回答得了「这一版**每一页**在手机上都不横向溢出吗」；
2. 某一段版式被改坏时，只有正好跑那一个脚本才看得见 —— 而「没红」与「没在跑」
   在 CI 里长得一模一样（这个仓库已经吃过一次同形的亏，见 RC-501）。

所以这一条把五个公开页面放进**同一把尺子**：`index.html` / `connect.html` / `roco.html` /
`box.html` / `workshop.html` × 两档窄屏（**390×844** 与 **360×640**）× 五条判据。

## 尺子（判据是纯函数，反证直接喂坏数据给它）

| 判据 | 说明 |
|---|---|
| 不横向溢出 | `scrollWidth === clientWidth`。这条是用户 P0 点名的（A7） |
| 声明的可点控件 ≥44×44 | **只对声明的范围**判红（见下表）——「整页每个链接都 44px」会把两个 KEEP 老页面也拖进来，而红线写着不许重写它们 |
| 主操作在首屏 | **逐页显式声明**的主操作（`PAGES[].primary`）必须在视口高度内；没声明就不判 |
| 页面真的渲染了 | 可见文本长度下限（**包括 shadow root 里的文本** —— 工坊模块渲染在自己的 shadow root 里，只看 `body.innerText` 会把它整块误判成白屏，第一版就是这么错的） |
| 控制台干净 | 这一页没有 `console.error` / 未捕获异常 |

**筛选菜单是打开着量的**：那个状态此前没有任何判据覆盖 —— 而它真的坏过。

## 实测：找到并修掉三个真缺陷

| 缺陷 | 表现 | 修法 |
|---|---|---|
| 模式徽记写死 `nowrap` | 360px 上 `#prematch-chip` 宽 355px、起始 left=12 ⇒ **整页横向溢出 7px** | 窄屏让它折行（`white-space:normal` + `overflow-wrap:anywhere`） |
| 筛选菜单是绝对定位浮层 | `roco.html` 360px 上菜单一打开 `scrollWidth` **471 > 360**（溢出 111px）；贴右会左边出屏 | 窄屏改成**就地展开**（`position:static` + `.fmenu[open]{flex-basis:100%}`），两侧都不越界 |
| 盒子页同样的浮层 | 390px 上菜单打开 `scrollWidth` **530 > 390**（溢出 140px） | `box.css` 同一修法 |
| 拇指目标不够 | `#coach-entry` 35px、`.side-tab` 38px、`.filter-reset` 29px | 窄屏统一 `min-height:44px`（注意 `.seg .side-tab` 是两个类，单写 `.side-tab` 会被压住 —— 第一版实测仍然 38px） |

修完之后：**10/10 判据通过**，`roco.html` 上声明的 **35 个**可点控件在 390 与 360 上都 ≥44×44。

## 反证（5 条，判据没命中也算失败）

横向溢出 20px / 声明的控件缩到 30×30 / 主操作推到视口下方 / 可见文本只剩 5 字（白屏）/
控制台 1 条报错 —— 同一把尺子逐条报出问题。

## 如实边界

- 这一条只量**版式**（溢出 / 触控尺寸 / 首屏 / 白屏 / 报错）；功能正确性由各自的验收脚本负责。
- 触控目标**只对声明的范围**判红。整页其它小于 44px 的元素**只记账**：
  营地页 36 个、加密配置页 2 个 —— 这两个是 KEEP 的老页面，红线不许重写，本轮不为它们改版式；
  `roco.html` 上还有 21 个（主要是开发者抽屉与折叠区里的次要控件，默认收起）。
- 主操作是**逐页显式声明**的，不是自动猜的：`roco.html` 认底栏那个 `#start-battle`
  （工坊里的开局按钮在 DOM 里更靠前，但它在页面下半部分，不是「一进来就能按」的那个）。
- 360×640 是**多加**的一档（用户只点名 390）：它的用途是抓「只在 390 刚好不溢出」的脆弱版式，
  实测确实抓到了 7px 那条。
- 两档都只覆盖**首屏 + 整页滚动宽**；`overflow: auto` 的局部滚动区里的横向溢出不在判据里。
