# RC-502 战斗信息架构（场上事实）

> 客户端：`src/client/roco.js`（`fieldFactsHtml` / `petCard` / `actionCardHtml` / `poolQueryOf`）
> 服务端：`src/server/roco-service.js`（`publicView()` 补两个引擎已经给了的字段；`roster` 支持 `support=all`）
> 单元判据：`tests/roco-page-ux.test.js`（10 条 RC-502，含 4 条必红）
> 浏览器判据：`scripts/roco/browser-roco-ux-acceptance.mjs`（7 条 + 2 条反证，真实键鼠）

## 为什么需要它

用户 P0 第 8 条写得很直白：**「页面看不到或点不动的能力，不得仅凭单元测试标记完成」**。
而在此之前，战斗页面上只有三样东西：血条、能量豆、异常。引擎的公开视图其实**一直在给**
印记、增益、防御冷却、能量上限，页面一个都没画 —— 这不是「引擎没给」，是**没人接**。

另一头也有一个真缺口：引擎按需推算的那 574 只（RC-402，`SIMULATABLE_UNVERIFIED`）
在页面上**根本够不到** —— 选宠页只列冻结已核验的 48 只。v3 的口径是「候选宇宙是全量 600+，
48 只只是迁移夹具」，所以全量视野本来就应该能选，只是必须**如实标出未核验**。

## 做了什么

### ① 场上事实（`fieldFactsHtml`）

每张战斗卡上一组事实，**逐项只在引擎给了的时候才出现**：

| 事实 | 来源字段 | 缺了怎么办 |
|---|---|---|
| 能量 `当前 / 上限` | `pets[].energy` + `self.energy_max` / `opponent.energy_max` | 上限拿不到就**只写当前值、不画豆子**（豆子的个数就是「上限」的暗示） |
| 异常 | `pets[].statuses` | 空就不画这一行 |
| 印记 | `pets[].marks`（名字是数据里的中文名，值是层数） | 空就不画；**不写「无」** |
| 增益 | `pets[].buffs`（只有己方有） | 认不出的键显示「未知增益」，原始键只进 `data-ff-unknown-keys`，不进可见文本 |
| 蓄力中 | `pets[].charging` | `false` 就不画 |
| 防御冷却 | `pets[].defense_cooldown` | `0` 就不画 |

`data-roco-field-facts` 把「这一张卡上真的渲染了哪些事实」写成属性
（`energy=2/6;marks=星陨印记:3;defense_cooldown=2`），验收脚本用它把 DOM 与 `state.view` 逐字对齐。

**增益的中文名是闭集**，来源是引擎真的会写的那些键：`atk/def/…`（`traits.py` 直接写
`buffs["atk"] += 100`）与四条属性威力键 `power_water/power_fight/power_bug/power_ice`
（`effects.py` 里只有这四条）。闭集外的键**不猜**。

**对手的增益不在公开视图里**（引擎只给对手场上的血/能量/异常/印记/冷却）。页面在对手那一栏
写明这一句 —— 不写的话，玩家会把我方「增益」那一行读成「双方都标了」。

### ② 换人卡写清「换上谁」

引擎给的 label 只有位次（`换上第2位`），而「第 2 位是谁」是公开视图自己就有的
（`self.pets[target_index].name`）。只写位次等于让玩家凭记忆换人 —— 这也是 A 组里
「页面看不到等于没有」的一条。名字拿不到就**只留位次**，不编。

### ③ 全量视野开关（默认关，逐字节不变）

选宠页多一个「包含按需推算的精灵（未核验）」：
- **不勾**：请求与结果逐字节不变（`offset/limit`，48 只 / 4 页）—— 既有 P0-1 判据全部照旧；
- **勾上**：请求加 `support=all`（服务端白名单新增这一个取值，别的取值 400），
  候选宇宙变成 622 只；每张按需推算的卡上写明「按需推算的配招 · 未核验」；
- 搜索这条路在全量视野下把取数上限从 200 提到 700（否则只搜到前 200 只）。

### ④ 服务端补两个字段（加性）

`publicView()` 原来把引擎已经给的 `defense_cooldown` 与 `charging` 丢掉了 →
页面永远画不出防御冷却。现在**只在引擎给了的时候**带出去（旧 fixture 形状不变）。

`roster` 路由新增 `support=all`，并在**分页分支**加 `build_support`
（默认无参回执**一个键都不加** —— 那份回执被禁止重跑的轨迹摘要钉着）。

## 浏览器实测（真实键鼠）

| 判据 | 实测 |
|---|---|
| 默认视野冻结 | `scope=frozen total=48 pages=4`，卡上支持等级只有 `FULL_VERIFIED`，搜不到幽星光 |
| 勾上开关换视野 | 真鼠标点开关 → `scope=all total=622 pages=52` |
| 按需推算的卡如实标记 | 真键盘搜「幽星光」→ 卡上「按需推算的配招 · 未核验」 |
| 全量视野的精灵能真的选上 | 真鼠标点它 → 进我方队伍 |
| 全量视野组队开局 | 真鼠标点满 3v3（我方 幽星光/雪影娃娃/喵喵）并开局 |
| 能量上限来自引擎 | `self=6 foe=6`，卡上「能量 ●●2 / 6」 |
| 印记逐条画在对手卡上 | 真鼠标点「错乱」→ 引擎 `{星陨印记:3}`，页面「印记 星陨印记 ×3」，钩子 `marks=星陨印记:3` |
| 防御冷却画在自己卡上 | 真鼠标「换上第2位 · 雪影娃娃」→ 再点「防御」→ 引擎 `defense_cooldown=2`，页面「防御冷却 2」 |

两条反证（把 DOM 改坏，同一条判据必须红）：去掉「未核验」标记 → 命中；删掉印记那一行 → 命中。

## 如实边界

- **蓄力中（术语 1007）够不到**：引擎里没有任何技能会把 `PetState.charge` 置位，
  所以这一行在浏览器里**驱动不出来**。代码留着（拿到 `true` 才画），但**不声称它被验过** ——
  要等引擎真的实现蓄力技能之后补一条场景。
- **印记只覆盖了「技能直接加印记」这一路**：`星陨印记` 这类由技能效果原语加的能画；
  由特性或回合末结算加的（`吸积盘`/`乌龟塔理论`/`风速仪` 那 31 条里的多数）在冻结 48 只里
  一条都驱动不出来，所以没进本轮证据。**31 条里有多少真的会落到 `marks` 上，本轮没数**。
- **增益只覆盖己方**：对手的增益不在公开视图里（引擎口径），页面照实说明，不补。
- **全量视野的 622 只里 574 只配招是推算的**（RC-402）：卡上标「未核验」，但
  「未核验」不等于「按规则结算过」—— 它只是能进引擎跑。
- 能量上限是**规则配置**给的（legacy 6 / 候选口径 10），页面不写死；但「上限到底是不是 10」
  本身仍属候选规则，台账里那条未核验（页面由 `unverified-note` 照实标出）。
