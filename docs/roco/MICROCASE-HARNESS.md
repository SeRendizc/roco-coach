## 0. 这份台账**不是**什么

- **没有任何一条 microcase 因为这份台账而「通过」。**
- `verification_passed` 恒为 false：通过只能来自游戏内实测。
- `ENGINE_ASSUMPTION` 表示「引擎有明确行为，但该行为未核验」，不是「已确认正确」。
- `observed` 是**真的跑一遍引擎**得到的结果，不是抄注释。

它在回答的是另一件事：**引擎对每一条待验机制现在按什么规则做，以及那条规则有没有被实测核验。** 两者是分开的两栏，不许混着读。

## 3. 怎么让这些变绿

只有一条路：**游戏内实测**。入口是

```bash
python3 scripts/roco/record-measurements.py --help
```

实测写进 `data/roco/measurements.jsonl`，再跑一次本脚本就会把两边摆在一起。
**判定规则要人来定**（例如「误差 ≤ 5% 算通过」），脚本不替人下这个结论——
否则就成了自己给自己判卷。

## 4. 需要的最少实测

按「一条实测能解锁多少条」排序：

1. **一次完整伤害**（技能名 + 双方精灵 + 是否防御 + 实际伤害数字）
   → 直接标定 MC-010 / MC-011 / MC-008，并给 MC-028 / MC-029 提供基线；
2. **一次同速对局**（两只速度相同的精灵，谁先动，重复几次）
   → MC-002；
3. **一次带属性增减的伤害**（例如「力量增效」后用同一技能打同一目标）
   → MC-028（相加还是相乘，差一倍）。

这三条都能在一局练习对局里拿到，不需要任何特殊环境。
