## 二、面试题点到的技术 → 落点与证据

### 1. ReAct / 工具调用（挂在①②）
- **落点**：`src/coach/runtime.js` 的 `gatherAgentEvidence`（规划器选工具 → 执行 → 回执进包 → 模型照回执说话）；工具合同在 `src/coach/toolbox.js`。
- **关键设计**：**该不该查**不交给模型 —— 政策（`policyFor`）能定的问句，第一枪由 `mustCall: policy.need` **强制**发出（`runtime.js:2809`）。起因是实测「这一族 6 条金标全部没读或读错」。
- **实测**：20 个常问问题 × 2 种页面形状 = 40 次真机里，**16 次直接由引擎本地作答**（0 次模型调用）；「现在该防御还是出招」会真的调 `simulate_branch`。
- **边界（诚实）**：六宠 PVP 链只有公开快照，`simulate_branch` 要的是服务端会话 ⇒ 目前回执会**如实说算不了**（`toolbox.js`，判据在 `tests/roco-battle-context.test.js` ③）。

### 2. RAG 工程（挂在①②）
- **落点**：`src/coach/rag-index.js` + `data/roco/rag/libs.json`（L1 台账/规则集、L2 数据包、L3 相性表、L4 战术卡、L5 术语、L8 持有名单）；引用守卫 `checkGroundedAnswer`（正文里的编号/引用必须真的交付过）。
- **实测**：语料 **1975 份**；检索判据 **14/14**，Recall@1 / MRR / 层级命中率全 **1.000**（`node scripts/roco/eval-rag-retrieval.mjs`）。
- **踩过的坑**：把 L4 战术卡直接塞进候选集后 Recall@1 从 1.000 掉到 0.794 ⇒ 加了「只在建议类问句里放卡片、只在定义类问句里放术语」的候选过滤，恢复 14/14。

### 3. Memory Stream / Reflection（挂在④③）
- **三类记忆**（`src/coach/memory.js` 文件头写明）：① 玩家**明说**的（`stated`/`preference`/`goal`/`favorite`）；② 系统**观察**到的（`journal`/`events`/`lessons`/`quizLog`）；③ 从①②**推出来的假设**（`reflections`/`mood`，永远标成假设、低置信、会过期）。
- **纪律**：情绪**只记玩家自己说的那个词**，不从连败/静默/慢操作推断（设计 C02）。
- **实测**：偏好真的影响结果 —— 速攻 ⇒ 培养建议「先试1点力量」、稳健 ⇒「先试1点耐久」；对局内同一局面综合分 **8.94 / 6.19 / 2.96**（速攻/中性/稳健），而「均值 11.8、最糟 -4.3」这些**事实逐字不变**。
- **补掉的一个洞**：进度一直在记、但 `quizMastery()` **从没被任何生产代码调用**；现在接进了出题（避开做过的变式）与「我学得怎么样」。

### 4. Agentic RL（挂②，**只做离线对比**）
- **现状：没做**。计划在 `docs/roadmap/MODEL-ROUTING-PLAN.md` 的 R1「云端质量对照」（同提示集跑 4B 与 DeepSeek，产 `reports/roco/model-quality-compare.json`）。
- 已有的可比基础：批量对局 + 建议策略（`src/game/engine.js` 的 `rankEnemyActions` 支持 `goal` 权重）、以及 `reports/` 下的对局产物。
- **为什么不在线训练**：没有算力也没有对局量；离线对比能回答"哪种建议策略赢得多"，这已经能改进产品。

### 5. 人格与情绪（挂④）
- **落点**：`src/coach/companion.js` 的语气档（`REGISTERS`）+ `memory.mood`（心情假设，只读玩家自己说的词）+ 复盘/开局等场景化措辞。
- **实测**：输赢两种记忆下的回答**确实不同**（见上表），而且都不编。

## 三、设计与实现里真正难的五件事（面试要的第 1 条）

1. **两套游戏数据不能混**：本仓有一个"练习引擎"（三只自研宠）和一份 622 只手游图鉴。混用的后果是**玩家看着不存在的宠物练**。做法：手游页面**故意不送**练习局存档（`src/client/roco.js` 里写着理由 + 判据钉住）；小测改用玩家自己那只（没有面板就**不出题**，见 `src/coach/runtime.js` 的 `quizPanelOf`）。
2. **模型很会说，但说的不是这个游戏的规则**：实测「水系打火系有优势吗？」模型答"宝可梦类游戏的常见规则"。做法：把这类问句**强制**路由到引擎的相性表，答案逐格来自回执（克制 ×2 / 不是克制关系）。
3. **回执预算会静默吃掉整族能力**：学习表整包 **23798 字节** > 运行时对第一枪回执的 **10000 字符**预算 ⇒ 回执被丢、模型只能答"证据里没有技能表"。做法：精简投影（**7166 字节**）。
4. **"记下来"不等于"用上了"**：练习进度、偏好都记了，但一个没被调用、一个只在两条路上生效。做法：接线 + 判据钉住"偏好必须改变建议/分数，但不许改变事实"。
5. **不许说"不知道"，也不许编**：模型给没标注的"不给结论"会被守卫打回；没有依据时改成**如实说清"为什么没有" + 两条能走的路**（例：「这一份上下文里没有对局记录…我不会凭空指出你哪一手有问题」）。40 次真机验收 **0 次服务出错、0 次被守卫打回**。

## 五、如实边界（面试时也该讲的部分）

- **六宠 PVP 的引擎分支模拟没接**：要服务端会话，目前只有公开快照 ⇒ 回执如实说"算不了"，不假装。
- **Agentic RL 只是计划**，没有任何训练产物。
- **手游侧的养成常量答的还是练习引擎的数**（能量上限 6 vs 手游 10）—— 改法有产品取舍（会从"给错数"变成"不答"），等人裁决。
- **质量盲评没做**：4B 与云端的答案谁更好，只有延迟与合法率，没有人评。
- `data/roco/normalized/**` 与旧规则集行为是冻结的（逐字节不可变），所有新能力都走"声明式"扩展。

## 六、Agentic RL：离线对比（2026-09-26 补上，脚本可重跑）

**做什么**：同一个开局种子、同一个对手策略，两臂配对打同一批对局 ——
手臂 A 是固定基线（服务端内置的贪心自动打），手臂 B **每一回合先问一次引擎**（`planBattle`，
就是教练在六宠对局里拿到的那份估值），按它的推荐选出对应合法行动再执行。两臂都不看对手私有信息。

**为什么这样算"用对战结果反过来挑建议策略"**：它回答的是产品问题「引擎的推荐到底比基线强多少」，
而不是训练一个策略。**不产出权重、不做在线学习** —— 当"强化学习"讲会过头。

```bash
node scripts/roco/eval-strategy-offline.mjs --seeds 8 --mode pvp-standard-six-pet \
  --json reports/roco/strategy-offline.json
```

**实测（2026-09-26，`reports/roco/strategy-offline.json`）** —— 四个对手策略、每臂 4 局、同种子配对：

| 对手策略 | 固定基线 | 听引擎建议 |
|---|---|---|
| `greedy_damage` | **负**（47 回合） | **胜**（37 回合） |
| `random_legal` | 胜（1 回合） | 胜（1 回合） |
| `conservative_switch` | 60 回合未分胜负 | 60 回合未分胜负（一直活着 6 只） |
| `shallow_search` | 胜（38 回合） | 胜（32 回合，更快） |
| **合计** | **2 胜 1 负**（已结束 3/4） | **3 胜 0 负**（已结束 3/4） |

**结论只说到证据支持的地方**：听建议这一臂**没有输过**，在两臂都赢的那一局里赢得更快（32 vs 38 回合）；
但**有效样本只有 4 个对手策略**（见下），所以这只能说"方向一致"，**不能**说"统计上显著更好"。

**报告里必须一起看的一个数**：「推荐命中合法行动的比例」= **130/130 = 100%** ——
说明两臂确实走在同一条建议链上（推荐的动作在合法列表里找得到），胜率差可以归因给"听不听建议"。

**两个限制（报告与脚本里都写着，不许抹掉）**：
1. **换种子不改变结果**：8 个种子两臂各 8 局，胜负与回合数**完全一致** ⇒ 同种子多局只等于**一个**样本。
   所以对比沿"对手策略"这个真正会改变对局的维度铺开，而不是堆局数。
2. `random_legal` 那种对手 1 回合就结束、`conservative_switch` 60 回合打不完 —— 这两种对局**信息量低**，
   把它们计入"合计"只是如实记录，权重不该等同。

**踩到的坑（写进脚本注释）**：引擎公开视图里结论字段叫 `battle_result`（不是 `result`）、对手叫
`opponent`（不是 `foe`）—— 用错名字的表现是"每局都算未结束"，胜率永远是 0/0，看着像对局没打完。
