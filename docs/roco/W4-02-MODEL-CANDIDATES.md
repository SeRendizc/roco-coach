# W4-02 预注册：**模型候选**轨迹集（第 41 轮）

**这份文件在跑之前写。** 判据先钉死。

## 0. 为什么现在能做：候选生成器不必是云端模型

W4-02 的第二半一直是「**模型候选**轨迹」，而它被记成「要 DeepSeek key」。
第 39 轮起这个前提不再成立：本机有一个**真的接进链路**的工具选择模型
（Qwen3.5-4B-4bit + LoRA `qwen35-4b-tool-v4`，见
`docs/roco/W4-04-SFT-PREREGISTRATION.md`，288 条门禁 **275/288**），
它经 OpenAI 兼容网关（`scripts/model/local-gateway.mjs`）可用。

所以本轮把「模型候选」用**本地模型**补齐，而不是继续挂着一个外部 key。
这不是降低标准：候选仍然由**真模型**产生、仍然过**同一个判定器**、
仍然保留失败轨迹；差别只是候选来自本机。

## 2. 订正：M1 原来写的 2,000 是**做不到的**

第一版 M1 直接抄了 W4-02 原文的「2,000—5,000」下限，**没有先量天花板**。跑之前量了：

```bash
# 每条任务可用多少世界，由任务集与世界池唯一决定
worldsFor(task, 9) 逐任务求和 = 1752
按类别: rules_lookup 648 / roster_constraint 216 / continue_stop 324 /
        brief_explain 180 / tool_failure 108 / stale_state 108 /
        evidence_conflict 108 / silence 60
```

模型臂的产物是「一个 `(任务, 世界)` 一条轨迹」，而世界池里每条任务只有 **3—9** 个
可用世界（第 36—37 轮把池子加到 23 个世界，就是这个数），所以**上限是 1,752**。
在 `temperature 0` 下重复采样只会产生重复行，不是新样本。

所以 M1 订正为 **≥ 1,700，天花板 1,752**。
**要真的到 2,000+，必须扩世界池**——那会同时改变规则臂那份产物（两者共用 `worldsFor`），
属于另一次要单独预注册的改动，不在本轮。

（这条订正写在**产出任何轨迹之前**，并且保留在这里而不是悄悄改掉：
「先写判据」的意义就在于它会被现实打脸时留下痕迹。）

## 3. 判据（跑之前钉死）

| # | 判据 | 阈值 | 为什么 |
|---|---|---|---|
| M1 | 轨迹条数 | **≥ 1,700**（天花板 **1,752**） | 见下面的订正：W4-02 写的区间下限是 2,000，但模型臂的**结构上限**是 1,752 |
| M2 | 八个类别 × 三个切分侧都要有 | 全部出现 | 少了哪一类，那一类就不能被当门禁用 |
| M3 | **同一个判定器** | `verify-agent-trajectories.mjs` 的结构 + 离线回放**全过** | 「用同一把尺子」是横向比较的前提 |
| M4 | 头部必须记**模型身份** | 模型路径 + 适配器 basename + 适配器 sha256 + 提示摘要 | 第 38 轮的存档错位就是因为没有它 |
| M5 | 失败**原样保留** | `stopped` 逐条记录，不做「重试到成功」 | 把失败洗成成功的第一步就是丢掉这个字段 |
| M6 | 与规则臂**逐任务配对**报差异 | 退化/扳回/都错三个数都给 | 只报总分会把「这边修好、那边坏」盖住 |
| M7 | 判定器两向自证 | 反向对照必须覆盖到**全部 11 条判据** | 只有正向的判定器等于「总是 true」 |
| M8 | 错误目录从**这一份**重建 | `source_sha256` 与新产物对得上 | 目录的溯源不能指向会被覆盖的路径 |

**口径上必须写明的两件事**：

- **不声称字节可复现**。规则臂那份是字节可复现的（无时间戳、无随机）；
  模型臂**不能**这么声称——同一份权重在同一台机器上也可能因浮点/并发而逐条不同。
  所以模型臂的产物靠**身份摘要**（适配器 sha256 + 提示摘要）钉住，而不是靠重跑一致。
  产物头部的 `disciplines` 要写明这一点。
- **通过率不是胜率，也不是「模型能力」**。它只说明「在这批构造任务上，
  这个适配器按这套判据过了多少条」。任务集与局面都是构造的。

### 5.1 两条独立代码路径在**同一批窗口**上判定完全一致

这是本轮最有价值的一条守卫：`build-agent-trajectories.mjs`（本产物）与
`shadow-replay.mjs`（影子回放）是两条各自独立的链，**用同一个判定器**。
按 `(case_id, world)` 逐条对拍 288 个共同窗口：**判定逐条相同**，
且两份产物记的适配器 sha256 一致（`tests/evals/roco/model-trajectories.test.js`）。

> 第一版这条守卫比的是「按类别总数」（1,617 vs 275），于是红——但那**不是**尺子分叉，
> 是两份产物覆盖的**窗口集不同**（9 个世界 vs 1 个世界）。
> 教训：**比数字之前先确认两个数字量的是同一批东西。**

### 5.2 与规则臂配对：退化 42、扳回 0

模型那份 1,752 个窗口里，有 **864** 个与规则臂产物（每任务 3 个世界）重合。
在这 864 个窗口上逐条配对：

| | 条数 |
|---|---|
| 规则 baseline 通过、模型通过 | 822 |
| **规则 baseline 通过、模型判挂（退化）** | **42**（`roster_constraint` 33、`rules_lookup` 9） |
| 规则 baseline 判挂、模型通过（扳回） | **0** |
| 两边都判挂 | 0 |

规则 baseline 在这 864 个窗口上是 **864/864**（任务集本来就是照着规则能过设计的）。
所以结论必须直说：**模型臂在这套任务集上从来没有超过规则 baseline，
它退化 42 条、扳回 0 条。** 这一份产物的用途是**候选数据与困难样本**，
不是「替换规则」。

### 5.3 SFT 把失败**换了一种形状**，而不是消灭了失败

同一套分类器（同一个文件、同一套 `match`）在两个来源上的对比：

| 失败分类 | 基座（63 条） | **SFT v4 之后（135 条）** |
|---|---|---|
| `asked-nothing`（没有发出任何工具调用，参数装配被拒） | **34** | **0** |
| `stopped-without-tool`（输出了 `{"stop":true}`，而任务要求查一次） | 1 | **90** |
| `wrong-args`（工具选对了、参数不对） | 15 | 36 |
| `wrong-tool`（工具选错） | 13 | 9 |

**读法**：SFT 把「连合法输出都给不出」（`invalid-arguments` 那类）**清零**了，
但失败**搬到了另一处**——现在模型输出格式完全正确、却**选择停下不查**（90 条）。
按类别看，剩下的 135 条里 `roster_constraint` 占 **105** 条。

**这直接指出下一步该补什么数据**：不是继续教格式（那已经好了），
而是教「有具体事实问题时不要停」——也就是 `stopped-without-tool` 这一格，
以及 `roster_constraint` 这个类别。这与 `docs/roco/SHADOW-REPLAY.md` §7 的结论一致。

### 5.4 仍然不声称

- **不声称字节可复现**（头部已写明）：同一份权重重跑可能逐条不同，靠身份摘要钉住；
- 不声称这是「模型能力」的度量：任务集与局面都是构造的，8 类里 6 类两边都满分
  （那 6 类**区分不出**差别，只有 `rules_lookup` 与 `roster_constraint` 有信号）；
- 不把通过率叫胜率，也不声称模型可以替代规则 baseline（§5.2：退化 42、扳回 0）；
- 不声称候选修复有效：目录里 `verified` 恒为 `false`。
