# 陪练「不打扰」验收：预注册

日期：2026-09-21　轮次：第 20 轮　状态：**跑之前先写死判据**

这份文件针对目标里第 6 条：**陪练的情绪、偏好与长期记忆是独立产品能力，
不能被对局历史摘要替代；要有真实主动触发与不打扰验收。**

它**只**覆盖「不打扰」这一半，并且明确区分两件事：

| | 谁来判 | 状态 |
|---|---|---|
| **不打扰（可机器判定）** | 程序 | **本轮做**，判据写在下面 |
| **像不像人 / 讨不讨厌（要真人）** | 3—5 位真人盲评 | 外部阻塞（W5-05），本轮**不声称** |

「机器判定通过」不等于「玩家不烦」。这条区别写在每一个结论前面，不允许混用。

## 1. 被测对象：真实主动触发通道

被测入口是**唯一**那个：`companionEvents(game, {...})`
（`src/coach/companion.js`）。它是页面原位气泡真正调用的函数——
一次只返回一个事件，或返回空数组表示这一回合不说话。
本验收不模拟页面，也不另写一套判定。

会话状态用 `companionSession(memory)`（它自己会读 `memory.journal` 里近 7 天的
主动关闭记录来收紧上限），气泡时序用 `companionCueSlot(...)`。

## 2. 指标（P1—P7）与阈值

固定 fixture：8 个确定种子（3/5/8/11/17/23/29/31）的**逐回合重放**。
高优先级观察在每局里只有 1—2 条会被真正提出，所以两类窗口的真实数量并不对等：

| 类别 | 怎么构造 | 实际窗口数 |
|---|---|---|
| 「该说话」 | 空账本重放，**有事件被提出**的回合 | **20** |
| 「该沉默」 | 前一趟把该局能说的都记进 `said` 之后重放，**不再提出**的回合 | **86** |

两类的数量不等不是缺陷：现实里绝大多数回合本来就没事可说。
判据用**比例**而不是绝对条数，所以不等的窗口数不影响口径。
硬边界另给 4 个构造窗口（PVP / 预制体验 / 刚被点掉 / 显式安静）。

| # | 指标 | 阈值 | 为什么是这个 |
|---|---|---|---|
| **P1** | 该沉默的窗口上真的沉默 | **≥ 0.90**（本轮 **86** 个该沉默窗口里最多开口 **8** 个） | 机器判定的「不打扰」下限。留 10% 余量是因为素材判定本身有噪声。**绝对条数跟着窗口数走**：这里 8 = 86 的 10%，换一批素材要重算，别把这个数当常量（第 45 轮修正：原文误抄了「该说话」那一列的 20） |
| **P2** | 该说话的窗口上真的说话 | **≥ 0.80** | 反向对照。只会闭嘴的陪练不算合格，「不打扰」不能靠永远不说来实现 |
| **P3** | 硬边界零违反 | **= 0**：线上竞技 PVP 中、玩家刚点掉之后、显式安静偏好下，**一次都不能开口** | 这三条是不可交换的硬边界，违反一次就整体不合格 |
| **P4** | 同一局上限 | 每局开口次数 **≤ `session.limit`**，且 `limit` 本身按 7 天关闭次数收紧（0/1/3） | 上限是既有产品规则，验收只是核对它真的生效 |
| **P5** | 冷却与去重 | 同一 `(event, 事实)` 在一局内**不重复**；已标记 `said` 的事件不再返回 | 重复说同一件事是最典型的打扰 |
| **P6** | 每条话都有真实素材 | 返回的每个事件都能产出 `proactiveText(...)`，且过 `checkCompanionRestraint` | 「宁可少说，不说废话」的可核对版本 |
| **P7** | 气泡时序 | `companionCueSlot` 在排队超 20 秒时给 `drop`、刚显示过给 `hold` | 一闪一闪比不说更烦；这条有明确常量 |

## 3. 判据自身必须可判别

每条指标都要有一个**必过**与一个**必挂**的构造样例（与 W5-04 的 H8 同一纪律）。
「永远返回空数组」的陪练必须挂 P2；「每回合都说话」的陪练必须挂 P1 与 P4。

## 4. 明确不声称

- 不声称真人觉得不烦——那要 W5-05 的盲评；
- 不声称覆盖了全部打扰形式（只覆盖这份 fixture 里的 40 个窗口）；
- 不把「P1 高」读成「陪练质量好」：它只说明该闭嘴时闭嘴了；
- 不声称这与情绪/记忆能力等价——记忆控制（查看/纠正/删除）由 C03 单独覆盖。
