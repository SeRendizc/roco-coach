## 按顺序执行

| 步骤 | 操作 | 必须留下的结果 |
|---|---|---|
| 03.1 | 审查现有候选生成是否真正使用公开物种和可学技能；登记隐藏值读点及没有依据的默认概率。保留有效模块，不另造平行信念系统。 | 候选生成路径与风险清单。 |
| 03.2 | 生成合法且相容的候选集合：已见物种、可能技能、可支持的个体范围和动作；每项保留来源、规则版本、证据与未知项。 | 候选协议和三个可复现局面。 |
| 03.3 | 依据已出技能、先手关系、可见伤害与状态更新候选。考虑随机伤害和多种未知因素；证据不唯一时保留多解，不强行猜中真实配装。 | 一次出招前后的候选差异与排除理由。 |
| 03.4 | 没有真实频率数据时使用情景集合与范围；均匀权重若仅用于基线必须显式标识，不展示为概率预测或最优结论。 | 无频率、空候选、矛盾证据的返回结果。 |
| 03.5 | 工具只输出本次分析需要的假设，限制候选数量并保留截断信息；候选过多时先按可解释规则缩减，不隐去重大威胁。 | 预算、截断与未知配置保留策略。 |

每做完一步更新 STATE.json 的 step 和 next_action。测试失败先定位本步最小原因；不要跳到下一步靠更多功能掩盖失败。

## 通过条件

- [ ] 候选来源可追溯，已观察事实与推测不混用。
- [ ] 隐藏真值变化不改变相同公开史的候选；新公开证据能合理更新。
- [ ] 候选为空或矛盾时明确降级，不生成伪精确概率。

## 必须执行的反例

- 同一公开伤害由两种个体配置都能解释时，两者都应保留。
- 已知不合法的技能组合不得进入候选。
