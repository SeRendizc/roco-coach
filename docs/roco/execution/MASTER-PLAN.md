# 小芽 DSH 总执行计划

2026-09-30 · 本计划把产品愿景转换为可连续执行的链路。所有初始状态为未验收；不得从文档推断完成。

## 目标与入口

目标：玩家能够完成“配队 → 看见公开阵容 → 获得当前合法建议 → 自己行动 → 看懂关键复盘 → 在新局面独立判断”。Coach 是主线，模拟器、配队、培养、陪伴与模型均服务于它。

产品定义见 [产品愿景与路线](../PRODUCT-VISION-AND-ROADMAP.md)。执行从 [00 服务恢复](00-PLAN.md) 开始；续跑只读 [STATE.json](STATE.json) 的 active_plan 与 next_action，不凭聊天记忆选择下一项。

用户已要求 DSH 逐项持续执行：完成一项后回到本总计划并继续下一项。用户新指令优先于本计划；本文件不授权重启用户服务、清理数据、启动训练或联系真人参与者。

## 每次运行的控制流程

1. 读总计划、STATE.json、当前分计划及它的最新 result.json。重新取 HEAD、工作区差异、活动成员/文件拥有者、8765 status；旧证据保留，但不能代替当前核对。
2. 有正在修的 P0 先承接，不重做。将已有实现与证据逐项映射到当前分计划；只有仍适用于当前版本的证据才可复用。
3. Lead 在 write_owners 登记实际文件、负责人和当前步骤。可以安排独立只读调查或不重叠文件任务；共享文件单一写入者。成员返回证据，Lead 做集成验收与状态更新。
4. 每次取当前分计划的一小步：实现最小改动 → 定向验证 → 留下证据 → 更新 step 与 next_action。一次不要跨多个分计划堆大补丁。
5. 当前项验收失败时，status=running，记录原因，继续修当前项；不得靠删除测试、放宽边界、修改黄金答案或包装措辞刷绿。
6. 通过必要门槛后生成 result.json，核对产物与版本，提交仅属于自己的文件，推送 Gitee 当前开发分支并验证远端 SHA。将本项标 passed，active_plan 切到 next，立即读取下一分计划并执行。
7. 阻塞时登记具体缺什么、已尝试什么、谁能解除、哪些步骤不依赖它。只继续明确无依赖的工作；不得把等待授权视为同意，也不得跳过前置门槛伪造通过。
8. 每次上下文将尽、进程退出或会话交接前，更新 STATE.json 和简短交接；恢复后从 next_action 续跑，不新写一套平行总计划。

正常的阶段完成不是停机点。只有用户叫停、明确外部依赖阻塞、工具硬限制，或整个计划真实完成时才可停止。若 DSH 有运行轮次/预算上限，必须如实登记限制并保存检查点；本文件不是调度器，不能自行越过平台限制，也不能声称会无限后台运行。

## 唯一状态与依赖规则

STATE.json 由 Lead 单独更新。状态为 pending / running / passed / blocked / waiting_external；active_plan 是当前工作入口。不要在多个文件维护互相冲突的勾选进度。

每项同时记录 code、isolated、player：unverified / passed / failed / pending_authorization / not_applicable。分计划 passed 表示其明确要求的开发与隔离门槛通过，不自动表示玩家端部署通过。总计划最终完成必须满足真人验收及需要的玩家端验收，不能从子项 passed 数量推断。

顺序依赖为 00→01→02→03→04→05→06→07→08→09→10→11→12。只有 00/10/11 明确允许玩家部署单独等待，才可继续隔离工作。若前项后续被发现回归，撤销受影响项的 passed，标明影响范围，先修复并复验必要链路。

所有数字目标为规划建议，不能伪称已经达到：时延暂以本地 p95≤1秒、复杂首条有效结论 p95≤3秒为目标；以实测设备/样本解释结果。真人首轮建议至少 5 人、至少 4 人独立完成核心链。事实/权限/合法性违规不能用平均分抵消。

## 统一证据包

每项使用 reports/roco/product-execution/<ID>/；创建目录不是完成。格式见 [EVIDENCE-TEMPLATE.md](EVIDENCE-TEMPLATE.md)。证据包含实际命令、完整退出码、精确版本、公开输入、假设、合法动作、前后状态和界面结果；敏感数据不入库。

必须证明与本项相关的反例会失败或被安全拒绝。已有测试名只作为阅读入口，实际命令要按当前代码核对；不能把静态关键词测试当成功能验收。不要为了凑数量扩写镜像实现的测试。

## 统一场景矩阵

- 战术：克制换人、未知配招、低能量、濒死、同速、开局已见但未上场、对手实际换人。
- 信息：预览前、预览后、无预览、公开事件更新、只改隐藏值、跨局/旧快照。
- 结局：胜、负、投降、没有可靠关键失误。
- 模型：云端、本地、拒绝/超时回退；三路均保留用户意图。
- 交互：查看不行动、采用只一次、陈旧结果取消、桌面/390px、切页/刷新。

各项完成自己的相关子集，11 做整合，不要求每次修改全量重跑所有矩阵。发现新风险再增加必要验证。

## 边界与写入纪律

- 4B 训练由用户本人负责，27B 暂缓；不自动训练、下载权重、切主模型。
- 不重启用户服务，不清理真实玩家/浏览器/训练数据。隔离测试可启动并关闭自己拥有的实例，用独立端口与 profile。
- 不覆盖其他成员草稿；不以 git checkout/reset --hard 恢复共享工作区。修改前记录 hash/备份；回滚只处理自己的精确差异。
- 规则数据若由生成器维护，修改生成器并重建，不直接改生成产物。保留本地模拟规则与外部资料来源的区别。
- README 是产品入口，只在已验收能力发生变化时更新简短状态；执行日志放证据目录，总计划不积累逐轮长篇叙事。
- Gitee 为当前保存目标。每项推送当前工作分支；不强推、不切 master、不顺便推 GitHub。提交与推送失败不得写成成功。
