## 按顺序执行

| 步骤 | 操作 | 必须留下的结果 |
|---|---|---|
| 06.1 | 追踪真实局末和主动问上一局两条入口，检查同名 review 函数、提前 return 和逐行日志路径；统一输入输出契约，避免只修旁路。 | 入口调用图与重复逻辑处置。 |
| 06.2 | 按 decision_id 读取当时观察、合法动作和玩家行动；分离合理决策坏结果、知识缺口、执行失误与判断失误。 | 关键候选点及证据。 |
| 06.3 | 对影响大且证据够的一个点调用分支对照，写清固定的对手行动、假设和搜索范围；接近的合理动作不判错。 | 当时合法替代和结果范围。 |
| 06.4 | 正文按关键回合→当时选择→一个改法→风险/下次判断呈现；完整事件放依据。没有可靠关键失误时明确说明，不硬造替代。 | 胜/负/投降/无明显失误四类输出。 |
| 06.5 | 局末可继续问为什么或如何练；云端、本地、被拒回退均保留复盘结构，禁止把末回合日志当完整复盘。 | 真实结算页操作与三路输出。 |

每做完一步更新 STATE.json 的 step 和 next_action。测试失败先定位本步最小原因；不要跳到下一步靠更多功能掩盖失败。
