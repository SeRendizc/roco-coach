## 按顺序执行

| 步骤 | 操作 | 必须留下的结果 |
|---|---|---|
| 10.1 | 盘点当前会话、队伍、个体、观察、对局与记忆如何保存及恢复；定义刷新/断线后明确行为，不能用沉默清空作为恢复。 | 恢复矩阵和数据拥有者。 |
| 10.2 | 在隔离实例注入慢模型、断网、异常工具回执、重复点击、乱序响应与服务暂不可用；保留玩家输入，防止重复行动。 | 故障注入前后状态与恢复操作。 |
| 10.3 | 核对跨局、切页、多标签和刷新时的匹配/失效机制；只恢复有证据的数据，不能把上一局挂回当前局。 | 交叉会话对照。 |
| 10.4 | 给分析和回放绑定规则版本；版本不匹配时明确阻止错误重放或迁移。不得无提示用新规则重新解释旧决策。 | 版本变化反例与产品提示。 |
| 10.5 | 记录 HEAD+dirty hash、前端资源、后端实例身份与启动时间/构建指纹。服务切换若需重启，准备具体方案与回滚点，等待用户明确授权，不自动执行。 | code / isolated / player 三栏及待授权方案。 |
| 10.6 | 检查自有测试进程和浏览器生命周期，只关闭自己创建的资源；记录相关回归门禁，不在用户服务上运行可能抢端口的全量脚本。 | 资源归属与干净退出证据。 |

每做完一步更新 STATE.json 的 step 和 next_action。测试失败先定位本步最小原因；不要跳到下一步靠更多功能掩盖失败。

## 通过条件

- [ ] 验收故障中无串局、重复结算、静默丢失，恢复行为可解释。
- [ ] 过期/异版本结果不能采用；玩家运行版无法确认时明确待核。
- [ ] 未擅自重启服务或清理真实数据。

## 必须执行的反例

- 重复请求/按钮双击不得多结算一回合。
- 客户端静态文件已更新但后端旧进程时，不能报整体已生效。
