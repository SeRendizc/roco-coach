## 按顺序执行

| 步骤 | 操作 | 必须留下的结果 |
|---|---|---|
| 01.1 | 画出真状态到 Python public/UI、Node 响应、客户端、Coach 工具、缓存和回放的字段流。逐字段登记事实、推测、隐藏真值及来源；避免只检查模型提示词。 | field-matrix.md 与真实调用路径。 |
| 01.2 | 定义并实现版本化观察契约：match_id、event_seq、decision_id/state_version、rules_version、来源事件与可见范围。命名可适配现有代码，但含义不能丢。 | schema 与兼容适配说明；现有调用方逐个迁移清单。 |
| 01.3 | 在首次预览尚未发生时不给对方六只；预览事件只包含实际展示字段。记录已出场、已出招、可见状态与资源，不把种族参考当个体真值。 | 预览前/后、出招后、无预览模式的 JSON 快照。 |
| 01.4 | 把当前决策观察快照固化到可回放记录；同一局的 UI/Coach 使用同一来源投影。推测单独存放，不回写成观察事实。 | 同一 decision_id 的 UI、工具输入与回放对照。 |
| 01.5 | 修复缓存键和旧协议兼容：绑定局、状态、规则与观察版本，取消陈旧分析；旧数据缺字段时明确降级，不补隐藏真值。 | 跨局、乱序/重复事件、旧快照的定向验证。 |
| 01.6 | 只改变隐藏个体值与真实配招，比较所有公开响应、工具输入与确定性分析输入；再改变实际可见事件，证明观察会更新。 | 隐藏变量不变性对照与公开变化正例。 |

每做完一步更新 STATE.json 的 step 和 next_action。测试失败先定位本步最小原因；不要跳到下一步靠更多功能掩盖失败。

## 通过条件

- [ ] 公开输入中没有未观察的隐藏个体值、四技能和对手待执行动作。
- [ ] 同一决策的 UI、Coach、回放可追溯到同一观察序列。
- [ ] 预览发生前及无预览模式没有提前泄漏阵容；新局不继承旧局事实。

## 必须执行的反例

- 固定公开史，仅改隐藏天分/六维/配招/后备资源，公开输入逐字段相同。
- 改变已展示物种或已公开技能，相关观察确实变化。
