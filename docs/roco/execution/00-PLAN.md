所属阶段：M0。目标：把当前 P0 修复收口成可复现的基线，让后续功能有可靠的对局入口。

[返回总计划](MASTER-PLAN.md) · [唯一执行状态](STATE.json)

## 进入条件

无。承接新 DSH 当前工作；先检查已有修复与证据，禁止按旧快照重做或覆盖。

首次进入先读总计划的共同协议，重新核对工作区与写入者。已有实现先验证再补缺，不按本文件重写一遍。本文是执行任务书，不宣称功能已完成。

## 写域与阅读入口

建议写域：roco/src/roco_env/coverage.py、service.py；必要的 roco/tests；启动烟测脚本。其他引擎文件须先在状态表追加确切写域。

Lead 开工前把实际文件与唯一拥有者写入 STATE.json.write_owners。建议写域不等于自动接管别人的未提交改动；冲突先协调。

先读：roco/tests/test_effect_coverage.py、test_cond_self_debuff_power.py、test_sim_endpoints.py、test_six_pet_battle.py；src/coach/roco-client.js。

| 00.1 | 只读核对 HEAD、差异、成员活动、8765 status、服务解释器及启动方式；把已存在的 DSH 草稿和未提交修复归属写入状态表。 | baseline.json：时间、HEAD、dirty paths、解释器、status 摘要、活动写域。 |
| 00.2 | 核对所有 coverage 调用方、真实签名与返回字段；确认缺失接口、能力映射和独立错误。以引擎执行行为及有效规则为依据，不能只满足旧计数。 | 缺口清单：调用方、契约、故障复现、最小改动范围。 |
| 00.3 | 完成当前最小兼容修复，保留原文件备份及草稿；按相关测试逐个处理错误。历史测试与当前规则冲突时记录冲突依据，不删断言刷绿。当前残余 8 个失败逐例核对输入、解析、结算事件和契约；禁止为了凑 306 或反证数量而反向拟合实现。若确证判据陈旧，提交独立证据和最小判据修订理由；未查清的语义问题继续修复。 | 精确 diff、定向测试完整输出与退出码。 |

每做完一步更新 STATE.json 的 step 和 next_action。测试失败先定位本步最小原因；不要跳到下一步靠更多功能掩盖失败。

## 通过条件

- [ ] 服务入口 import 成功；定向测试无未解释失败。
- [ ] 隔离实例真实创建与推进对局、技能详情成功，事件与状态一致。
- [ ] 玩家服务与隔离实例分栏；未授权切换不能伪造通过。
- [ ] 未支持机制不得在分析中被当作正常伤害或完整支持。

## 必须执行的反例

- 仅在临时副本或隔离测试中模拟缺少必要导出，烟测必须失败；正常副本通过。不得破坏共享源码或玩家实例做故障注入。
- 不支持的技能效果明确返回缺口，不给已完整结算的假结论。

## 证据与收尾

证据保存到 reports/roco/product-execution/00/，至少包括 result.json、简短 acceptance.md、原始命令/退出码与请求或状态差异；涉及页面时附真实操作截图。格式见 [证据模板](EVIDENCE-TEMPLATE.md)。不得保存密钥或玩家私有数据。

只提交自己拥有的文件。通过后保存 Gitee 当前工作分支并核对远端 SHA；推送失败单独登记，不伪造已保存。不要修改 master、强推或混入他人的 WIP。
