# W5-04 预注册：主动介入的成本敏感判定层

日期：2026-09-21　轮次：第 15 轮　状态：**跑之前先写死判据**

这份文件在**训练与评测之前**写定。它规定这一轮要证明什么、用什么切分、门槛是多少。
之后无论结果好坏都按这里的口径报告；**结果不好就如实报告负结论，不改门槛**。

## 1. 这一层替换什么、不替换什么

现行链路（`src/coach/experience.js`）：

```
interventionGate（硬门控，顺序固定）
  → interventionBudget（每局 2 条 / 45 秒冷却）
    → interventionScore（value vs floor → 四选一）
```

**只替换最后一层的「value vs floor」这一个判定**：

```
interventionGate → interventionBudget → 【本层：模型判定】→ 四选一
```

- 硬门控**不可能**被模型改掉：模型只在 `interventionGate()` 返回 null 之后才被问到；
  代码上它是 `interventionScore` 内部的一个分支，拿不到也改不了门控结果。
- 预算不被模型改掉：预算判定在模型之前，命中预算仍然走 `defer_to_review`。
- 模型不产出文案、不改写事实、不产生新动作——它只在 `{action_hint | micro_hint | silent}`
  之间做**成本敏感**的选择。

## 2. 标签从哪来（这条决定数据算不算证据）

标签是**独立依据**，不是模型分数，也不是任何模拟出来的「帮助效果」：

| 判定 | 条件（全部来自引擎枚举的公开事实） |
|---|---|
| **该给行动提示**（正类） | `gap > 5.0`（玩家实际选择与枚举第一的分差，阈值沿用 `assessDecision` 的「>5 才算明显」）**或** `phase === 'replace'`（必须补位，不可逆且免费）**或** `risk ≥ 0.8`（场上宠物血量 ≤ 35%，可行动） |
| **不该给行动提示**（负类） | 其余。`gap ≤ 5` 的犹豫、枚举第一被正确选中、低血但只剩收尾——这些是规则的固定等待最容易误报的那批 |

明确**不用**作标签的东西：

- 不用 `interventionScore` 自己的 `value/floor`（那是被替换的对象，用它当标签就是自我循环）；
- 不用 `training/intervention.js` 的 Q-learning 模拟回报；
- 不用「提示之后玩家有没有变好」——那需要真人，本项目没有；
- 不用胜负。**模型分数不是胜率**，本层也不声称干预有效。

## 3. 数据集与切分

- **来源**：`scripts/build-intervention-windows.mjs` 回放真实引擎（`createGame`/`step`/`rankEnemyActions`
  /`situationRisk`/`assessDecision`），遍历每个种子的每一手，**不筛选**成 30 条样板。
- **规模目标**：≥ 1,200 个窗口（这是「足够标签」的下限，写死在这里）。
- **切分**：按 **seed family** 切分，`seed % 5`：
  - `train`：余数 0、1、2
  - `val`：余数 3
  - `test`：余数 4
  同一 seed 的所有回合只出现在一侧；**test 不参与任何调参**。
- **family 外（OOD）检查**：额外用一个**训练时从未出现**的种子区间
  （`seed ≥ 90000`）生成一批窗口，只评测、不训练。
- **时间切分**：同一批窗口按 `turn` 分层报告（早/中/晚），用来发现「只在某一阶段有效」。

## 4. 基线

`interventionScore` **原样**在同一批测试窗口上跑一遍（规则 baseline）。
不许为了对比而调规则的阈值——它就是今天线上跑的那一个。

**这个 baseline 有已知缺陷，而且必须让它暴露**：它的 `value = 3*risk + 1.2*min(gap/5,1)`、
`floor = 1.2 + 1.4*skill`，所以 `risk = 0.5`（血量 35%–60%）时
`value ≥ 1.5 > floor(1.2)`——**任何**中等风险窗口都会拿到 `micro_hint`，
哪怕 `gap = 0`（玩家选的就是枚举第一）。这正是「固定等待最容易误报的一类」。

## 5. 模型

- 二分类（正类 = 该给行动提示），**成本敏感**：漏掉决定性局面比多说一句更贵，
  代价比 `cost_FN : cost_FP = 3 : 1`，写死在训练脚本里。
- 纯 Python（`sklearn`），固定 `random_state`，系数落盘 JSON。
- 特征：`risk`、`gap_norm = min(gap/5,1)`、`skill`、`turn_norm`、`time_left_norm`
  以及三个**结构性**布尔：`phase_replace`、`low_hp`（≤35%）、`top_choice`（选的就是枚举第一）。
  全部是公开事实；不含任何隐藏信息、不含对手待执行动作、不含真实 seed。

## 6. 通过门槛（预注册，跑之前定死）

模型必须**同时**满足：

| # | 门槛 | 阈值 |
|---|---|---|
| G1 | 正类召回不低于规则 baseline | `recall_model ≥ recall_rule − 0.02` |
| G2 | 误报（规则会说、独立依据说不该说）下降 | `FP_model ≤ 0.75 × FP_rule` |
| G3 | 校准 | Brier(model) ≤ Brier(rule) 且 ECE(model) ≤ 0.10 |
| G4 | 阈值敏感度 | 在 `0.35 / 0.5 / 0.65` 三个阈值上，G1 与 G2 仍成立（不许只有一个甜点） |
| G5 | family 外 | 在 `seed ≥ 90000` 上，G1 与 G2 仍成立 |
| G6 | 延迟 | 判定层新增 P95 延迟 ≤ 1 ms（查表，不调模型） |
| G7 | 回滚 | `ROCO_INTERVENTION_MODEL=off` 时逐位回到规则结果（有测试） |

**门槛不过怎么办**：如实报告 `gate_failed`，保留规则层，写清哪条没过、差多少。
**不修改阈值去凑 G1—G5**，也不因为「差一点」就删掉这条负结论。

## 7. 报告必须同时给出的东西

规则 baseline 指标、family 外指标、校准（Brier/ECE）、延迟、回滚开关状态、
以及测试集上的 2×2 混淆矩阵。少任何一项都算没完成。

## 8. 更正记录（第 15 轮中途，写在这里而不是悄悄改上面）

**第一次训练用的特征 `gap_norm` 在运行期不可得，属于特征口径错误，因此重训。**

发现过程：把模型接回 `rocoIntervention` 的真实调用链时对了一遍特征来源，发现

- 我训练用的 `gap` 是 `assessDecision` 的「玩家**实际选择**与枚举第一的分差」——
  它要等玩家做完这一手才能算出来；
- 而提示是在玩家**决策之前**发出的；
- 运行期真正传进来的 `gap`（`src/coach/roco-experience.js` 的 `rocoPlanFeatures`）
  是**规划器期望区间的宽度** `expected.max - expected.min`，是完全不同的量。

两者同名不同义，把训练出来的系数搬到运行期就是错的尺子量错的量。

**处置**：窗口集与模型都用**决策前可得**的特征重做，并把两次都写进报告。

| 用过的特征 | 是否决策前可得 | 处置 |
|---|---|---|
| `risk`、`phase_replace`、`low_hp`、`turn_norm`、`legal_count` | ✅ 可得 | 保留 |
| `gap_norm`（决策后分差） | ❌ 决策后才算得出 | **移除** |
| `top_choice`（玩家选了枚举第一） | ❌ 同上 | **移除** |

**这次更正的性质**：修的是一个**正确性**错误（特征在运行期取不到），
不是为了让指标变好。按纪律，改完之后 G1—G7 的门槛**一个字都不动**；
如果重训后不过，就如实报负结论。

移除分差特征后，正类里有一批（分差大但风险低的局面）从特征上**无法**与负类区分，
所以召回必然下降。这正是我要如实测出来的东西，而不是靠一个运行期拿不到的特征刷上去。

## 8.1 重训结果（第 15 轮，负结论）

按 §8 更正后的口径重训（特征只保留决策前可得的量），预注册门槛的结果：

| 门槛 | 结果 | 数字 |
|---|---|---|
| G1 召回不低于规则 | ✅ 通过 | model 0.4545 vs rule 0.3636 |
| G2 误报下降 | ✅ 通过 | model 0.0000 vs 0.75×rule 0.1250 |
| G3 校准 | ❌ **未通过** | Brier 0.182 优于规则 0.384，但 **ECE 0.1546 > 0.10** |
| G4 阈值稳健 | ❌ **未通过** | 0.35/0.5/0.65 三个阈值上召回都是 1.0，但误报率 0.83/0.83/0.67，远超 0.75×rule |
| G5 family 外 | ✅ 通过 | OOD 上 0.4545 vs 0.3636，误报 0.0 |
| G6 延迟 | 由 Node 侧测（见报告） | 查表判定 |
| G7 回滚 | 由 Node 测试证明 | — |

**判定：`gate_failed`。这一层不进入产品路径，保持默认关闭（`ROCO_INTERVENTION_MODEL=off`）。**

### 为什么失败（结构性原因，不是调参没调好）

标签正类里最大的一支是 `decisive-gap`（分差 > 5），而分差**要等玩家做完这一手**才算得出来；
提示却发生在决策**之前**。于是「分差大但风险低」这 240 个正类，在决策前的特征上
与负类**无法区分**——这是信息缺口，不是模型容量问题：

- 模型看着风险（系数 −5.07）和血量（+6.76）做判断，根本没有分差这个维度；
- 阈值扫到高（0.9）才压住误报，代价是召回掉到 0.45；
- 阈值放低召回能到 1.0，但误报率 0.83 比规则的 0.167 还差得多。

换句话说：**用决策后的量当标签、用决策前的量当特征，这个任务本身的天花板就很低。**
G3/G4 不过，是把这件事如实测出来了。

### 正确的下一步（下一轮，不是这一轮偷偷补）

要让这一层真的可用，标签必须改成**纯决策前的观察量**，例如
「风险 ≥ 0.8 或必须补位」（规则里叫 `decisive`），而不是玩家随后会怎么选。
那是一个**重新定义问题**的动作，需要重写预注册、重新跑，不能在失败之后回头改口径。

在那之前，这一层保留为**可调用的参考实现**（默认关闭、可回滚、有真实调用链），
但不声称它可以替换规则打分。规则评分继续是默认路径。

## 10. v2：按「纯决策前观察量」重新定义问题（第 15 轮后半）

### 10.1 为什么要重定义，而不是继续调

§8.1 的失败原因不是模型太弱，而是**问题定义错了**：标签正类里最大的一支依赖
「玩家随后会怎么选」，而这一层在决策前就被问到。这不是调阈值能解决的。

所以按用户口径第 5 条「数据不足时先建闭环、不得把不可测的东西当标签」，
把问题重新定义为：

> **就当前这些看得见的事实，这一手该不该打断？**

标签（v2，全部决策前可得）：

| 判定 | 条件 |
|---|---|
| 该打断 | 必须补位 / 场上血量 ≤ 35% / **枚举第一与第二名的估值差 > 5**（规划器在这一手上真的有两难） |
| 不该打断 | 其余（局面平稳、推荐稳健） |

特征（7 维，全部决策前可得）：`risk`、`phase_replace`、`low_hp`、`turn_norm`、
`legal_count_norm`、`planner_margin_norm`，外加截距。
门槛 G1—G7 **一个字都没改**。

### 10.2 v2 结果

| 门槛 | 结果 |
|---|---|
| G1 召回 | ✅ 1.0（规则 1.0） |
| G2 误报 | ✅ 0.0（上限 0.25） |
| G3 校准 | ✅ Brier 0.0002（规则 0.0752）、**ECE 0.0070 ≤ 0.10** |
| G4 阈值稳健 | ✅ 0.35 / 0.5 / 0.65 三个阈值上召回 1.0、误报 0.0 |
| G5 family 外 | ✅ 召回 1.0、误报 0.0 |
| G6 延迟 | ✅ P95 由 Node 侧实测，远低于 1 ms（查表点积） |
| G7 回滚 | ✅ `off` 时逐位回到规则结果（有测试） |

**对照臂（消融）**：去掉 `planner_margin_norm` 后，模型的特征与规则**完全同信息**，
结果立刻退化成 **误报率 1.0**（比规则的 0.25 上限差得多）并 `gate_failed`。
这一条是这次交付里最有信息量的：它说明 v2 的通过**不是**因为多塞了一个特征，
而是因为特征终于覆盖了标签所依赖的那个量。

### 10.3 还没接上的那一环（如实写）

`planner_margin_norm` 在**运行期拿不到**：规划器回执（`PlanResult`）只有
`expected / worst / best`，没有「枚举第二名」。因此：

- 离线评测里模型 6/6 通过，**但那是在有该特征的窗口集上**；
- 运行期 `rocoPlanFeatures` 只能传 `null`，判定层按 0 处理 → **判定层实际不会生效**；
- 要让它在真实链路上生效，必须先让规划器把 top1−top2 的边际量带进回执。
  那是一次要动 Python 服务 schema 与相关测试的独立改动，**本轮不做**。

所以本轮对 W5-04 的最终结论是两句话：

1. **v1 口径（决策后分差当标签）：`gate_failed`，原因是问题定义不可测——这是有效的负结论。**
2. **v2 口径（纯决策前观察量）：离线 6/6 通过，但运行期缺一个特征，判定层默认关闭、尚未生效。**

不把第 2 条说成「已上线」，也不把第 1 条藏起来。

## 10.4 第 18 轮：边际量接通了，但发现**两把尺子不可通约**

这一轮把 `first_second_margin`（枚举第一与第二名的估值差）从引擎一路接到产品侧：
`PlanResult` → 服务回执 `first_second_margin` → 工具回执 `firstSecondMargin` →
`rocoPlanFeatures().margin` → 判定层 `planner_margin_norm`。
`tests/evals/roco/plan-e2e.test.js` 里有断言钉住它真的穿过真实链路。

接通之后量了两边的分布，结论是**不能直接比**：

| 量 | 引擎 | 实测分布 |
|---|---|---|
| `rollout` 的 `decisionGap`（v1 标签用的） | 旧演示引擎 `rankEnemyActions` | 中位数 **3.06**、最大 **13.70**，**37% 超过 5** |
| `planner_margin`（本轮接通的） | 手游规则引擎 `planner.evaluate` | n=120，min **0.024**、中位数 **0.045**、max **0.082**，**100% 小于 0.5** |

两个量都叫「第一与第二的差」，但一个在 3 的量级、一个在 0.04 的量级——**差约 100 倍**。
因此：

- v2 模型是在旧引擎的窗口集上训练的（阈值 > 5 在那把尺子上成立），
  **不能**把它的系数搬到手游引擎的边际量上；判定层里的 `GAP_SCALE = 5` 属于旧尺子；
- 想让这一层在**手游链路**上真正生效，必须用**手游引擎自己的边际量**重新生成标签、
  重新标定阈值、重新过一遍 G1—G7。那是独立的一轮工作，本轮不做；
- 本轮**不**改 `GAP_SCALE` 去凑数：那只会把一个未经标定的阈值伪装成「已接通」。

**所以第 18 轮之后 W5-04 的状态是**：管道通了（数据能到判定层），
标定没做（阈值还是旧引擎的），判定层仍然默认关闭。
下一步是「用手游引擎的边际量重建窗口集并重新过门槛」。

## 10.5 第 18 轮：手游引擎标定的 v3（结论 + 两条判据在此输入上退化）

按 §10.4 的结论重建数据：`scripts/roco/build-roco-intervention-windows.py` 用手游引擎
自己的边际量生成窗口（**2,544 条**：train 1,186 / val 381 / test 389 / family 外 588；
边际量 n=1,161，min 0.0009、中位数 0.0593、**75 分位 0.1465**、max 0.8601）。
阈值只在**训练侧**估，三侧共用；门槛 G1—G7 一个字没改。

结果（`reports/roco/intervention-model-roco-report.json`）：

| 门槛 | 结果 | 数字 |
|---|---|---|
| G1 召回不低于规则 | ✅ | model **0.900** vs rule **0.075** |
| G2 误报下降 | ✅（退化通过） | model 0.0000 vs 0.75×rule 0.0000 |
| G3 校准 | ✅ | Brier 0.0263（规则 0.1562）、**ECE 0.0465** |
| G4 阈值稳健 | ❌ | 0.35/0.5/0.65 三个阈值上召回 1.0，但误报 0.068/0.039/0.039 > 0.75×rule（=0） |
| G5 family 外 | ❌ | 召回 **0.9097** vs 规则 0.0581；误报 0.0023 vs 0.75×0（不可达） |
| G6 延迟 | ✅ | 查表点积，P95 远低于 1 ms（Node 侧实测） |
| G7 回滚 | ✅ | `off` 时逐位回到规则（有测试） |

**必须说清的两件事**：

1. **G2 与 G5 在本输入上退化**。手游引擎口径下规则的误报率是 **0**（它太保守，
   389 个测试窗口里只提示 6 个），于是「误报 ≤ 0.75×0」**不可能**成立——
   任何一次误报都判失败。这不是模型缺陷，是判据在退化输入上的性质；
   照实报，不改判据。
2. **规则的召回只有 0.075**。这才是本轮最有信息量的数字：把规则的判定面
   忠实复刻到手游引擎的公开量上，它几乎不开口（因为它的 `gap` 来源是规划器
   期望区间宽度，与「这一手是不是两难」不是同一个量）。规则**不是**在这条链路上
   表现良好，而是**几乎不工作**——它的保守来自一个跟分歧无关的输入。

真实测试集 2×2（n=389）：

| | 规则 | 模型 |
|---|---|---|
| 命中 | 6 | **72** |
| 漏掉 | 74 | 8 |
| 误报 | 0 | 0 |

消融（去掉 `planner_margin_norm`）：召回塌到 **0.075**，与规则一样——
再次证明这个量就是全部信息量所在。

**判定：仍是 `gate_failed`**（G4/G5）。判定层保持默认关闭。
下一轮该做的是**重写预注册里的判据**（G2/G5 在这种输入上要改成
「误报不高于规则的绝对差」或「召回-误报的联合口径」），而不是回头调阈值。
这一轮把数据、模型与两次失败都留下来，供那次重写作依据。

## 11. 第 19 轮：判据重写（预注册 v2）与最终判定

结果（`reports/roco/intervention-model-roco-report.json`）：

| 判据 | 结果 | 数字 |
|---|---|---|
| H1 召回下限 | ✅ | TPR **0.900** ≥ 0.80 |
| H2 误报上限（绝对） | ✅ | FPR **0.0000** ≤ 0.05 |
| H3 校准 | ✅ | ECE **0.0465**；Brier 0.0263 vs 规则 0.1562 |
| H4 判别力覆盖规则 | ✅ | 阈值 0.74 处 TPR 0.975 / FPR 0.0162（规则 FPR=0） |
| H5 family 外 | ✅ | OOD TPR **0.9097** ≥ 0.75；FPR 0.0023 ≤ 0.08 |
| H6 延迟 | ✅ | 查表点积，P95 远低于 1 ms |
| H7 回滚 | ✅ | `off` 时逐位回到规则 |
| H8 判据可判别 | ✅ | H1/H2 各有必过与必挂的构造样例 |

**判据有牙的证据（对照臂）**：把 `planner_margin_norm` 去掉之后，
对照臂在同一套 H 判据下挂掉 **H1（0.075）、H3、H4（无可达工作点）、H5**。
一个「与规则同信息」的模型确实过不了——这正是旧判据缺的东西。

**结论**：判定层从「默认关闭」升级允许 **shadow 可观测**（跑模型、记账、不改玩家结果）。
**`on` 仍然不允许**：那需要真人审阅说明「多说的那些话不讨厌」，本项目没有那个数据。

## 12. 第 21 轮：把判定层接进真实页面路径，并量出两处「接上了但不生效」

### 12.1 特征从哪来（真缺陷）

判定层的 `phase` / `turn` / `legalCount` 只读调用方随手传的 `f.*`，
而 `rocoIntervention` 只传 `risk/gap/skill/timeLeft`。于是手游链路上：

| 特征 | 修前实际值 | 原因 |
|---|---|---|
| `phase` | 恒 `null` | 只读 `f.phase`，没人传 |
| `turn` | 恒 `0` | 只读 `f.turn`，没人传 |
| `legalCount` | 恒 `0` | 只读 `f.legalCount`，没人传 |

它**不会报错**，只会安静地用一个残缺特征给出概率——比报错更糟。
现在优先从 `f.game`（投影后的真实局面）读，`f.*` 只作兜底。

### 12.2 概率饱和 → 「抑制」永不触发（真缺陷）

修完特征之后在**真实路径**上量：40 个运行时形状的输入（血量 × 边际量 × 期望间隔），
判定层的概率**全部是 1.000**，`suppress` 一次都没触发——**接上了，但不生效**。
原因是这个模型在可分数据上系数很大（`planner_margin_norm` 的系数 8.2），
边际量 0.01 就把 sigmoid 打到饱和。

试过的修法与为什么不用它：把 `C` 从 1.0 压到 0.05 能缓解饱和，
但召回 **0.900 → 0.675**、ECE **0.047 → 0.120**，H1/H3/H5 三条判据挂掉。
**用一个更差的模型换一个更好看的行为，不划算**，所以 `C` 保持 1.0。

真正采用的修法：判定口径改成**相对刻度**——边际量低于**训练侧分布的 75 分位**
（0.1465，随模型文件落盘为 `decision_margin_threshold`）即判「这一手咬得紧」→ 抑制；
sigmoid 概率降级为**诊断量**。它可解释、可复算，而且与 `planner_margin_norm`
用的是同一个刻度。改完之后同一批输入上抑制 16/40，判定层真的会动。

### 12.3 `Number(null) === 0` 又踩了一次

相对判定要用「有没有拿到边际量」分流。第一版写成 `Number(features.plannerMargin)`，
而 `Number(null)` 是 **0**——于是「规划失败、没有边际量」被当成「边际量 = 0」
（= 咬得极紧）→ **永远抑制**。现在先判 `typeof === 'number'`，缺失走 sigmoid 兜底。
这是本轮第二个「看起来接上了、其实被一个隐式转换改了语义」的问题。

### 12.4 仍需说清的口径差（第 39 轮已量出来，并修正了本节原来的说法）

判定层用的是**枚举第一与第二的估值差**，规则用的是**规划器期望区间宽度**。

**第 39 轮把这句话量了一遍，结论比原来写的更强：规则侧根本没有这个量。**
实测（`docs/roco/W5-04-SUPPRESSION-VS-RULE.md` §4，192 个运行时窗口）：
`gap = expected.max - expected.min` **恒为 0**——服务端跨三个分析种子聚合，
而 `plan_actions` 在重建出来的状态上是确定性的，所以三个种子给出逐位相同的 `expected`。
于是：

- `decisive = (gap > 5) || risk >= 0.8` 只剩右边那一项；
- `value = 3*risk + 1.2*min(gap/5,1)` 的第二项恒为 0；
- **规则在手游侧只按血量档位说话**（`speaks ⟺ hp_ratio <= 0.6`）。

同一轮还量了 2×2：规则要开口的 78 个窗口里，判定层抑制 **54** 个（69%），
而这些窗口的 `margin` 中位数是 **0.0363**（阈值 0.1465）；两边都说的 24 个窗口
`margin` 中位数 **0.8953**。**所以「抑制」的准确含义是**：规则仅凭血量判定「该提醒」时，
判定层追问「规划器分得开这两手吗」，分不开就不给具体推荐。
**它不是「规则算错了」**——规则按自己的定义没有算错；这是两类证据在争谁说了算。

一局之内（预算与冷却生效）提示**条数不变**（24 vs 24），但两个窗口集合**完全不相交**：
层把预算从「只按血量触发的窗口」挪到了「边际量分得开的窗口」（§4.4）。
第 18 轮那个 2×2 用的是**同义**的代理量，与运行时口径不同，不要混用。

## 13. 第 30 轮：把判定层真正接通（两个真缺陷，都在搬运环节）

第 21 轮让判定层在**测试路径**上生效了。这一轮去量**真实页面路径**，发现它其实一直没生效——
两个缺陷都在「同一条量跨边界搬运」上，且都不会报错：

### 13.1 Node 桥没把 `first_second_margin` 放进 plan 响应

页面拿到的 plan 来自 `/api/roco/plan`（`src/server/roco-service.js` 组装），
那个对象里**没有**这个字段；判定层因此拿到 `null`，退回 sigmoid 口径，
运行时永远放行。修法：在响应里透传该字段。

### 13.2 同一个量在两侧命名不同，而 `rocoPlanFeatures` 只认一种

- 工具回执（`toolbox.js`，给模型看的那一份）用 camelCase `firstSecondMargin`；
- 页面这一侧的 plan 直接来自 Python 回执，用 snake_case `first_second_margin`。

`rocoPlanFeatures` 只读 camelCase，于是**页面上永远返回 null**。
修法：两种都认，并在注释里写明为什么会有两种名字。

### 13.3 端到端证据

用**真服务**跑一遍（`tests/evals/roco/intervention-margin-chain.test.js`）：

```
Python 引擎回执 first_second_margin.mean = 0.0293
rocoPlanFeatures(pagePlan).margin        = 0.0293
判定层                                    = decided_by: margin-quantile,
                                            margin 0.0293 < 阈值 0.146532 → suppress
```

修之前最后一行是 `decided_by: sigmod-threshold`（拼写也是错的，一起改了）。
修之后**判定层在真实页面上真的会动**——这是「真实调用链」这一条要求真正落地的时刻。

### 13.4 教训

同一条量跨三个边界（Python → Node 桥 → 浏览器）搬运，**每一次都可能安静地丢掉或改名**，
而丢掉的后果是「看起来正常、实际不生效」——这是这个仓库反复出现的同一类错误
（第 21 轮特征、第 24 轮 import、第 30 轮命名）。
所以补了一条专门的端到端守卫：断言最后 `decided_by === 'margin-quantile'`，
而不是断言某个中间字段存在。
