## 用户原文（要点）

1. **没法翻页**；「特点」那一行**过于模板化、根本没意义** —— 应该**看体系**；**基本属性为什么不单独拉出来说**；
   元素太紧；**小芽和上面一点空格都没有**；**这小芽也用不了**；**宠物先让我选**。
2. **阵容评估好像也没有**；小芽需要下翻，**很不易用**。
3. 元素**没对齐**；**小芽为什么那么矮**；小芽的位置**得重新设计**。
4. 元素乱，**重新设计**；底部**行动区太乱**，**应按类型分类**（技能 / 物品 / 换精灵 / 逃跑）；
   **物品要用洛手（洛克王国：世界手游）真实机制**；UI 要**留空间**，**左右拉平太丑**；
   **技能显示也不全**。
5. **丑**；而且「**为啥我之前给你说的、使用洛手真实的机制你都不听**」——
   **六精灵、4 心（魔力/心），心没了就输 PVP**……「案例很多」——要**全面接入洛手的规则、机制、玩法**。

### D5 的处理（不许绕过证据纪律）

- 用户（项目所有者）**断言**：标准 PVP 是六精灵、**4 心**、心耗尽判负。这属于**一手项目指令**，
  但**不是**官方公告也不是实机录屏，所以：
  1. **台账不加重复条目**（2026-09-22 复核结论）：现有三条已经逐字覆盖该断言且等级正确——
     `EV-PVP-STANDARD-TEAM-SIZE`（六宠，`CROSS_SOURCE_SUPPORTED`，`MC-E07`）、
     `EV-PVP-STANDARD-MANA`（4 点魔力，同等级，`MC-E08`）、
     `EV-PVP-FAINT-MANA-LOSS`（力竭 -1 魔力、胜负判据是「先让对方魔力归零」，`MC-E09`）。
     所有者指令本身**不构成**独立来源：它不支持更高等级，也不该被拿去凑 `CROSS_SOURCE_SUPPORTED`
     的「两条 URL 不同来源」门槛（一次尝试正因为只有一个 URL 而被检查器拒绝，已回滚）。
     需要补的是 **`MC-E08` 实机录制**，不是台账条目。
     `data/roco/battle-modes.json` 的 `pvp-standard-six-pet` 已登记 `mana_pool: 4 / faint_mana_cost: 1`，
     与本断言一致。
  2. **引擎侧**：当前 `legacy_sim_v1` **没有「心」这一概念**（胜负按打光判）。所以**不许**在 UI 上
     凭空画一个心计数器 —— 那是「编规则」。正确做法：UI/契约**预留心与胜负条件**（读自
     `data/roco/rulesets/*.json` 与 `battle-modes.json`），**引擎没有就给 `unknown` 并说明**；
     真实实现属于 RC-101/RC-102 的 candidate 规则落地（并等 `MC-E08` 录制）。
  3. **物品/技能分类**同样：按**引擎实际给出的动作类型**分组（`kind`：skill/item/switch/escape），
     物品名用冻结数据里的真实名字；**冻结数据里没有的，不许编**。

## 与现有工作的关系

- **不推倒重写**：本轮只改玩家层（`src/client/**`）与必要的只读数据转发（`src/server/roco-service.js`），
  不动引擎规则、不动 Agent/RAG/Memory/三角色能力、不动 release gate 的 17 套件。
- **RC-305（六槽工坊新页面）已在做**：它与本指令方向一致（六槽、未知对手、渐进推荐），
  但**不替代**本文件要求的「先让玩家选 + 行动区分类 + 小芽重排」这些**现有页面**的缺陷修复。

# 第二批 P0 产品问题（同日追加，逐条可核对）

> 用户第二条消息：一组来自**真实试玩**的 P0 问题，并要求**自然接入 RC-304 → RC-305 → RC-306 路线**，
> **不另起一套临时页面**，**也不要只改颜色和间距**。

## 架构裁定（由此条消息得出，全组照做）

1. **产品面只有一页**：标准 PVP 的玩家面是 `src/client/roco.html`（用户截图吐槽的那一页）。
   RC-305 的六槽工作台 + 评估 + 右侧 Coach 栏以**可挂载模块** `src/client/team-workshop.js`
   （`mountTeamWorkshop(rootEl, opts)`）交付，由 `roco.js` 挂载；`workshop.html` 降级为开发夹具，
   不再自称产品页。数据契约仍是 `GET /api/roco/workshop`。
2. **合法行动由 BattleMode 决定，不由前端决定**：标准 PVP 主入口 = 技能 / 聚能 / 换精灵，
   投降入次级「更多」。旧引擎的**回复药、净化药、逃跑**在标准 PVP 下**不得出现**；
   只有存在真实证据且对应 PVE 模式允许时才显示。前端只渲染引擎给的 `kind`，不自己编动作名。
3. **数值只来自引擎**：魔力/「心」的数值若引擎没给，就如实显示「未核验」；
   **绝对不许**画假的心形计数器或自己编一个 4。
