# PVP 的**公平与博弈**：显式规则 + 判据（2026-09-25）

> **这份文档是什么**：把人类点名的三条**第一性规则**写成可回查的显式规则，并指出每条**由什么判据守住**（判据带反证）。
> 它不是设计说明，是**规则**：以后任何"往公开面塞对手动作""把猜说成知道"的改动，都必须先改这三条并说明理由。
>
> **人类原话（逐字，别改写）**：
> - 「**这是洛克王国手游的规则，这是 pvp 大哥，公平、博弈知道吗？**」（B1 的出处）
> - 「**和上面说的一样，这不是能读取的信息，我方确定出招前都不能知道对方动作**（这很重要！！）」（c06，B1/B2 的出处）
> - 「切我方**不能读取对面任何非公开数据**」（c02，B2 的出处）
> - 「同样涉及预判理论上都麻烦」（c11）、「这很复杂的，我觉得你想简单了」（c22）（B3 的出处）
>
> **效力等级**：这几条是**人类实机口径**（本仓最高权威），不是社区推论，也不是工程约定。

## B1 · 出招前**不可能**知道对手要做什么 —— 这是 PVP 的公平与博弈本身

**规则**：双方在同一回合**同时**决定行动；在**我方行动被确定之前**，系统里**不存在**"对手这一手是什么"这个事实。
任何把它当作已知信息去读取、转发或复述的行为，都是**破坏博弈**，不是"实现细节"。

**这条解释了两件事为什么必须成立**：
1. **公开面里没有"对手待执行动作"**（不是"藏起来"，而是**在这一刻还不存在**）；
2. **推演只能给分支/可能性**（"如果对手换宠会怎样 / 如果对手攻击会怎样"），不能给"对手会换宠"这样的**单点结论**。

**守在哪（可回查）**：
| 位置 | 守的是什么 |
|---|---|
| `roco/src/roco_env/env.py:2102 public_planner_state()` | 交给教练的**唯一**局面协议；docstring 逐字写「绝不包含：seed、随机源、`_pending_*`、对手后备血量/能量/配招」 |
| `roco/src/roco_env/service.py:25-31` | 服务契约：请求里出现真实 seed / 对手待执行动作一律拒；`local-game` 域才带私有状态，**教练侧不得使用** |
| `src/coach/toolbox.js:145` | `read_state` 契约逐字：「当前公开局面；**不含电脑待执行动作或真实随机种子**」 |
| `src/coach/toolbox.js:160` | `plan_actions` 契约逐字：「**公开** planner state…**不得含真实随机种子或对手待执行动作**」 |
| `src/coach/runtime.js:1207` | 正文守卫：`simultaneous-action-order` —— 「先看对手出招再…」这类**把顺序说反**的话直接判不合格 |

**判据**：`tests/roco-pvp-fairness.test.js`（① 契约文本钉死、② 隐藏键在任何深度都被拒、③ 顺序说反必红）。

## B2 · 不许读取对手的**非公开数据** —— 先定义"哪些属于公开面"

**规则**：教练（以及任何替教练取数的通道）**只许**读下面的公开面；其余一律**不可读**，读不到时**如实说不知道**。

| 公开（可以读） | 非公开（**不可读**，读了就是违规） |
|---|---|
| 双方**场上**精灵的公开面板：生命、能量、公开状态与印记、防御冷却、是否蓄力、增益 | **真实随机种子 / 随机源**（能预测同速裁决与后续随机结果） |
| 己方**后备**的完整面板与配招（自己的信息） | **对手后备的血量 / 能量 / 配招** |
| 对手后备的**位次、精灵 id、是否倒下、当前 active 位**（术语 3010 的公开部分） | **对手待执行动作**（`_pending_*`）、对手的选择 |
| 已结算回合的**事件记录**（战报里已经公开发生过的事） | 对手的私有状态整份（`env.serialize()` 的产物，`service.py:879`） |

**⚠️ 一处仍未核实的边界（不许猜）**：**段位分档**下的可见性差异 —— 社区两源说「大师以下开局看不到对方 6 只、大师以上明牌」，
而官方一手只写「进入对战后点击头像下方的咕噜球区域，还能够查看敌我双方的场下精灵」（**未按段位分层**）。
⇒ 本仓**没有**"分档可见性"这个概念，`EV-PVP-OPPONENT-ROSTER-VISIBLE` 是 `COMMUNITY_CURRENT` 单源；**高分段建议若要区分视野，必须先裁决**。

**守在哪**：
- 引擎侧：`service.py` 的隐藏键检测（**任意深度**都拒 —— 注释逐字：「我一开始给 `state.seed` 开了一个「只允许 state 下一层」的口子，那是错的…现在任何深度、任何位置的 seed 都会被拒」）；
- 教练侧：`src/coach/toolbox.js:311` 的 `ROCO_HIDDEN_KEYS`（归一化后比较）+ `safeObject()` 的**递归**检查；
  它与 `src/coach/roco-client.js` 的 `HIDDEN_KEYS` 是**逐字镜像**，漂移由 `tests/evals/roco/toolbox-roco.test.js` 抓。

**判据**：`tests/roco-pvp-fairness.test.js`（④ 每个隐藏键在任何深度都被拒 + 反证：合法 state 会被放行）。

## B3 · 凡"预测对手下一手"的话，**只许说可能性/分支，或如实说不知道**

**规则**：可以说「如果对面换宠，你这一手会打空」；**不许**说「对面一定会换宠」。说不清就说"我看不到对手这一手"。
理由：这是 B1 的直接推论 —— 那一手**还不存在**，任何确定性说法都是**编**。

**守在哪**：`src/coach/runtime.js` 的 `checkGroundedAnswer`（2026-09-25 新增一族）
- `opponent-action-certainty`：正文出现「对手/对面/敌方/对方 + 一定/肯定/必定/必然/绝对/100% + 换宠/防御/出招/聚能…」即判不合格；
- 已有的 `simultaneous-action-order`（顺序说反）与 `unsupported-certainty`（必胜/稳赢/100%）继续管相邻的两类；
- 命中后走**已有的降级路径**（换成引擎结论 + 如实说"模型那句话没过核对"），**不新造降级逻辑**。

**判据**：`tests/roco-pvp-fairness.test.js`（⑤ 四类确定性说法必红、⑥ 五类可能性/否定/条件句**不许误伤**）。

## 这张表怎么用（给下一个 agent）

1. **要往公开面加字段**？先问：这个字段在"我方行动确定之前"是否**已经存在**？不存在 ⇒ 它属于 B1 禁止的那类。
2. **要写"预判"话术**？只能用「如果…那么…」的分支句，或"我看不到/不好说"。
3. **看到模型说了确定性预测**？那是 `opponent-action-certainty` 该抓的，别只在提示词里劝。
4. 相关台账：`EV-PVP-UNKNOWN-OPPONENT`（`pvp.fairness`）、`EV-PVP-OPPONENT-ROSTER-VISIBLE`（`pvp.fairness`）、
   `EV-PVP-FAIRNESS-NO-FUTURE-KNOWLEDGE`（人类实机口径，2026-09-25 新增）。
