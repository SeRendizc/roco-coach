# 小芽：产品愿景与落地路线

2026-09-30 · 产品规划，不是功能完成声明。

本文承接用户对军师、老师、陪练和不完全信息分析的要求，提出下一阶段产品取舍与验收标准。新增设计与数字目标均是本计划的建议，不冒充用户原话或现有实测。早期方案和逐轮记录保留作历史证据；发生冲突时以用户最新指令为准，再按本文及开局阵容修订计划实施。

## 1. 要做成什么

**小芽是一位住在宠物对战训练场里的成长教练：帮助玩家做出更好的选择，理解选择的理由，并在下一次相似局面中逐渐独立判断。**

玩家不应为了获得帮助先学会提问、读懂日志或配置一组 Agent。不打开聊天也能收到关键帮助；主动提问时又能追问到真实依据。随着玩家学会，提示变少、独立决策变好，才是成功。

第一阶段的主要用户是已经认识精灵和基本操作、但在配招、换人、资源分配和临场取舍上缺少方法的玩家。新手需要机制解释，熟练玩家需要分支比较；二者使用同一位小芽，通过提示深度和练习目标适配，不分裂成三套互不相通的聊天产品。

主要使用场景是本地训练与赛后学习。当前没有接入官方游戏客户端，也不把模拟器规则等同于官方完整规则。未来接真实宿主必须重新核验公开信息、权限、公平性和规则版本。

### 产品取舍

- Roco 六宠训练场成为近期主要验收对象；自研小兽营地保留作入门体验和可控实验场。共享教练契约，保留各自规则，不强行合并引擎。
- 先把“配好一队 → 打完一局 → 学到一点 → 再练一次”做完整，再扩宠物机制、内容量和接入平台。
- 每次改动都要能回答：它减少了哪种决策困难？玩家在哪个页面获益？怎样验证？
- 近期不建设排位匹配、社交社区、复杂养成经济、语音角色系统。模型训练也不是产品可用的前置条件。

## 2. 一次完整体验

| 时刻 | 玩家要解决的问题 | 小芽应交付什么 | 默认交互 |
|---|---|---|---|
| 首页 | 今天练什么？上次的问题是什么？ | 一个可跳过的练习目标、继续上次进度 | 一个入口，不堆指标面板 |
| 盒子与培养 | 我喜欢的精灵怎么用，值得投入什么？ | 保留本命宠的方案；投入前后的具体阈值和代价；允许先不投入 | 原位比较，应用前预览，可撤销 |
| 配队 | 这六只靠什么赢，薄弱点怎么补？ | 首发思路、核心配合、换人接应、四技能分工、主要威胁 | 先给一套打法，再给一项可选调整 |
| 开局 | 对面带了谁，最需要防什么？ | 记住真实展示的六只，指出一项主要对位风险 | 短暂预览与可回看的“已见阵容” |
| 局中 | 现在怎么办？对面换人怎么办？ | 合法首选、理由、主要风险，必要时一个备选 | 简短提示；问了就直接回答 |
| 局末 | 哪个决定值得改，下局怎么试？ | 一个关键决策、当时合法替代、适用条件和下一次练习 | 结算页短复盘，依据可展开 |
| 下次回来 | 我有没有进步？ | 用另一局面检查同一知识点，减少已掌握内容的提示 | 可跳过，不用打卡施压 |

示例仅描述回答形态，具体技能和结论必须由当前证据生成：

> “先用这招压当前对手，保留换人能量。开局见过的那只水系若上场，我们再换草系接；它的真实配招还没露。”

> “第 7 回合值得再看：当时已经知道它能先手，你仍留在场上。换到后备可以少承受一轮伤害，但会交出节奏。下局先练‘行动前看先手和能量’。”

不要求每局找错；合理决策遇到坏结果时，应明确肯定决策过程。没有可靠反事实时说明证据不足，不能说“这一局就输在这一手”。

## 3. 让分析真正有用

### 3.1 同一份公开观察

结算引擎持有真状态；玩家 UI、Coach 和分析工具只接收授权观察。禁止先把隐藏状态传入模型再靠提示词让它忽略。

| 信息 | 可以知道什么 | 不可以假定什么 |
|---|---|---|
| 我方个体 | 当前模式实际向玩家提供的等级、面板、配招、资源和状态 | 未导入字段自动成为真实值 |
| 开局对方阵容 | 预览实际展示的物种、形象、属性及明确可见的顺序 | 看见物种就知道天分、性格、真实六维与四技能 |
| 已公开战斗事件 | 已出招、换人、可见状态、血量/能量读数或区间 | 未展示的后备血量、道具、冷却和下一步动作 |
| 图鉴与规则 | 种族参考、可能技能、合法机制、版本来源 | 对方一定携带某招或一定采用某套个体配置 |
| 推测 | 与公开证据相容的候选、上下界、被排除的假设 | 无数据支撑的精确概率和胜率 |

以 `match_id`、`event_seq`、规则版本记录观察事件。`opening_roster_revealed` 只在预览确实发生后加入公开记录；关闭预览后保留记忆，新局重新开始。无预览模式只记已出场者。复盘使用决策当时的观察快照，不能偷用终局知识。

实现需同时核对网络响应、浏览器数据、工具输入、缓存键和回放：任何一层泄漏，边界都不成立。

### 3.2 从“可能”走到“建议”

1. 先根据公开规则与观察生成相容的对方配置和动作候选，标出来源与缺口。
2. 用已公开的技能、先手关系、伤害区间等证据更新候选；随机伤害、状态和未知个体值可能导致多解，不能过度排除。
3. 在当前合法动作中比较攻击、防御、聚能、换人及模式允许的自由动作；纳入能量、换人成本、存活和后续对位。
4. 第一版先做有时间预算的一至两回合主要分支，至少考虑“对手留场”和“对手换入已见威胁”。根据规则决定双方动作是否同时选择，不能把未知对手行动当成已知再决策。
5. 综合眼前收益、最坏损失、资源保留与下一回合选择空间。对结果相近的动作保留并列合理，不强行排名制造差距。
6. 若不同合理假设下首选稳定，给明确建议；若排序易变，说明决定排序的条件，并给稳健备选。没有可靠概率时使用情景对照和范围，不对候选随意等权后宣称最优。

“最优”仅能指**在明确规则、目标函数、候选集合和搜索深度内**的最优。默认面向玩家说“更稳”“能保留后手”“在这个假设下收益更高”。复杂分析超时应返回仍有效的合法保守建议，而不是阻塞操作。

### 3.3 模型与工具各自负责什么

模型负责理解玩家目标和语境、判断缺什么证据、选择工具、提出可检验的假设、比较工具给出的取舍、组织教学和陪伴。规则引擎负责合法性、结算与可复现模拟；公开投影控制模型能够知道什么。

模型不得自行填写伤害、胜率或未调用工具的模拟结果。工具也不能仅返回“推荐动作”而不保留候选、假设、规则版本和有效期。最后由校验层检查建议是否仍合法、证据是否支持结论、状态是否过期。

## 4. 军师、老师和陪练如何协作

### 军师：抓住值得说的一刻

主动提示只在玩家还能行动、风险或收益差值得注意、证据足够且信息不重复时出现。主动提醒预算不能拦截玩家明确提出的战术问题。支持适度提醒、仅关键风险和关闭主动提醒；设置立即生效。

默认建议保持一至三短句，先行动再理由与主要风险；“查看”只解释或定位，“采用”必须由玩家触发并再次检查状态。页面不挤压战场、不抢焦点，过期建议撤回。无模型、慢模型和校验回退仍需保留玩家意图，不能把“该换谁”降成闲聊。

### 老师：让复盘变成下一次能力

复盘先区分知识缺口、判断失误、执行失误和合理选择后的随机结果。选择影响较大、证据充分且玩家能够改变的一处决策，显示“当时知道什么 → 有什么选择 → 差别在哪里 → 下次怎么判断”。完整日志只作可展开依据。

问答先直接回答，再用当前队伍或刚才那一手解释。玩家愿意深入时再给一个变式问题；教学不能强迫玩家先答题才能获得答案。练习要改变精灵、数值或情境，检验迁移而非背原答案。

掌握记录按知识点区分“尚无证据”“提示下成功”“独立成功”“跨局重复成功”。一次答对、点击采纳、赢下一局均不足以证明掌握。版本改变或多次失败时允许下调结论。

### 陪练：有情境、有分寸、尊重偏好

表达认可时点明玩家实际做好的选择；失利时先接住情绪，再由玩家选择是否复盘。不要虚构心理状态，不以每回合说话维持存在感，不把“陪伴”变成催玩或讨好。

休息提醒采用玩家可设置的时长、时段与频率，结合实际会话活动，避免把后台挂页算成持续游玩。优先在局末、首页或培养操作间隙提示，可延后或关闭；不做健康诊断，不中断关键行动。

记忆默认本地、可查看和纠正。明确偏好立即生效，行为推断标作暂定。提供删除与导出，删除需覆盖摘要和索引。送给模型的材料只包含当前任务必要信息。

## 5. 真正能用的底线

- 一局从开始到结束可完整运行；引擎不可用时明确显示故障，不能用页面 HTTP 200 表示健康。
- 技能详情、合法动作、实际结算、建议、培养面板采用同一规则与个体投影；未支持机制在选择或分析前可见，不能默默按普通伤害处理。
- 规则变更有版本；对局锁定规则，旧回放不能无提示地换新规则重算。
- 断网、模型超时、刷新、重复点击、切页和多局切换具有明确行为，不能串局、重复行动或展示过期回答。
- 队伍与培养改动先预览、可撤销；保存失败有提示，不能吞数据。恢复进行中的对局若尚未实现，界面应如实说明。
- 默认只呈现玩家需要的信息；证据和不确定性可展开，工程诊断留给开发者。

## 6. 实施顺序与退出条件

按依赖推进，不给未经估算的完成日期。每阶段交付可运行的一条体验和对应证据，不以新文档作为完成凭据。

| 阶段 | 交付与涉及范围 | 可以进入下一阶段的条件 |
|---|---|---|
| M0 服务与规则可信 | 修复 Python 入口和能力判据契约；逐技能结算与支持说明一致；建立启动烟测 | import、健康、创建对局、合法动作结算、技能详情通过；复现原故障的测试能拦住回归；分别记录隔离实例与玩家端状态 |
| M1 玩家与小芽看见同一局 | 公开观察事件、开局预览与回看、按回合快照、缓存与工具边界 | 已见六只不会遗忘；未预览不提前知道；隐藏值替换不影响同一公开输入；跨局不串数据 |
| M2 一局中能帮上忙 | 合法动作比较、有限分支、稳健建议、及时呈现、三路回退 | 七类关键场景真实页面走通；相对简单规则提示有可解释改进；查看不行动，采用只行动一次，迟到建议不可采用 |
| M3 打完知道练什么 | 按当时信息做关键复盘、变式练习、掌握证据 | 胜/负/投降/无明显失误均合理；每条替代当时合法；玩家能用自己的话讲清理由，并在无提示变式中检验 |
| M4 战前战后连起来 | 配队打法、目标培养、长期偏好、情境陪伴、休息提醒 | 本命宠和预算约束被遵守；配队修改可预览撤销；从复盘能进入对应练习或培养比较；关闭提醒有效 |
| M5 小范围可用版本 | 连续会话、错误恢复、版本证据、真人试用、质量看板 | 用户可独立完成完整流程；阻断性问题清零；记录真实学习收益、打扰与失败案例，再决定扩机制或模型 |

M0 当前由 DSH 修复会话负责。README 与本文由 Codex 编写。后续任务先指定文件写域与接口负责人，再并行；同一共享文件只留一个写入者。验收通过后按用户指定保存至 Gitee，不能把 WIP 快照写成可用发布版。

### 第一条必须验收的纵向体验

选一套机制可核验的六宠阵容 → 开局真实展示六只 → 玩家问“该换谁” → 小芽比较留场和换人 → 玩家查看与采用 → 真实状态转移 → 局末一条复盘 → 下一局一个无提示变式。

这条链是产品价值的最小证明。先完成它，再增加更深搜索、更多机制与更复杂的玩家画像。

## 7. 怎么判断好不好用

以下是首轮验收建议，不是已有成绩。冻结场景与规则版本，保留失败，避免训练或调参反复看同一批验收题。

| 维度 | 验证方法 | 建议门槛 |
|---|---|---|
| 事实与权限 | 替换隐藏六维/天分/配招/后备状态，比较公开投影与确定性建议；扫描网络与工具输入 | 冻结集隐藏信息泄漏为 0；缺证据不能生成确定断言 |
| 行动安全 | 覆盖克制换人、未知配招、低能量、濒死、同速、未上场已见宠、对手实际换人 | 非法行动、过期采用、重复结算均为 0 |
| 策略价值 | 同局面对比不提示、简单规则提示、现有 Coach 和新版；用独立规则复核或专家盲评 | 明显有害建议为 0；对相近合理动作接受并列；逐个解释无提升或退步 |
| 时效 | 保存事件、计算、呈现、玩家行动时间；分别统计本地、云端与回退 | 暂定本地首条有效建议 p95 ≤1 秒；复杂回答首条可用结论 p95 ≤3 秒；超时不阻塞操作，指标按实际机器复核 |
| 可理解性 | 让玩家复述“建议做什么、为什么、主要风险” | 首轮至少 5 位目标用户；至少 4 位无需开发者解释完成核心链路；记录原话，不把小样本推广成普遍结论 |
| 学习收益 | 前测、训练、无提示变式和延迟复测，区分提示下成功 | 相比简单提示有方向一致的改善证据；样本不足明确标未证明，不以胜率或采纳率替代 |
| 打扰与陪伴 | 记录主动提示次数、重复/过期率、关闭原因，并访谈 | 偏好违规为 0；无新增价值不重复；玩家主动提问始终获得相应处理 |
| 可靠性 | 连续多局、刷新、离线、慢模型、异常回执、规则版本切换 | 验收中无数据丢失、串局、不可恢复的界面卡死；恢复机制有实测 |

冻结场景同时保留状态、公开观察、假设、合法候选、工具结果、实际动作、规则/代码版本和呈现时间。避免只检验关键词出现或回答变长；机器检查之后仍需观察真人是否能理解和使用。

## 8. 工程落点与演进原则

| 能力 | 现有入口，需核对具体实现 | 应保持的契约 |
|---|---|---|
| 规则与公开状态 | `roco/src/roco_env/env.py`、`service.py`、`src/server/roco-service.js` | 真值与观察分离，规则版本和状态版本可追溯 |
| 对手假设与动作分析 | `src/coach/opponent-belief.mjs`、`coach-advice.js`、Python 规划器 | 假设来源、分支预算、合法候选与收益定义显式 |
| 模型编排与回退 | `src/coach/runtime.js`、`toolbox.js`、`roco-client.js` | 保意图、限权限、有限工具调用、超时与失效处理 |
| 复盘与学习 | `teacher.js`、`teacher-review.js`、`roco-experience.js` | 决策时信息、反事实边界与掌握证据一致 |
| 陪伴与记忆 | `companion.js`、`memory.js`、`experience.js` | 偏好优先、少打扰、可纠正可删除 |
| 玩家交互 | `src/client/roco.js`、`xiaoya.js`、`team-workshop.js`、`box*.js` | 一个小芽入口、可理解的操作、无静默数据损失 |

存在多个 review/建议入口时，先画实际调用路径与契约测试，再逐步收敛，避免重写一套旁路。先证明本地规则与工具产生价值，再评估模型改善了哪些环节；不按模型大小判断质量。

4B 训练由用户本人负责，27B 暂缓。可准备版本化工具契约与隔离评测集，但不得自动启动训练、下载权重或切换主服务模型。用户服务重启与数据清理不属于本计划授权。
