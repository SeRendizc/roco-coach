## 二、第 3 项为什么降级成"待审候选"（Codex 的三条纠偏，我逐条复核成立）

1. **历史模型输出 + 工具回执 `ok` ≠ 黄金标签。**
   例：「为什么这一手要防御？」被标成 `{"stop":true}`，而该轨迹的 `reply` 是
   「这次没有查到可用的规则事实（complete），未核验的部分我不编。」——**这是一条失败轨迹**；
   同一句在数据里出现 **12 次**（只换措辞/锁定前缀）。
2. **目标语义本身就错。** 例：「化蝶是哪一只？」的目标是 `pet_000225`（**寂灭骨龙**；化蝶是 `pet_000124`），
   另一行还给过 `pet_000190`。⇒ 必须**逐条核语义**。
3. **"88 族、跨片 0 重叠"语义无意义。** 实测 `case_id` 是**措辞变体**（288 个），
   去掉 `-fN-N` 后的**语义族只有 27 个**；`be-defense-f0-01`(train)/`f1-02`(valid)/`f2-02`(test) **跨片**。

## 四、**推荐**与可运行的对齐方案（都不动主服务、都不启动训练）

**已核实的前提**：`mlx_lm.tuner.datasets` 调 `apply_chat_template` **4 处、没有一处传 `enable_thinking`**
（该类源码里该关键字 **0 命中**）⇒ **mlx-lm 没有这个旋钮**，所以"在 yaml 里加一行"是**做不到的**。

### 推荐：把**训练**对齐到 `enable_thinking=False`（与服务一致）

理由：服务侧已经默认关；关思考**省 token**，而我们的任务只是"下一步查不查工具"这种小决策，
不需要思维链；对齐方向选"改训练"就**不动线上任何东西**。

**方案 A（最不侵入，推荐）—— 用包装 tokenizer 在训练侧注入默认值**
写一个自己的数据入口（`scripts/model/train_chat_dataset.py`），继承 mlx-lm 的
`ChatDataset`，只覆盖取 token 的那一处，让 `apply_chat_template(..., enable_thinking=False)`；
训练脚本用 `--data` 指到它。**不改 mlx-lm 源码、不改服务**。

