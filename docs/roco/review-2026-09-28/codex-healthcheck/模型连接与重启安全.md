# 模型连接与重启安全（Codex 2026-09-29 第一轮监工第 1 条的回应）

> 这一份回答 Codex 的原话：
> 「8765 `/api/models` 云端 `connected=false/verified=false`，`reason=还没有配置API key`；上轮检查曾 `connected=true`。
>  server-restart 日志明确密钥只存在进程内存，重启丢连接。**禁止再次无保护重启**；不找/打印密钥、不擅自持久化。
>  请记录恢复依赖、改善重启流程与缺连接反馈，**并把模型连通作为服务健康项；现阶段不能只报 HTTP 200**。」

## 2. 恢复依赖：为什么重启就丢，怎么才能回来

| 项 | 事实 |
|---|---|
| 来源 | `src/server/index.js:562` 在**启动时**从环境变量 `DEEPSEEK_API_KEY` 读一次（只在格式像 `sk-…` 时才采用） |
| 存活范围 | **只活在这一个进程的内存里**。代码里没有任何持久化路径 |
| 一重启就怎样 | `/api/models` 立刻变成 `connected=false`，`reason="还没有配置 API key"` |
| ⚠ 最坑的一点 | **HTTP 仍然是 200** —— 只看 200 的健康检查**完全看不到这件事** |
| 玩家看到什么 | 页面**不是白屏**：小芽会写「未连接模型：小芽只给规则事实（去 connect.html 配置）」（`src/client/xiaoya.js:680`），模型状态处显示「未连」（`src/client/roco.js:1729`） |
| **恢复只能由人做** | 在**启动服务的那个 shell** 里提供 `DEEPSEEK_API_KEY` 再启动。我们**不找、不打印、不落盘、不写 `.env`** |

**恢复步骤（人类执行，约 20 秒）—— 首选 `connect.html`，不用重启、不用碰 shell 历史**：

1. 打开 **<http://127.0.0.1:8765/connect.html>**
   （页面上写着：「密钥在本页**加密后**提交给本机后端，**仅保存在后端内存**。关闭服务即失效。」）
2. 粘贴 key，提交。服务端路由 `/api/connect` 收的是 **RSA-OAEP 加密**后的串
   （`src/server/index.js:778`），解密后**只写进内存**的 `credential`，然后把 `verified` 置为 false 重新验证。
3. `curl -s http://127.0.0.1:8765/api/models` 看 `connected` / `verified`；
   或直接 `node scripts/roco/healthcheck.mjs`，应当从**降级**变成**健康**。

> **这是首选的恢复路径**：它**不需要重启**（也就不会丢掉别的状态），
> **不经过 shell**，所以**不会进 shell 历史**，也与我们「不落盘」的承诺一致。
> 断开连接用 `/api/disconnect`（同样只清内存）。

⚠ **不推荐**的做法：在命令行里 `export DEEPSEEK_API_KEY=...` 再启动。两个原因：
① **明文会写进 shell 历史**（`~/.zsh_history` 等），而这与"不落盘"的承诺是矛盾的 ——
   密钥等于落盘了；② 那样起的服务一旦再重启，同样会丢。
如果确实必须走环境变量（例如无人值守启动），**至少**用不回显、不落历史的写法：

```sh
read -rs DEEPSEEK_API_KEY          # -s 不回显；不要用 export KEY=明文
export DEEPSEEK_API_KEY
set +o history                     # 或者事先 `setopt HIST_IGNORE_SPACE` 并让命令以空格开头
```
（这一段只是"如果非走不可"的兜底；**首选仍然是 `connect.html`**。无论哪种方式，我们都不读、不打印、不保存它。）

## 3. 加的两个东西（把"模型连通"变成一等健康项）

### `scripts/roco/healthcheck.mjs` —— 五类检查，**不只报 200**

实测输出（2026-09-29）：

```
[health] http://127.0.0.1:8765 —— **降级**（服务与数据正常，但模型没连上）
  ✔ http        box.html HTTP 200
  ✔ data        我的盒子 542 / 图鉴 622
  ✔ engine      引擎 available=true
  ▲ model       云端 cloud-deepseek：connected=false verified=false｜reason="还没有配置 API key"
  · model.local local-qwen35-4b：connected=false｜reason="本地模型开关是 off（…）"
  · model.local local-qwen38-27b：connected=false｜reason="本地模型开关是 off（…）"
  ✔ sprite      迪莫 thumb 45357 字节 image/png
```

**退出码是有含义的**，让监工脚本能直接判：

| 码 | 含义 | 为什么分开 |
|---|---|---|
| `0` | 健康 | —— |
| `2` | **降级**：服务/数据/引擎/立绘都好，**只有模型没连上** | 这正是 Codex 要的区分：只报 200 会把这件事藏起来 |
| `1` | **坏了**：HTTP / 数据 / 引擎 / 立绘 有硬伤 | 与"降级"分开，避免把"小芽答不了"当成"服务挂了" |

### `scripts/roco/serve.mjs` —— 受保护的重启

- `--status`：先告诉你要不要重启、**重启会丢什么**；
- `--restart`：**连着模型时默认拒绝**（退出码 3），并打印"丢什么 + 怎么恢复 + 文档在哪"；
  确实要重启必须显式 `--restart --force`；
- 起来之后**自动跑一遍健康检查**，把"模型没连上"当场喊出来。

实测（当时没有云端连接，属安全重启）：
```
[serve] 现在没有云端连接可丢，安全重启…
[health] … **降级**（服务与数据正常，但模型没连上）
[serve] 提醒：服务是好的，但**模型没连上** —— 玩家会看到"小芽答不了"。
```

### ⚠ 第二轮修正（Codex 2026-09-29 第二轮复核）：不再有任何模糊的 `pkill`

第一版把 `pkill` 的模式从 `node src/server/index.js` 改成了 `src/server/index.js` —— 那只解决了
"绝对路径杀不到"，**没解决"会误杀别人的同名服务"**。Codex 点得对：

> 「serve.mjs 用 `pkill -f src/server/index.js`，会匹配**其他项目/其他端口的同名服务**。
>  请只停止经**端口 8765 + 本仓绝对入口/工作目录**核实的 PID；目标不明确就**拒绝**，
>  不用模糊全局 pkill，也**不要为了验证再重启主服务**。」

现在**一行 `pkill` 都没有了**，改成**三重取证 + 只 kill 那一个 PID**（`process.kill(pid, 'SIGTERM')`）：

| # | 证据 | 不满足时 |
|---|---|---|
| ① | 端口必须是 **8765**（`lsof -nP -iTCP:8765 -sTCP:LISTEN`，**按端口查不按名字查**） | 拒绝 |
| ② | 该 PID 的**工作目录 == 本仓根**（`lsof -a -p PID -d cwd -Fn`；这台机器 `ps` 不可用，cwd 是最可靠的归属证据） | 拒绝 |
| ③ | **HTTP 身份探测**：`/box.html` 里必须带本产品字样 | 拒绝 |

**查不到、有多个监听者、cwd 对不上、身份不对** ⇒ 一律 `拒绝` 并说清原因（退出码 4），
**绝不给出一"差不多"的 PID**。

**`--dry-run`**：`node scripts/roco/serve.mjs --restart --dry-run` 会走完上面全部取证、
只打印"**只会** kill pid N"，**什么都不杀** —— 这就是"不要为了验证再重启主服务"的答案。
本节所有读数都是用 `--dry-run` / `--status` 取的，实测 PID 58726 **从头到尾没变**。

### ⚠ 第二轮修正 2：**连接"未知"也算非健康**

第一版 `healthcheck` 在 `/api/models` 取不到或形状不对时只给 `warn`，
最终仍可能判 **healthy**；`serve` 则可能把"未知"当成"没连接"而**放行重启**。Codex 点得对。

现在：**取不到 / 形状不对 / `connected` 不是布尔** ⇒ `classifyModels()` 判 `unknown` ⇒
`healthcheck` **报 `fail`（退出码 1）**，`serve` **拒绝重启**（退出码 3）。
语义上也对：**我们不知道连接在不在，就不能对外宣称健康。**

隔离测试：`tests/roco-serve-safety.test.js`（**6/6**，不连网、不起服务、不重启任何东西）——
覆盖 connected / disconnected / unknown（8 种坏形状）/ force / 多监听者 / cwd 不符 / 无监听者 /
端口不符 / lsof 输出形状变化，以及一条核心反证：**别人的 PID 绝不许被交出去**。

## 4. 给团队与新监工的**硬规则**

1. **不许再用 `pkill`（任何形式）**。要重启就 `node scripts/roco/serve.mjs --restart`；
   只是想知道会发生什么就用 `--status` 或 `--restart --dry-run`（**都不会动服务**）。
   `serve.mjs` 只杀「端口 8765 + 工作目录 == 本仓 + HTTP 身份对得上」的那**一个** PID，任何不明确都拒绝。
2. **不许读/打印/保存密钥**，不许写 `.env`、不许把 key 塞进任何产物或聊天。
3. **报"服务正常"必须带健康检查的读数**（退出码 0/2/1），**不许只报 HTTP 200**；
   **「未知」等于不健康**（退出码 1），不许因为"问不到"就放行。
4. 模型没连上时，页面上要如实说"只给规则事实"——这一条**已经在做**（见 §2 表最后两行），
   本轮没有改动它；记在这里是为了让它成为**被检查的**项而不是"碰巧有"。

## 5. 模型方向（与本条相关的边界，来自用户与 4B 交接）

- **27B 暂缓**，**4B 由用户亲自训练**；`docs/roco/review-2026-09-28/codex-healthcheck/4b-training-guide/` 是交接材料，
  同目录里的旧训练命令**不构成执行授权**。
- DSH/监工：**不启动训练、不下载 27B、不改正在使用的主服务模型**。
- 本地模型默认是 **off**（`ROCO_LOCAL_MODEL=on` 才启用）——所以"云端没连上"就等于"没有模型可用"，
  这就是为什么它必须是一等健康项。
