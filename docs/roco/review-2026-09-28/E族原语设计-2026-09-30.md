## 1. 关键未知已定：`cleanse` 事件的 `cleared` 是**什么量纲**（真样本 dump）

```
【有可驱散物】skill_000325 晒太阳「驱散敌方所有增益。」
   准备：我方 buffs {} · 敌方 buffs {"spa":70,"spe":30,"def":20}
   实跑 EVENT cleanse {"side":"player","cleared":**["def","spa","spe"]**}
   结果：敌方 buffs = {}          ← 真的清空了 ✓ · marks 一个没动
【反证·无可驱散物】敌方 buffs {}
   实跑 EVENT cleanse {"cleared":**[]**} ⇒ **Δ = 0** ✓（事件照发、数组为空 ⇒ "驱散 0 个"可观测 ✓）
宿主体（`env._apply_effect_batch` 的 `cleanse` 分支，逐字）：
   cleared = sorted(foe.field_pet.buffs) ; foe.field_pet.buffs.clear()
```
**结论（三条，都会影响新原语设计）**
1. `cleared` = **被清掉的 `buffs` 键名数组**；**没有层数维度** ✗
2. 宿主体**只碰 `buffs`，完全不碰 `marks`** ✗ ⇒ 「印记」那 5 条**没有落点**
3. **层数只存在于 `marks`**（`marks["星陨印记"] = 3` ⇒ 3 层 ✓）；`buffs` 是 `{stat: 百分比}`，**"层"这个概念不存在** ✗
   ⇒ ⇒ 「每驱散1层」**只能**建立在**印记层数**上；用 buffs 去实现它就是**编造量纲** ✗

## 2. ⚠️ 先于新原语的一条：现有 `cleanse` 有一处**语义错位**（比"没实现"更糟 ✗）

```
skill_000408 焚烧烙印「驱散**双方所有印记**，每驱散1层，敌方获得5层灼烧。」
  解析层：**认了** ⇒ `cleanse{target:"foe", what:None}`（`_CLEANSE` 只认「驱散双方所有印记」这一种写法）
  准备：我方 marks={"风起印记":2} · 敌方 marks={"星陨印记":3} · 敌方 buffs={"spa":70}
  实跑：EVENT cleanse {"cleared":**["spa"]**}      ← **清掉的是敌方的"增益"** ✗（描述要求驱散的是**印记**）
        EVENT status_added {"status":"灼烧","layers":5}   ← 后半照常结算 ⇒ 界面上"看起来生效了" ✓
  结果：敌方 marks 仍 {"星陨印记":3}（**一层没驱散** ✗）· 我方 marks 仍 {"风起印记":2}（**一层没驱散** ✗）
        ⇒ 而**敌方增益被静默清掉了** ✗（玩家观测到的副作用与描述无关）
skill_000332 倾泻「…则驱散双方所有印记」同型（本次 `cleared:[]` **只因对手当时没 buffs** ⇒ 碰巧没造成副作用 ✗）
```
**判定**：**半成品（语义错位）** ✗ —— 它**不是"如实报不支持"**（那种不碰局面），而是**执行了另一件事** ✗
**建议止血（不需要新原语）**：`_apply_effect_batch` 的 cleanse 分支**按 `what` 分派**；
`what` 认不出（现在 332/408 都是 `None`）时 **fail closed**：不执行、只 `_note_unsupported` ✓
⇒ 这条**应排在所有新原语之前**（当前它会改错局面 ✓）

## 4. 新原语要覆盖的形状（**描述原文 → 语义 → 落点**）

### 形状 B：驱散印记（5 条）
```
原文：驱散<双方|自己|敌方>所有印记 / 驱散敌方印记
语义：把指定一侧（或两侧）的 `marks` 清空；**必须同时报告"清掉了几层"**（见形状 E）
落点：写点 = `env._apply_effect_batch` 的 `cleanse` 分支（现在只动 `buffs` ✗ ⇒ 要按 `what` 分派）
      读点 = `PetState.marks`（`{印记名: 层数}` ✓ 层数天然存在 ✓）· 事件 `cleanse`
```
### 形状 C：驱散自己的减益（4 条）
```
原文：驱散自己的减益
语义：清 `self.buffs` 里 **delta < 0** 的键（"减益"= 负向属性修正；术语 1013）
落点：同一个 `cleanse` 分支，加 **side=self** + **取负值** 两个维度
     ⚠ 与 A 的差别只有这两维 ⇒ 落点完全复用 ✓（**这是最省的一条**）
```
### 形状 D：驱散敌方 N 种增益（2 条）
```
原文：驱散敌方1种增益
语义：清 `foe.buffs` 里**恰好 1 个**正向键 —— ⚠ **"选哪一个"数据里没有定义** ✗
⇒ 两条出路（**需要拍板**）：
  ① **本地规则**：例如"清绝对值最大的那个"（人类授权"缺参数就在本地规则里显式定义" ✓）
     但这是**选择语义**、不是补数字 ⇒ 我倾向要人类/Lead 明确点头 ✓
  ② **fail closed**：如实报不支持 ✓（**不做也不错** ✓）
落点：若走 ①，仍在同一个 `cleanse` 分支（加 `count=N` 维度）
```
### 形状 E：每驱散 1 层（2 条，**依赖 B**）
```
原文：每驱散1层，<后续效果>
语义：读"**刚刚被驱散的印记层数合计**"，按 1 层 = 1 份后续效果
⇒ **必须**由 B 的报告提供 **层数**（现在 `cleared` 只有键名 ✗）
⇒ ⇒ **量纲警告**：`buffs` 没有"层"✗ ⇒ 若某条写「每驱散1层**增益**」⇒ **如实报不支持** ✓（不许编量纲）
落点：写点 = B 的 cleanse 分支；读点 = 紧跟着的那条效果（408→灼烧层数 · 415→物攻%）
```

## 5. 建议的原语形状（给实现者，**照抄即可**）

```python
# 解析层（parse.py）：把五种写法读成同一结构
Effect(kind="cleanse", target="self"|"foe"|"both", value={
    "scope": "增益" | "减益" | "印记",     # 清什么
    "count": None | 1,                      # None = 所有；1 = 1 种（形状 D）
})
# 事件（env.py::_apply_effect_batch 的 cleanse 分支）
_bump(state, "cleanse", {
    "side": side,
    "scope": scope,                          # 新增：说清清的是哪一类
    "cleared": [...],                        # ★ 保持原语义：buffs 键名 / 印记名（**不许改量纲** ✗ 兼容既有 325）
    "cleared_layers": {name: layers},        # ★ 新增（仅 scope=="印记"）：供形状 E 消费
    "layers_total": int,                     # ★ 新增：`cleared_layers` 之和
})
```
**兼容纪律（三条）**
1. **`cleared` 的既有语义不许改** ✗ —— `325` 的读数（`["def","spa","spe"]`）与判据都钉着它 ✓
2. 新键（`scope` / `cleared_layers` / `layers_total`）**只在「印记」这一支出现** ⇒ A 形状的事件**逐位不变** ✓
3. ⚠ **ⓐ 风险**：`cleared_layers` 若**没有消费者**就是"写了没人读" ✗ ⇒ **必须与形状 E 同批落地**，
   或**先不加这个键**（形状 B 单独先做）✓ —— 这是本设计的**唯一 ⓐ 风险点**，明确写在这里 ✓

**判据（每条要钉的）+ 反证（Δ 必须 0）**
```
① A（325）既有判据保持 ✓：有物 ⇒ `cleared:["def","spa","spe"]` + buffs 真清空；**反证** 无物 ⇒ `cleared:[]` 且 buffs 不变 ✓
② B：双方/己方/敌方各一条 —— 断言 `marks` 真的空了、**`buffs` 一个没动** ✓（**这条正好钉住 §2 那个错位** ✗）
   反证：**没有印记时** ⇒ `cleared:[]`（或 `cleared_layers:{}`）· **marks 不变** · **后续效果（灼烧/物攻）Δ=0** ✓
③ C：先给自方挂 `buffs{atk:-30,spa:-20}` 与一个正向 `def:+50` ⇒ 断言**只清掉负向那两个**、正向留着 ✓
   反证：**只有增益没有减益** ⇒ `cleared:[]` 且 buffs 不变 ✓
④ E：印记 3 层 ⇒ 后续效果 = 3 份；**反证：印记 0 层 ⇒ 后续效果一份都不给** ✓（"驱散 0 层不许触发" ✓）
⑤ D：若走 fail closed ⇒ 断言判据 `resolved=False` + 点名 ✓（**不做也不错** ✓）
```
