## 0. 什么叫"完成"（**唯一口径**，缺一条就算半成品 ✗）

```
一条能力/功能算"完成"必须**五条全有**：
  ① **能跑通**        —— 真跑一次（引擎：真打一局；前端：真浏览器；数据：真跑评测器）
  ② **判据绿**        —— 有判据钉住它，且判据**是真判它**（不是只判"对象有键"✗）
  ③ **运行时报据**    —— 事件 / 字段 diff / 可见面读数（**不是"代码里有"** ✗）
  ④ **反证**          —— 条件不成立时 **Δ 必须 0**（对照实验）
  ⑤ **对照实验**      —— 至少一个"应该不触发"的输入，且它真的不触发
```
**判"半成品"的六种形态**（本会话全部见过 ✗）：
```
ⓐ **写了没人读**：事件/字段真发，但引擎里**没有任何读点**（例：task-25 那 11 条能力位 ✗）
ⓑ **恒不触发**：分支写了但条件永假（例：`_damage_preview` 里那支 ✗）
ⓒ **同名两份**：定义了两遍，**跑的是旧的那份**（例：`renderTeamPlanBlock` / `hideEvalDrawer` ✗）
ⓓ **占位/常量**：文案像判断，其实是等权假设或写死的字符串 ✗
ⓔ **只在 DOM/代码里，不在可见面**：`textContent` 有、玩家看不到（closed `<details>` ✗）
ⓕ **只在解析层**：parser 认了 ⇒ `resolved=True`，但**运行时没结算** ✗
```
