## 2. 自曝：我的探针**行数模型写错了**（不是代码缺陷）

我最初的逐步断言写成"`turn` 不变 ⇒ 行数不增"，跑出 **9 条 problems**。查清后确认**是我模型错**，真实序列是：
```
battle→battle   turn +1  行数 **+1**        （每个正常回合恰好一行 ✓）
battle→replace  turn 不变 行数 **+1**        ← 先起一行（这一回合的前半段）
replace→battle  turn +1  行数 **+0**        ← 并进上一行收口（这一回合的后半段）
```
即"**先起一行、再合并收口**"，**终局一行/回合**（28 行 / 28 回合、严格单增、无重复）；
`turnSteps: 25` 与 3 个 `+0` 逐步对账吻合 ⇒ "不同回合没有被并掉" 也成立。

> **纪律**：0 命中 / 失败先怀疑**自己查的地方**。这一条与"把中途态当结果"是同一族错误。

## 3. 边界：`field` 为空那一帧**在真局不可达**（已量清原因，不是"没找到"）

定向打两局（`node tmp/xy-r17-frame.mjs`），每次推进后立刻采样 `phase / field / needs_replacement`：
```
第1局 win：phase 分布 {battle:25, replace:5, ended:1} · 对手 field 为空 = 0 帧 · 真倒下(hp=0) = 4 帧 · 28 行/turns 1..28
第2局 win：与第1局逐字相同
倒下帧逐字样本：
  step10 turn10 phase=replace foeField=魔力猫 hp=0  need=["enemy"]
  step16 turn15 phase=replace foeField=鸭吉吉 hp=0  need=["enemy"]
  step20 turn18 phase=replace foeField=草头鸭 hp=0  need=["enemy"]
```
**归因（可判定的事实）**：补位阶段引擎把**倒下的那只留在场上（hp 0）**，`needs_replacement=["enemy"]` 只表示"轮到对面补人"，
**`field` 本身不置空** ⇒ UI 视图的「（名字未登记）」分支**在真局不可达**，只有合成用例 **㉝** 覆盖。

**撞到的相邻那一帧（玩家真会看到的一瞬）——两局 0 违规**：
```
matchHistory 里 before/after 名字为 null 的行：对面 0 · 我方 0        ← field 有值 ⇒ 必须有名字 ✓
后备血量泄漏行数：0 ✓            turnLog 里对面名字为空的条数：0 ✓
正文含 pet_id = False ✓          正文「对面 未知/某某/精灵/对手」= False ✓      正文回合号重复 = [] ✓
```
⇒ **"有名字时绝不错报未登记"（假报方向）守住了**；"该未登记时照实"由 ㉝ 守。两条合起来口径完整。

**要不要补真局覆盖？** 建议**保持现状**（Lead 已裁决）：
- (a) 引擎侧把补位阶段 `field` 置空 = **改公开协议**，且与「手游里倒下的那只还画在场上」的既有口径冲突，且属引擎写域、无玩家需求支撑；

## 4. 一条要记进材料的纪律：**同一个样本不许数成两个**

第 3 节那"两局"**逐字相同**（同 seed 同选人 ⇒ 同一局复现：`phase 分布`、倒下帧、`turnLog` 12 条全一样）
⇒ 所以"两局"在这条上**等于一次独立样本**，**不许当两次独立证据**。

> 它是「**跨时间点比较会骗人**」的**姊妹纪律**：那条防的是**拿不同时间的量去比**，
> 这条防的是**把同一个样本数成两个**。两者都会让"证据数量"看起来比实际多。
