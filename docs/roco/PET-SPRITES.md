# 48 只精灵立绘（槽位 → 画）与身份审计

> ⚠ **2026-09-28 已知缺口（如实标注，不假装齐全）**：本页的「48」是**立绘资产**的槽数，**不是**可玩层的只数。人类 2026-09-28 拍板「所有精灵实装」之后，冻结可玩层已经是 **542 只**（可玩层 530 + 基线 12），而 `data/roco/assets/pets/manifest.json` 仍然只有 **48 槽 / 96 张 PNG**
> ⇒ **542 只里只有 48 只有立绘，另外 494 只没有**。这是**资产缺口**，不是文档口径过时，也不是数据错误。
> 页面上的表现：没有立绘的精灵走头像兜底（见 `src/client/box.js` 的 `avatarOf`），不会白屏、也不会编一张画出来。
> 要不要补立绘、补哪些，等人类发话；补之前这一页的「48」就只描述**资产**。

> 这一页回答一个问题：**页面上第 N 号精灵显示的那张画，真的是第 N 号精灵吗？**
> 2026-09-23 人类报「立绘很多对不上」，查明的根因不是画错，而是**文件与槽位错位一格**。
> 结论与判据都在 `data/roco/derived/pet-sprite-audit.json`（生成器
> `scripts/roco/build-pet-sprite-audit.mjs`，闸门 `scripts/roco/verify-pet-sprites.mjs`）。

## 1. 资产在哪、谁在用

| 位置 | 作用 |
|---|---|
| `data/roco/assets/pets/<asset_key>-{default,action}.png` | 仓库内的 96 张 384×512 RGBA 立绘（48 槽 × 2 态） |
| `data/roco/assets/pets/manifest.json` | 48 槽的 `slot / name / asset_key / types / role / speed_tier`；**绑定键是 `asset_key`，不是显示名** |
| `data/roco/assets/pets-unmapped/` | 名单**外**的立绘（见 §3），不参与 48 名单 |
| `GET /api/roco/sprite?id=<pet_id>&name=<名>&v=default\|action` | 只读路由：`pet_id → 槽位 → asset_key`，key 必须在 manifest 名单里（不做目录遍历） |
| `src/client/roco.js` 的 `b3SpriteUrl()` / `b3-sprite` | 战斗页立绘；拿不到图就 `data-b3-sprite="none"` 并**留空**（不画占位、不猜） |

## 2. 审计怎么做的（两把尺子）

1. **逐像素**：把 12 张素材板按行优先展开成 96 个格位（每只精灵占相邻两格：
   `default`、`action`），再把仓库里 96 个文件与格子逐像素比对。86 张**逐字节相同**；
   槽 17–20 那 8 张来自一张格子是 443.5×443.5 的方图（`batch-05.png`），
   按**记录在案的等比变换**（放大到高 512 → 水平居中裁到 384，双线性）重切过，
   复核时用同一个变换重算一遍，MAD ≤ 1.5 像素。
2. **逐张识图**（人眼 + 子代理独立复核）：形态与名字逐个对，边界抽样
   （槽 24 对齐、槽 25 起错位、槽 37/38/47/48 的棋契陛下两变体）。

两条证据合起来给出**规则**（机器可读地写在审计产物里）：

```
格位 p（1..96）属于序列里第 ceil(p/2) 只精灵：
  序列 = 名单第 1..24 槽 + 名单第 26..48 槽 + 名单外的「云灵」
所以：槽 s ≤ 24 占格位 2s-1 / 2s；槽 s ≥ 26 占格位 2s-3 / 2s-2；格位 95/96 无归属。
```

## 3. 查明的两件事（都不是「画错了」）

- **错位一格**：素材集从第 25 张起整体偏移 —— 文件 `pet-25-蹦蹦种子` 里装的是
  **花魁蜂后**（槽 26）的画，`pet-26-花魁蜂后` 里装的是深蓝鲸（槽 27）……直到
  `pet-47-画间法师手` 里装的是棋契陛下·盾形态（槽 48）。**24 个槽位全部显示成下一只**。
  修法：把旧槽 25–47 的**内容**依次挪到槽 26–48（文件名/`asset_key` 不变），
  这样「槽位 ↔ 画」重新对齐，且不需要重新生成任何图。
- **槽 25「蹦蹦种子」没有立绘**：素材集里根本没有它，却多出一张名单外的
  「云灵」（深蓝小云灵：大发光黄眼、周身白云、头顶金环、金色闪电）。游戏数据
  （`data/roco/raw/extracted/rocom-data/data/sprites.json`，1132 个名字）里搜不到「云灵」，
  所以它不是本名单里某一只的别名。**槽 25 曾故意留空**（战斗页 `img.onerror` 留空并记
  `data-b3-sprite="none"` —— 宁可空着，也不显示别人的画）；**2026-09-24 人类自己给了这只的画**
  （`/Users/serendizc/Codex/Internship/bengbeng-seed-default-action-384x512.png`，上下两帧：
  站姿 + 跳姿），于是按「外部来源」登记进 `data/roco/assets/pets-sources.json` 并落成两张 384×512。
  审计口径随之新增一档 `human-supplied`：**它不是素材板切出来的，也不许被当成素材板里的一格**。

### 3.1 人类供图这一张重做过一次（第一版有可见缺陷）

第一版把两帧按 **y=256 硬切**、再用「边缘像素延伸」补边。实测源图 **y=225..247 整段是空白**，
站姿内容到 y=220 结束，而跳姿那根茎**从 y=248 就开始**（在 256 之上）⇒ 硬切会把跳姿的茎切进站姿帧里，
再被纵向拉成一条 **135px 高的绿条**（action 帧顶上同样有一条）；接缝也在（实测第 361..364 行是一条全宽色带）。
重做后的确定性变换（逐字写在 `pets-sources.json` 的 `transform_script` 里）：

| 步骤 | 做法 |
|---|---|
| 切帧 | 按**空白行**切：default = 源 `y0..245`、action = 源 `y246..511` |
| 内容框 | 与左上角实测底色 `rgb(249,248,241)` 容差 26 求 bbox：default 225×217 @(79,5)、action 291×239 @(54,249) |
| 缩放 | **两帧同一个缩放** `s = min(384/291, (512-48)/239) = 1.3196`（两帧同缩放 ⇒ 切换立绘时体型不跳） |
| 摆放 | 双线性重采样 → 底边留 24px、水平居中；其余像素**平铺底色**（不拉伸边缘） |
| 产物 | `pet-25-蹦蹦种子-default.png`（`297x286 @(44,202)`，sha256 `d23ae33…`）、`-action.png`（`384x315 @(0,173)`，sha256 `40e189c…`） |

重做完 `node scripts/roco/build-pet-sprite-audit.mjs` **96 张 / 人类供图 2 / 缺图 0 / 默认立绘互异 48**，
`node scripts/roco/verify-pet-sprites.mjs` 判 **pass**。**已知边界**：源图跳姿那根茎在它自己那一帧的顶边就被画布裁断了，
所以 action 立绘的茎顶端是直的（这是源图的边界，不是变换造成的）；要让角色像素材板那样占满整幅，得人类给两张独立的 384×512。

## 4. 补图 / 换图的正确姿势

1. 把新图做成 384×512 RGBA PNG，命名 `<asset_key>-{default,action}.png`；
2. 放进 `data/roco/assets/pets/`；
3. 重跑 `node scripts/roco/build-pet-sprite-audit.mjs --sheets <素材板目录>`，
   它会重新逐像素对回素材板；**对不上就会红**（这时要么补素材板，要么明确登记这是名单外的图）；
4. 跑 `node scripts/roco/verify-pet-sprites.mjs` 确认闸门这条绿。

**两条不同的路，不许混**：素材板切出来的图，出处由 `build-pet-sprite-audit.mjs` 逐像素对回格子；
**人类自己画的/给的图**（现在只有槽 25）走 `data/roco/assets/pets-sources.json` 的 `human_supplied` 条目 ——
里面必须写清 `source_file` + `source_sha256`、**逐帧的切法**、变换的字面步骤、以及每张产物的 sha256。
判定「这张是不是人类供图」以那份名单为准，**不是**看它像不像素材板。

> 纪律：**不发明、不猜、不拿别人的画凑**。已知缺图的槽位（现在只有 25）在审计产物里
> 写 `missing-known`，闸门会**拒绝**它突然多出一张未经审计的图。

## 5. 判据红在哪（必红方向）

- 改任何一个立绘文件的字节 → `verify-pet-sprites` 报「立绘变了（sha256 不一致）」；
- 给槽 25 塞一张图但不重跑审计 → 报「记为已知缺图，但文件存在了」（**现在槽 25 已是 `human-supplied`**，
  这条反证仍然有效：把 `pets-sources.json` 里那条删掉、文件留着，闸门必须报「对不上任何格子」）；
- 把两个槽位指向同一张画（例如复制 `pet-38` 去补 `pet-48`）→ 报「同一张图」；
- 素材板里某个文件被换成别的画 → `build-pet-sprite-audit.mjs` 报「对到第 X 格，期望第 Y 格」。
