# 精灵数值的四层口径（人类 2026-09-27：「应该做种族和个体值、性格和资质就够吧？」）

> 这一页回答一件事：**人类点名的四层，我们各自对应到哪份数据、算不算得出来、还有什么是空白。**
> 口径的**唯一实现**在 `src/coach/talent.js`（面板与性格系数）与 `data/roco/normalized/<ruleset>/full-catalog.json`
> （种族值）；判据在 `tests/roco-panel-level.test.js`、`tests/roco-talent-nature.test.js`、`tests/roco-codex-local.test.js`。
> 数字**只来自数据层**，缺的写"查不到"，不猜（红线）。

## 一、四层对照表

| 人类的说法 | 我们的层 | 数据在哪 | 状态 |
|---|---|---|---|
| **种族值** | 图鉴六维（race / base stats） | `full-catalog.json` 的 `stats`；**522 只已按人类拍板采用抓包值**（`stats_source: capture-2026-09-27`，旧值留在 `stats_previous`） | ✅ 已建 |
| **个体值**（资质、天分） | 天分：六项各 **0–10** | `src/coach/individuals.js` + 存档里的每只个体 | ✅ 层已建；**真实值没有**（抓包是静态数据，不含每只的天分）⇒ 现在的个体是示例/掷点，引用时要说明 |
| **性格** | 30 条（6 长处 × 5 短处，无中性） | `src/coach/natures-data.js` + `talent.js` 的 `natureFactor` | ✅ 已建 |
| **资质**（整体说法） | **不是第三份数据**：官方攻略把它说成「种族值（白条）+ 天分（黄条）」的**显示概念** | 就是上面两层的合成视图，换算走面板公式 | ✅ 口径写清（见下） |

**「资质」这个词有三种用法**，别混（查证记录见台账 §C6.325 与 `docs/roco/MECHANICS-VS-POKEMON.md`）：
1. **单项资质** = 那一项的天分（0–10，道具「能力钥匙」可 +1、上限 10）⇒ 就是我们的**个体值**这一层；
2. **整体资质** = 白条（种族值）+ 黄条（天分）的合成显示 ⇒ 不是独立数据层；
3. 口语里"资质好"常指**天分高** ⇒ 归第 1 种。

## 二、面板怎么算（等级 60 是默认档）

```
其他(L) = round( (round((种族值 + 3×个体值) × (L + 50) / 100) + 10) × 性格 ) + 50
生命(L) = round( (round((种族值 + 3×个体值) × (L + 25) / 50 ) + 70) × 性格 ) + 100
```

- **等级上限 60**（官方公众号逐字）；`LEVEL_FORMULA.default_level = 60`，超过 60 级**不给面板**并说明原因。
- **个体值按 UI 的 0–10 直接代入**（公式里的 `3×` 就是"内部 ×6"那一套的单位换算，不是额外加成）。
- **取整顺序敏感**：先 round 内层 → 加常数 → 乘性格 → round → 加末尾常数。
  判例：噼啪鸟（速度种族值 145、满突破开朗）必须 **294**，换个顺序是 293。
- **L=60 退化成社区那两行 PVP 公式**（`(60+50)/100 = 1.1`、`(60+25)/50 = 1.7`）—— "1.1 是 60 级的指纹"。
- **自证**：拿我们自己的抓包六维复算 wiki「PVP 一速榜」公布的 9 个速度值，**9/9 全中**。

## 三、性格的突破阶梯（人类 2026-09-27 的裁定）

| 档 | 长处 | 短处 |
|---|---|---|
| 零突破（**缺省**） | **+10%** | −10% |
| 每次突破（20/30/40/50/60 级，共 5 次） | 再 +2% | 不变 |
| 满突破 | **+20%** | −10% |

- 人类原话：「一个加 10%，一个减 10%，可不变化幅度就是 20%？」⇒ **20% 是幅度**（−10% 到 +10% 的跨度），
  不是"长处 +20%"。这也是"PVP 归一化档 = 满突破"的由来（那个档取 1.2）。
- **2026-09-28 复核（主源逐字，人类要求"再查一下"）**：小破站 WIKI 的
  [`Module:NatureDex`](https://wiki.biligame.com/rocom/Module:NatureDex?action=raw) 里写着它的生成方式与口径 ——
  数值取自游戏 UI 反编译 `UMG_PetCharacter_PopUp_C.lua:103-104`：
  `负面 = −negative_effect_proportion//100 %`（固定）、
  `正面 = (positive_effect_proportion + positive_effect_grow×(突破阶段−1))//100 %`，
  突破阶段由 `BREAK_NUMBER_CONF`（5 行，**20/30/40/50/60 级**）算出、**取值 1~6**。
  该模块逐字：「当前 30 种玩家性格数值完全一致：**负面 −10%，正面 +10% 起每次突破 +2%、满突破 +20%**」。
  ⇒ **默认（零突破＝阶段 1）就是 +10% / −10%**；我们代码里 `natureFactor` 的缺省、面板问句、
  性格建议**全部走这一档**，`+20%` 只出现在显式标注的 PVP 归一化档（`pvpPanelOf`）。
- 同一条来源里另外三条我们**还没用上**的事实（记在这里，别丢）：
  ① **30 种性格两两组合穷举、数值幅度完全相同** ⇒「挑性格只看加减的是哪两项属性」；
  ② 道具**「残缺魔镜」可以修正性格带来的负面影响**（我们还没有这件道具的任何数据）；
  ③ **部分精灵蛋与「命定花种」给出固定性格的个体**（不是随机）—— 我们现在的个体性格全是掷点，
     没有"固定性格来源"这一层。
- **我们没有"每只突破到第几段"这个数据** ⇒ 缺省一律按**零突破下界**算，并在 `unknown` 里说明；
  PVP 归一化那一档由 `pvpPanelOf()` 显式取满突破。

## 四、明确**不做**的四层（人类拍板，逐个记原因）

| 不做的层 | 为什么 |
|---|---|
| **学习力 / 努力值** | 人类：「学习力不知道是啥但是应该做……就够吧？」⇒ 不建。查证：这个游戏里没有"学习力"这个系统，对应物是努力值/成长等级，且 PVP 把它归一化成**常数**（公式末尾那个 `+50`） |
| **星级 / 突破** | 人类拍板不建。查证：星级与突破是**同一根 0→5 轴**，它**不加种族值**，只抬资质数值、天分上限、等级上限，并提高性格的增益幅度（减益固定） |
| **隐藏个体值** | 无来源（只有攻略提到存在，没有可核对的数值口径）⇒ 不建 |
| **觉醒** | 另一条独立的 0–5 轴（60 级 + 5 星解锁）⇒ 不在四层内 |

## 五、这一层还有哪些空白（不许当成已解决）

1. **每只的真实天分/性格/突破次数都不在抓包里** —— 抓包是**静态图鉴数据**。个体层现在能算，但喂进去的值是示例；
   真要算玩家自己那只，得由页面/存档提供那几项（这是"补精灵信息"之外的另一类数据）。
2. **抓包 `pets.csv` 里的 `sum_race`/`sum_api` 不可信**（521/547 与逐项之和对不上）⇒ 我们**只用六项**，合计现加。
3. **1 级实测面板**没有任何来源（查不到就说查不到）；公式在 L=1 给的是**推算值**，不是实测。
4. **5 只执行域分歧**（铠甲虫/音速犬/声波缇塔/十字蝌蚪/深渊蛙）：图鉴层用抓包值，引擎（模拟基线）用冻结值；
   回答数值读图鉴层，模拟读执行域。逐值登记在 `tests/roco-hke-layer.test.js` ⑥。
