# F03 · 2–3 分钟录屏脚本（可照拍）

> 本脚本**只描述页面真的会做的事**。每一段都标了证据：
> 页面元素与文案来自 `src/client/roco.html` / `src/client/roco.js`（实读），
> 场景顺序来自 `scripts/roco/demo-acceptance.mjs`（实读），
> 「屏幕上会出现什么」的实测数值来自 `reports/roco/demo-acceptance/demo-acceptance.json`（**16 项检查全部 ok，`failed: 0`**）。
>
> 一条重要前提：**这次演示不需要 API key**。演示页只请求 `/api/bootstrap`、`/api/roco/status`、
> `/api/roco/battle/new|advance`、`/api/roco/plan`（`roco.js` 实读，无 `api/coach` 引用），
> 从不调用模型。规则由本机 Python 引擎按 S4 快照结算。

## 0. 怎么跑（开拍前 2 分钟）

```bash
# 在仓库根目录
npm start                      # 起本机 Node 服务，默认端口 8765
```

浏览器打开：

```text
http://127.0.0.1:8765/roco.html
```

- 页面 URL 是 `/roco.html`（`src/server/index.js:240` 的 `PAGE_ALIASES` 把 `roco.html` 映射到 `src/client/roco.html`）。
- **不需要** `DEEPSEEK_API_KEY`，也不要去 `/connect.html`。
- 右上角状态标签开局应显示「规则服务：未启动」或「规则服务：就绪后自动启动」，点「开一局」时才会拉起 Python 子进程
  （`roco-service.js:115-131` 的 `ensure()`；空闲 5 分钟自动回收）。
- 本机需要装好 Python 3 与 Chrome（如果要复跑验收脚本 `npm run roco:demo-acceptance`）。

**拍摄建议**：窗口 1440×1100（验收脚本用的就是这个尺寸），浏览器缩放 100%，关掉书签栏，
录屏范围保留整页——右下角的主动提示条与局末卡片都是**固定在页面角落**的（`roco.html:67,75`）。

**一个坑提前说清**：验收脚本里有一步 `Page.bringToFront` +
`Emulation.setFocusEmulationEnabled`，因为**窗口失焦是硬门控**
（`experience.js:157` 的 `f.window-unfocused`）。真人录屏时只要录制窗口是前台就被满足；
如果你切到别的窗口再切回来，提示条会先消失（`roco.js:398` 的 `blur`）再重新判定（`roco.js:399` 的 `focus`）
—— 这不是 bug，不要剪掉这段「回来后重新判定」。

## 2. 逐段脚本

### 0:00–0:12 · 开场

- **点什么**：什么都不点，停在刚打开的页面上。
- **屏幕上应该出现**：标题「小芽 · 手游规则演示 `roco-world-s4-2026-09-10`」；
  右上角三个控件「规则服务：未启动」「**开一局**」「重开」；
  中间「未开局」；两侧面板「你的队伍」「训练对手」；
  下方四块：「这一回合的行动」「本回合发生了什么」「对局记录」「这次演示覆盖了什么」。
  「这次演示覆盖了什么」里列着六条场景与它们的 `data-roco-*` 判据。
- **说一句**：「这一页没有聊天框 —— 它要证明的是，玩家不打开对话也能得到帮助。」

> 证据：`roco.html:4-9,21,25,36,46,52,61`；`roco.js:361-372`（`COVERAGE` 六条）。

### 0:12–0:25 · ①（F01-a）无聊天入口

- **点什么**：把鼠标在页面上扫一圈（或轻微滚动），让观众看到没有输入框；
  然后指向唯一的那个输入框。
- **屏幕上应该出现**：页面上**只有**一个输入框：`想说点什么（例如「好烦，又输了」）` + 按钮「说一句」。
  它在「对局记录」面板里，属于陪练，不是战术问答。**没有** `#chat-input`，**没有** `#chat-form`，
  页面上 `textarea` 数量为 0。
- **说一句**：「整页只有一个输入框，而且它只处理情绪和偏好 —— 战术建议由左边那条提示主动给。」

> 证据：`roco.html:53-56`；验收脚本的检查「页面没有聊天入口（无 `#chat-input` / `#chat-form` / `textarea`）」，
> 实测 `{"chat":false,"coachApi":false,"textareas":0}`（`demo-acceptance.json`）。

### 0:25–0:58 · ②（F01-b）危险局面主动短提示 + 展开取舍

- **点什么**：
  1. 点「**开一局**」（会调用 `/api/roco/battle/new`，默认阵容 `pet_000225 / pet_000190 / pet_000445`，
     对手策略 `greedy_damage`，对局种子固定为 `20260921`，所以同一串操作必然复现同一局）。
  2. 连点几次「**让双方各走一步（自动演示）**」，把当前精灵打到血线以下
     （验收脚本的判据是 `hp/max_hp ≤ 0.4`，实测用了 2 次自动推进把血量打到 **0.39**）。
  3. 点「**✦ 让小芽看一眼**」（跑 `/api/roco/plan`，`depth:2, beam:4`）。
  4. 点提示条右下角的「**展开取舍**」。
- **屏幕上应该出现**：
  - 页面右下角浮出提示条：标题「**✦ 小芽**」+ 右上角「×」；
  - 正文是一句可执行的建议，实测原文：**「可以优先考虑「龙吼」，注意对方可能换上第3位（最坏尾部 0.41 ~ 0.41）」**；
  - 一行小字「**依据：moderate-risk**」；
  - 展开后出现可核对的数字，实测原文：
    「期望区间：0.77 ~ 0.82（均值 0.80）」
    「搜索：90 个分支 · 深度 2 · 分析种子 11/29/47」
    「对手应对：换上第3位（是启发式建模，不是真人行为）」
    「这是公开信息 + 固定分析种子的结果，真实对局 seed 没有参与；也不声称胜率。」
  - 同时「本回合发生了什么」里逐条列出引擎事件；出现未核验机制时会是
    「**未核验、因此未结算：…**」这样的行。
- **说一句**：「它在血量掉到 39% 时开口，给的是可以立刻点的一手，并且把依据摊开 —— 数字来自公开信息和固定的分析种子，真实对局种子没有参与，也不声称胜率。」

> 证据：`roco.js:234-256`（开局）、`276-284`（自动推进）、`286-304,208-217`（规划 + 展开内容）；
> `roco-service.js:29,40,188-190`（默认阵容 / 默认策略 / 固定种子）；
> 实测文案与数字见 `demo-acceptance.json` 的「展开里有可核对的搜索证据（区间、分支、分析种子）」与
> 「提示不把胜率当结论、也不承诺必胜」两条检查（`detail` 字段）。
>
> ⚠️ 不要念成「最优解」「胜率多少」。页面自己被断言禁止出现
> `\d+%胜` / `胜率:\d` / `最优` / `一定能赢` 这类表述（`demo-acceptance.mjs` 的正则）。

### 0:58–1:15 · ③（F01-c）该沉默的局面

- **点什么**：点提示条右上角的「**×**」（`aria-label` =「本场不再主动提醒」），
  然后点一次「让双方各走一步（自动演示）」或「✦ 让小芽看一眼」触发重新判定。
- **屏幕上应该出现**：提示条**消失**，并且**不再回来**。页面 `body` 上记录的结论变成
  `data-roco-action="silent"`、`data-roco-gate="hint-dismissed"`（结论按**最后一次判定**写，
  包括「判定为沉默」和「被硬门控拦下」）。
- **说一句**：「玩家说不想听，它这一局就不再主动开口 —— 沉默是判定结果，不是忘了说。」

> 证据：`roco.js:380-384`（点 ×）、`149-157`（`hideHint` 会写 `data-roco-action` / `data-roco-gate`）、
> `178-181`（`session.dismissed` 门控）；`experience.js:160`（`hint-dismissed` 是硬门控）；
> 验收检查「点掉后该沉默的局面不再提示」实测 `hidden=true action=silent`。
>
> 补充可选镜头（如果你想展示另一类沉默，不影响六条主线）：把浏览器切到后台再切回，
> 门控分别是 `background` / `window-unfocused`（`experience.js:157,163`），提示会在切回前台后重新判定。

### 1:15–1:40 · ④（F01-d）阵容变化撤销旧建议

- **点什么**：
  1. 在「这一回合的行动」里点一个**换人**按钮（按钮上写「换上第N位」这类标签，实测点的是「换上第2位」）。
  2. 观察提示条：旧的先消失，新的判定结果重新出现。
- **屏幕上应该出现**：
  - 顶部回合/版本推进：状态版本从 `v10` 涨到 `v15`（实测口径），「规则服务：已连接 · 状态版本 N」里的数字变大；
  - 「本回合发生了什么」里出现换人的事件行；
  - 旧提示**不会**继续挂在旧版本上；`body` 上的 `data-roco-hint-version` 跟着变成新版本；
  - 因为阵容变了，本局「玩家已点掉」的记录被重置，所以它**重新获得一次开口机会**。
- **说一句**：「一旦局面推进，上一手算出来的建议就地作废 —— 它绝不会让你看着一句已经不存在局面的建议。」

> 证据：`roco.js:258-274`（`playAction`：换人时 `state.plan = null`、`session.dismissed = false`、
> `refreshHint({reason:'roster-changed'})` 再 `requestPlan`）、`173-177`（陈旧判定先撤下旧提示）、
> `roco-experience.js:110-113`（`rocoHintStale` 是唯一入口）；
> 验收检查「换人后旧建议不再挂在旧版本上」实测 `换上第2位 v10 → v15`。

### 1:40–2:05 · ⑤（F01-e）局末一个教学入口

- **点什么**：连点「让双方各走一步（自动演示）」，直到顶部阶段标签出现「对局结束：…」。
- **屏幕上应该出现**：
  - 「对局记录」面板从「还没打完一局。」变成一句总结，实测原文：
    **「第 16 回合那个决策点值得回看（这一局 16 个回合）。」**（本次实测结果是 `loss`，这一句随真实结果变化）；
  - 页面中部浮出局末卡片，标题「**✦ 局末一个决策点**」，正文是一个问题 + 一行小字，
    实测原文：问题「倒下那一回合，如果先用回复药或先换一只不被克的，后面会不一样吗？」，
    小字「这一局共 N 个回合。只挑这一个决策点，不把整局复盘一遍。」
  - `body` 上的 `data-roco-lesson="shown"`。
- **说一句**：「输了不硬夸、也不硬挑错：它一局只挑一个决策点，因为复盘一整套不如想清一手。」

> 证据：`roco.js:307-324`（`finishMatch`：先 `rememberBattle` 记真实结果，再 `rocoLessonEntry`）、
> `roco-experience.js:142-156`（没有值得拎出来的就返回 `null`，卡片不显示）；
> 验收检查「局末给出一个教学入口」「局末教学入口在页面上真的显示了」均 ok。

### 2:05–2:25 · ⑥（F01-f）玩家抱怨时先回应情绪

- **点什么**：在「对小芽说一句」输入框里打 **`好烦，又输了`**，点「说一句」。
- **屏幕上应该出现**：输入框下方出现一行回复，实测原文：
  **「嗯，这一局确实不顺。要复盘的话我随时在，不想说就先歇会儿。」**
  同时 `body` 上记录：`data-roco-companion="R2"`（档位）、`data-roco-companion-why`（为什么用这一档）、
  `data-roco-companion-seen="yes"`。
- **说一句**：「它先接住情绪，再谈局面 —— 而且这一档的措辞是从真实的跨局记录里选出来的，不是随机套模板。」

> 证据：`roco.js:333-358`（`say()`：`intentOf` → `decideRegister` → `chatReply`，并写三个 dataset）；
> `companion.js:227-254,527-536`（`REGISTERS` 与 `emotion` 意图的档位选择）；
> 验收检查「玩家抱怨时陪练先回应情绪（R2/R3）」实测 `R2: 嗯，这一局确实不顺。…`。
>
> ⚠️ 档位可能是 `R2` 也可能是 `R3`：`R3` 出现在「真实记录里已经连败 ≥2 局」时
> （`companion.js:535`）。如果本机 `localStorage` 里已经有连败记录，你会拍到 `R3` ——
> 那也是正确的，不要重录。想拍到干净的 `R2`，可以先清掉本站 `localStorage` 的
> `roco-coach-memory-v1`（`roco.js:42`）。

### 2:25–2:30 · 收尾

- **点什么**：不需要操作。
- **屏幕上应该出现**：右下角「这次演示覆盖了什么」的六条清单，和刚拍完的六个场景一一对应。
- **说一句**：「这六条都在浏览器验收里跑过：16 项检查、0 失败，还留了 7 张截图。规则来自固定 revision 的社区快照，未核验的机制它一律不猜。」

> 证据：`reports/roco/demo-acceptance/demo-acceptance.json`（`passed: 16, failed: 0`，
> `screenshots` 7 张）；`roco.js:361-372`。

## 3. 可复现性：想重跑一遍同样的镜头

```bash
npm run roco:demo-acceptance
```

它会：进程内起一个**不配密钥**的服务（模型调用一律失败）→ 按需拉起真 Python 规则服务 →
用无头 Chrome 打开 `roco.html` → 通过 `window.rocoDemo` 与 `document.body.dataset.roco*` 读数 →
写出 `reports/roco/demo-acceptance/demo-acceptance.json` 与 7 张 PNG。

**为什么镜头可复现**：对局种子固定为 `DEMO_SEED = 20260921`（`roco-service.js:40`），
引擎是确定性回放的（`env.py:420-427` 的 `_rng_for(state)` 由 `(seed, turn)` 派生）。
所以「同一个 seed + 同一串动作 = 完全一样的一局」不是巧合，是设计。

**但数字不要写死进旁白**：上面的具体数值（血量 0.39、90 个分支、期望区间 0.77~0.82、16 回合）
来自 `demo-acceptance.json` 记录的那一次运行。动作序列一变，这些数就会变 —— 脚本里要念的是
**结构与口径**（「依据」「公开信息 + 固定分析种子」「不声称胜率」），不是那几个数字。
