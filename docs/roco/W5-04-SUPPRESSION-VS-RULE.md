# W5-04 预注册：判定层到底有没有在真实链路上生效（第 39 轮）

**这份文件在动手之前写。** 判据先钉死，免得看到结果之后才决定什么算「生效」。

## 0. 起因：又一次「接上了但不生效」

第 21 与第 30 轮各修过一次同一形状的问题（特征只读调用方字段、命名不一致）。
第 39 轮用**真实 bridge 产物**量了一次，发现它**又一次**没生效，只是这次断在更靠后的一环。

真实 bridge（`/api/roco/plan`）返回：

```json
"first_second_margin": {"min": 0.1774, "max": 0.1774, "mean": 0.1774,
                        "scale": "one-ply-value", "note": "…"}
```

而 `rocoPlanFeatures` 读的是：

```js
const rawMargin = Number.isFinite(plan.firstSecondMargin) ? plan.firstSecondMargin
  : (Number.isFinite(plan.first_second_margin) ? plan.first_second_margin : null);
```

`Number.isFinite({...})` 是 **false** → `margin = null` → 判定层走 sigmoid 兜底口径。
实测（一次性的临时探针，未改仓库；同一条链现在由 `tests/evals/roco/intervention-margin-chain.test.js` 走真实路由钉住）：`decided_by: "sigmod-threshold"`、`margin: null`、
`threshold: 0.88`、`probability: 0.9498` → **永远 `suppress: false`**。
也就是说：页面上这一层从来没生效过，而第 30 轮那条「端到端守卫」是绿的，
因为**它自己捏了一个标量** `first_second_margin: mean` —— 服务端从来不这么发。

**这是同一个坑的第三次复现，而且这次是被「本该抓住它的那条测试」盖住的。**

## 2. 「抑制 ≠ 规则犯错」怎么量（本轮要回答的那个开放问题）

`docs/roco/W5-04-INTERVENTION-GATE.md` §12.4 写的是「两个量同源但不同义，一致性没有被验证过」。
本轮把它变成可算的东西：

- **规则用的量**：`gap = expected.max - expected.min`（三个分析种子之间期望值的**离散度**）
  与 `risk`（由血量档位给出）。判定面是
  `decisive = (gap > 5) || risk >= 0.8`、`speaks = decisive || 3*risk >= 1.2`。
- **判定层用的量**：`first_second_margin.mean`（枚举第一与第二的估值差）。

要报的 2×2（在**真实引擎**产生的窗口上）：

| | 层抑制 | 层放行 |
|---|---|---|
| 规则要开口 | **分歧格**（层压掉了规则要说的） | 一致（都说） |
| 规则沉默 | 一致（都不说） | 层放行但规则本来也不说（结果仍是 silent） |

外加两个**必须一起报**的数：

1. `gap > 5` 在手游引擎上到底出现过几次。若为 0，则规则的 `decisive-gap` 分支
   在这条链上是**死代码**，「规则用分差判断」这句话在手游侧不成立——
   那么 §12.4 说的「两个量同源不同义」其实还要更强：**规则侧根本没有分差可用**。
2. 层的抑制与规则的开口**具体在哪几类局面上分歧**（按 `phase` / 血量档 / 回合带）。

**不声称**：分歧格的「谁对」需要局外仲裁（更深搜索或真人），本轮只负责把分歧量出来，
不据此改写规则阈值。

## 4. 结果（跑完之后追加，判据一个字没改）

npm run roco:intervention-agreement -- --seeds 24 --turns 10
# → reports/roco/intervention-agreement.json（240 个窗口，192 个进评分）

### 4.1 先确认那条链真的通了（S1 / S2）

| 项 | 修前 | 修后 |
|---|---|---|
| `rocoPlanFeatures(真实 plan).margin` | **null** | **有限数**（= `first_second_margin.mean`） |
| 判定层 `decided_by` | `sigmod-threshold`（概率恒 ~0.95 → **永远放行**） | **`margin-quantile`**（192/192） |
| 判定层 `margin` | null | 有值；`margin_threshold = 0.146532` |

端到端守卫已改成走**真实路由**（`/api/roco/plan`），不再自己捏 payload（S3）。

### 4.2 问题② 的答案：规则的 `decisive-gap` 分支在这条链上是**死代码**

| 量 | 结果 |
|---|---|
| `gap = expected.max - expected.min` | **192/192 个窗口全为 0**（`all_zero: true`） |
| `gap > 5` 出现次数 | **0** |
| `decisive` 来源 | `by_gap` **0** ／ `by_risk` 20 ／ 合计 20 |
| 直接量引擎（3 个分析种子 × 11 个局面） | `expected` 与 `first_second_margin` **逐位相同** |

原因在服务端：跨种子聚合（`service.py` 的 `for sv in raw_seeds`）虽然重建了状态，
但 `plan_actions` 在重建出来的状态上是**确定性**的，所以三个种子给出同一个 `expected`
→ 区间宽度恒为 0。于是：

- `decisive = (gap > 5) || risk >= 0.8` **只剩右边那一项**；
- `value = 3*risk + 1.2*min(gap/5, 1)` 的第二项**恒为 0**；
- 规则在手游侧**只按血量档位说话**：`speaks ⟺ risk >= 0.4 ⟺ hp_ratio <= 0.6`。

这一条同时意味着：`docs/roco/W5-04-INTERVENTION-GATE.md` §12.4 说的「两个量同源但不同义」
**还说轻了**——不是同一个源的两种口径，而是**规则侧根本没有这个量**。

顺带修掉一个面向玩家的小失真：页面上原来写「期望区间：0.58 ~ 0.58（均值 0.58）」，
把一个点估计写成区间。现在按真实形状说话（`expectedLine`），并且有测试钉住。

### 4.3 问题① 的答案：「抑制 = 规则犯错」这句话在这条链上没有内容

2×2（192 个评分窗口）：

| | 层抑制 | 层放行 |
|---|---|---|
| **规则要开口**（78） | **54（69%）** | 24 |
| **规则沉默**（114） | 52 | 62 |

- **分歧格 54 条的 `margin` 中位数 = 0.0363**（阈值 0.1465）——层抑制的正是
  「枚举第一与第二几乎打平」的窗口；
- **一致格 24 条的 `margin` 中位数 = 0.8953**——两边都说的窗口，边际量非常清楚。
- 按血量档看分歧：`0.35—0.6` 档 44 条、`≤0.35` 档 10 条；`>0.6` 档 0 条
  （那一档规则本来就不说话）。

**所以「抑制」的准确含义是**：规则**仅凭血量**判定「该提醒」时，判定层会追问一句
「规划器分得开这两手吗」；分不开（边际量小）就不给具体推荐。
它不是「规则算错了」——规则按自己的定义并没有算错；而是**两类证据在争谁说了算**。

### 4.4 一局之内：提示**条数不变**，但换成了**另外几条**

每局用连续的 session（频率预算 2 条/局 + 45 秒冷却都生效）：

| 口径 | 规则开口窗口 | 判定层开口窗口 |
|---|---|---|
| 每窗口独立 session | 78 | 24 |
| **同一局内连续推进** | **24** | **24** |

条数一样，但**两个集合完全不相交**（`规则开口而层不说 = 24`，`层说而规则不说 = 24`）：
层把预算从「最早那几个只按血量触发的窗口」挪到了「边际量分得开的窗口」。

**这条必须一起报**：只看「条数不变」会以为这一层没有效果；
只看「69% 被抑制」又会以为它把提示砍掉了七成。真实效果是**换了位置**。
