## 今天的三条「可优化的地方」（已做成可复现证据）

1. **规则真源不一致（最高优先级）**：官方采访里「电系打翠顶夫人（翼+水）= 三倍」，但本仓引擎与 RAG 语料按 2026-09-25 社区口径算 **4×**，客户端却按游戏数据算 **3×**。
   - 复现：`node scripts/interview/replay-scarlett-bad-cases.mjs`
   - 修复提案：分支 `fix/typechart-official-3x` @ `81ec0d45`，patch 在 [patches/typechart-official-3x.patch](docs/interview/patches/typechart-official-3x.patch)
   - 状态：行为已验证 3×；旧裁决判据/金标需按「改钉+留痕+金标送审」流程改，**未合入**。
2. **灼烧免疫只对了一半**：术语 1002 写「火系精灵免疫灼烧」，`effects.py` 也声明了 `immune_element=火系`，但只有天气路径消费它；技能施加灼烧不判免疫 ⇒ 官方 Bad Case 2 在本仓会算成「可以烧」。
3. **grounded 守卫的语义盲区**：`checkGroundedAnswer` 能拦「999 伤害」这类不存在数字，但放行「2 倍/两倍/强力克制」——因为 2/3 是规则常量、中文数字量词表没有「倍」、等级词没有数字。官方 Bad Case 恰好是「有依据但事实错」，落在盲区里。今天实测命令与输出见 Bad-Case 文档 §2.5。
