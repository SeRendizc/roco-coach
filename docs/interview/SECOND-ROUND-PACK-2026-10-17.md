### A1 规则引擎与 LLM 的分工：引擎决定事实，模型只决定措辞

**一句话**：合法行动、伤害、顺序、状态计时全部在 Python 引擎算；模型只做三件事——接自然语言、
按需查证、把算好的事实说成人话。

**30 秒展开**：拿六宠页的「这回合我该换谁？」举例：政策判定必须模拟分支，代码直接发
`simulate_branch`，工具拿 `battle_id` 去服务端会话请 Python 引擎算，回执（推荐/最坏/分支数）进包，
模型只基于回执说话。它一次都不算伤害。
⚠ **反例要说清**：像“我只能回血吗”这类问句，事实本来就在 `publicState` 里，实测是 **0 次工具调用**
（`agentStop:'policy-no-tool'`）——别拿它当工具链例子（旧面试文档写错了，见 §10 过期值 #5）。
不用模型行不行？能覆盖一部分，但接不住“我不想老换宠”“咋办”这种自由表述；所以分工不是“模型更强”，
是“模型更会理解语言，引擎更会算数”。

**代码证据**：
- 模型只拿证据包：`src/coach/runtime.js:2721` `provider.generate(modelPacket(...))`；
- 工具合同 12 个：`src/coach/toolbox.js:144`（`read_state` / `search_rules` / `compare_actions` /
  `simulate_branch` / `read_match` / `read_evidence` / `read_last_turn` / `query_rules` /
  `evaluate_team` / `compare_team_change` / `plan_actions` / `summarize_battle`）；
- 军师的方法自述：`src/coach/strategist.js:125`“合法行动枚举 → 共用结算器 → 平均收益与最坏情况比较”；
- 引擎规划：`roco/src/roco_env/planner.py:850` `plan_actions()`，`immediate_greedy` 在 `:1283`；
- **政策先行（policy-first）的实测**：同一批 288 个窗口、同一个本地 4B，只把“第一步要不要调工具”
  从模型手里挪到代码手里：**两轮 286–288/288、0 条由通过转失败**（单臂 local_4b、逐窗口配对、方差大；旧文档 232/288→288/288 只在旧模型臂产物复现）
  `[N7]`（`docs/roco/AGENT-POLICY-FIRST.md` §2.1，产物在 `reports/roco/agent-policy-first/`）。

**最可能的追问**：
- “那模型是不是可有可无？”→ 不是。policy-first 只接管**第一步**，后面还是模型看回执决定；且它测的是
  “确定性窗口上的通过率”，不是“开放式对话质量”。模型的价值在理解目标、处理没见过的问法、组织解释。
- “你凭什么说规则比模型准？”→ 不说“规则更聪明”，说“规则可复现、可审计、错了能定位”；模型负责
  规则不擅长的那一半。

**说错就扣分**：不要说“模型能做决策/算伤害”“有了 LLM 建议质量就好了”；也不要说“引擎一定对/规则真值一定没问题”
——双属性倍率有一条已知的三层口径不一致（见 §4 F6），要主动承认。

### A2 有界工具循环：首步政策、模型最多再规划 2 次、回执上限 3、停止原因是冻结取值域

**一句话**：`gatherAgentEvidenceOnce` 是一个有界循环：政策决定第一枪，模型看回执决定下一步或停；
最多 3 张回执；所有停止原因都在 `AGENT_STOPS` 里，写错一个字测试会红。

**30 秒展开**：一次干净的工具轨迹是：`policy` 发第一枪 → 回执进 `trace` → `planner` 收到 receipts
和 `remaining` → 选第二个工具或 `stop:true` → 到上限停。循环还有**一次全局纠错券**：模型工具名写错/
参数不合法/重复调用时，把失败做成一条错误回执让它重试一次，但步数、去重、政策首枪都不放松。
为什么要有界：外部证据和自家实测都指向“小模型上多步是负收益”，而且玩家在局内等不起。
**今天实测的一条真实轨迹**（只读探针，`CODE-TRACE-2026-10-17.md` §5.2）：`simulate_branch`（政策首枪，
`chosenBy:'policy'`）→ `read_state`（模型看回执后自己决定再查）→ 停；trace=2、`stopped=complete`、
`remaining` 2→1。

**代码证据**：
- 主循环：`runtime.js:4460` `gatherAgentEvidenceOnce`；首枪 `:4489-4504`；循环 `:4505`
  `for(let i=trace.length;i<Math.min(4,limit);i++)`；`limit=3` 是默认值（`:4460`）；
- 停止原因：`runtime.js:2933-2961` `AGENT_STOPS`，当前 **22 种**（`[N3]`，可 `node` 复算）；
  分组是 `policy-*`（代码门控）/ `planner-*`（规划器失败）/ 循环边界（`invalid-*`、`repeated-tool`、
  `*-budget`）/ `complete`；
- 单一事实源判据：`tests/roco-agent-stops.test.js:36`（源码里出现的每个值都在域里）、`:48`（不许有死值）、
  `:55`（命名成组、无重复）；
- 确定性两步轨迹：`tests/evals/tool-arguments.test.js:403`。

**诚实边界（一定要主动说）**：真实模型评测里**没有观察到多步工具链**。44 条既有真实记录加补跑 4 条，
`toolTrace` 长度最大是 1 `[N6]`（`reports/react-evidence-check.json`）。多步能力由**确定性 planner
测试**保证，不是由真实模型样本证明。

**最可能的追问**：
- “最多几步？为什么是 3？”→ 生产口径是**最多 3 张回执**（`runCoach` 不传 limit，取默认 `limit=3`）；
  `Math.min(4,limit)` 里的 4 只是函数字面上限，生产取不到（旧文档说“4 轮”不准确，见 §10 过期值 #3）。

- “模型就是不会多步，那你的循环不是摆设吗？”→ 是“能力在代码里、证据在确定性测试里”；我承认真实
  模型没走过多步，也不拿单工具记录冒充多步 ReAct。

### A4 过期建议三层失效：版本 / 交付前再验 / 服务端取消

**一句话**：旧建议作废不是靠 prompt 提醒，是靠三层代码：每次局面变化提升 epoch 并 abort 在途请求；

`AbortError`。页面 `ask()` 再用 `stateToken` 与 `taskIsCurrent()` 验一遍对局 ID、规则版本、TTL；
自动提示另外用 `hintEpoch`。最后，浏览器断开时服务端中止上游请求，避免“用户走了还在花钱算”。

**代码证据**：

### A9 教学闭环：学习结论是“可修正假设”，只算无提示的独立行动

合理率 ≥75%，才说“出现迁移迹象，仍需观察”；一次答对不算掌握。

**30 秒展开**：每一条学习判断都带 `causalClaim:false`。练习掌握要求 ≥3 次独立答对且落在 ≥2 个不同变式
（`QUIZ_MASTERY`），出题会避开做过的变式。反向也通：同一课连续出现独立失误，会把“已掌握”标回
“未掌握”，老师才有机会再讲一次；删除一条行为证据会级联让引用它的推断失效。这样“学习”是可证伪的。

**代码证据**：
- `src/coach/memory.js:230` `transferAssessment`（`recent` 最多 8 条、`recent.length>=3 &&
  cases.size>=2 && matches.size>=2 && reasonable/recent.length>=.75`）；`:126` `adaptiveGate`；
  `:472` `QUIZ_MASTERY={minIndependent:3,minVariants:2}`、`:476` `quizMastery`；`:236` `coachSelfAudit`；
- 出题：`src/coach/teacher.js:81` `makeQuiz`（变式 id 进 id）、`:113`（参数化题干）、
  `:455` `practiceQuestion`；
- 测试：`tests/roco-teaching-loop.test.js:27`（避开做过的变式）、`tests/roco-memory-three-classes.test.js`。

**诚实边界**：没有真人迁移数据（`T04` 无提示迁移、`R09` 真人试玩都未完成）；不拿采纳率、
赢了 一局、答对一道题当学习指标。

## 4. 五个失败故事（每个都按“我原来以为 / 实测 / 根因 / 改法”讲）

> 面试官最认这个：能主动交代失败，比只报喜强。每个都可以现场打开证据。
> 注意：有几条是**上一轮的我踩的、接手时抓到的**——照实说，不揽功也不甩锅。

### F1 检索没赢：我以为加反例/语义会更好，实测没有

- **我原来以为**：把反例字段提权重、加语义检索，Hit@3 会明显超过关键词基线。
- **实测**：128 条四臂，关键词 88.39%、混合 90.18%、反例 91.07%，最好的臂相对基线 +2.68pp，
  McNemar p=0.4531、CI 含 0 `[N8]`；真正的洞是负例拒答只有 56.25%（7 条越界提问仍召回卡片）。
  语义轮更差：纯语义 9/14 < 词项 11/14 `[N9]`。
- **根因**：① 查询集是我自己写的，写题时已经知道卡片用词，绝对值偏乐观；② 词项检索没有最低分/
  弃答阈值，只要命中任意二元组就 `score>0`；③ 把 principle 和 counterexample 拼成一个字段、权重都为 1，
  反例信息被稀释。
- **改法**：保留关键词为默认，公开失败结论；下一轮要独立盲标集 + 弃答阈值，而不是继续在同一批自写
  查询上调权重。证据：`reports/retrieval-extended-summary.md`、`reports/semantic-summary.txt`。
- **今天实测的边界（主动说）**：四臂数字是 2026-09-17 的归档产物；今天复跑脚本会直接抛
  `未知检索策略 hybrid`（`hybrid` 策略已退役，`src/coach/strategist.js:160`）——所以是“归档可对账、
  今天不可复跑”（`EVIDENCE-LEDGER.md` D1）。

### F2 规划器“默认停止”的权衡：我以为改提示词只有好处

- **我原来以为**：让规划器默认停止、把调用当例外，会同时降低多余调用和提升质量。
- **实测**（44 条同一预注册用例、每条一次真实 `POST /api/coach`）：多余工具调用率
  **75.00% → 33.33%**、自停率 **3.23% → 96.77%**、严格正确率 **31.25% → 50.00%**，
  但漏调从 **0/19 → 7/19**；首选工具（在允许集合内）**90.63% → 78.13%** 变差 `[N10]`
  （`reports/live-model-eval-before-after.md` §2）。
- **根因**：把“该不该调”交给模型本来就测不准（同一份报告里“该不该调”正确率 71.88%→65.63%）；
  提示词改成默认停止后，模型把“明确要求模拟/计算”的问句也停了。
- **改法**：承认这是权衡不是纯改善；补“三类必须调用”的硬需求指令；在运行时加政策首枪
  （`policy.need`，`runtime.js:2680-2682`）把模型测不准的那一半拿走。证据：`reports/planner-tuning-log.md`、
  `docs/roco/AGENT-POLICY-FIRST.md`。
- **今天实测的边界**：这组数字是 **2026-09-25 单次运行、44 条**；今天是**离线重算归档 raw**
  （`_analysis-before.json` / `_analysis-pass2.json`，0 次模型调用）复现同值，不是重发真实请求
  （`EVIDENCE-LEDGER.md` C5-C8）。现场说“报告里记的是…，今天离线重算对上了”。

### F3 语音功能验证失败并停用：不是“改个名字算完成”

- **我原来以为**：浏览器 `speechSynthesis` 指定 zh-CN 声音就能稳定播普通话。
- **实测**：首次播报正常，之后一律播成粤语并在结尾爆音；触发点是 `speechSynthesis.cancel()`，无法恢复。
- **根因**：`getVoices()` 首次常返回空数组，`startsWith('zh')` 会命中 zh-HK/zh-TW；取消后 voice 选择
  漂移。没有可靠修复路径。
- **改法**：整体停用（`VOICE_FEATURE=false`），隐藏语音控件，只留一行“语音已暂停使用”，保留代码和
  设置项，把失败原因写进注释与文档；不说“做完了”。证据：`src/client/app.js:1224-1236`；
  旧提纲 `docs/INTERVIEW-DRILL.md:177`。

### F4 测试的“假绿”与并行验收互相干扰：两次都不是业务 bug，是验证方式 bug

- **我原来以为**：测试通过 = 守卫真的在工作；两套验收并行跑能省时间。
- **实测一**：守卫自检从 `node --test` 里再起 `node --test`，子进程继承 `NODE_TEST_CONTEXT=child-v8`，
  不按参数跑测试文件、永远 exit 0 ⇒ **7 条注入全部报“仍绿”**，看起来像守卫全失效。
- **实测二**：`guard-selftest` 与全量判据并行跑 ⇒ 1710/1711 假红一条（“找不到注入点”），因为
  `guard-selftest` 的工作方式是**逐条改写源码、跑子测试、再恢复**，两个进程读到对方注入一半的文件。
- **根因**：验证手段本身有共享可变状态/环境泄漏；契约原文早就写了“不能和并行单测放一起”，我没先读。
- **改法**：子进程前清 `NODE_TEST_CONTEXT` / `NODE_TEST_WORKER_ID`（`scripts/roco/guard-selftest.mjs:214-217`），
  另加静态判据要求所有起 `node --test` 的地方都清理（`tests/evals/subprocess-env.test.js`）；
  把“这两类验收不许并行”写进套件说明（`scripts/roco/verify-release.mjs:107-110`）。
  现状：登记 **15 条注入，红 15**（`[N2]`；今天原始台账 `checked:15, ok:15`，`INJECTIONS.length===15` 已核）。
- **面试价值**：**“测试通过”和“测试真的在跑”在 CI 里长得一模一样。**
  注意：今天**单独串行**复跑 `test:unit` 仍是 **tests 2084 / pass 2068 / fail 15 / skipped 1** `[N1]`，
  15 条 = **14 条公开树自带 + 1 条本机环境红**（未跟踪 `pnpm-lock.yaml` 触发结构契约），**不是并发假红**
  （`EVIDENCE-LEDGER.md` A7）。所以“单独重跑就全绿”这句话不能再讲；报数前先说明工作树状态。

### F5 云端回退与来源标注：HTTP 成功 ≠ 模型答对 ≠ 页面正确

- **我原来以为**：模型调用成功、返回了正文，就等于这条回答可用。
- **实测**：provider HTTP 失败时，回答能继续（本地回退），但必须保留玩家原话、如实标
  `provider:'local-fallback'`、不能声称“本局规则/等模型太久/正在重连”；取消中的请求必须是
  `AbortError`，不能变成一条回退回答。三个事实分开：模型调用成功、模型正文正确、最终页面正确。
- **根因**：回退路径最容易把“本地兜底”写成“模型分析”，也最容易把用户原话丢掉。
- **改法**：`src/coach/client.js:54` 再判一次守卫；`runtime.js:2918-2919` 写清来源与原因；
  传输层测试逐条钉住：`tests/roco-quality-transport-20261006.test.js:12`（HTTP 失败 → 诚实回退）、
  `:32`（`provider==='local-fallback'`、`execution==='local-fallback'`）、`:35`（保留原话）、
  `:36`（回退状态不许声称时长/本局规则）、`:43`（取消仍是 AbortError）。
- **正面证据（今天对账过）**：2026-10-06 三个真实云端样本 3/3 HTTP 200、`rawModelText===deliveredText`、
  交付文字逐字出现在 UI、`provider=deepseek`、`fallback=0` `[N20]`。引用时标明“2026-10-06 归档对账，
  今天只对账不重发付费请求”。
- **补充（仓库外记录）**：2026-10-16 独立玩家验收里出现过一次更难的失败：服务端返回 HTTP 200 响应头，
  但正文在约 8 秒生产截止内没有完整返回，本地取消后页面回退；回退只给了生命和能量事实，没有首选/
  理由/风险，所以**用户任务仍失败** `[N18·待核]`。讲法：区分“服务返回/页面有内容/用户任务完成”，
  下一步要核对请求路由、工具证据与调用截止，而不是单纯延长超时。

## 5. 十五个高频 Q&A

> 每题给“30–60 秒能说出口的骨架 + 追问怎么接”。**不要背整段**，记骨架。

**Q1 为什么还需要 LLM？引擎不是算得准吗？**
引擎负责计算，模型负责理解与表达：接住“我不想老换宠”“咋办”这类自由表述、按需查证、把算好的事实
组织成人话。关键论据是替代品对比：不用模型就得写死所有说法，玩家换个问法就答不上；用了模型又不
能让它碰数值。所以分工是“程序决定事实，模型只决定措辞”。证据：`runtime.js:2721`（模型只拿证据包）、
`src/coach/strategist.js:125`。
追问“那模型是不是可有可无”→ 不是；policy-first 只接管第一步，后面仍靠模型看回执决定（A1）。

**Q2 哪里真的是 Agent，哪里只是流水线？**
真的是 Agent 的只有一处：`gatherAgentEvidenceOnce`——模型先给规划（工具+参数），代码执行、回执给它，
它再决定下一步或停。其余角色（strategist/teacher/companion）是规则模板 + 可选模型措辞，没有工具循环，
我不用“Agent”这个词包装它们。也不能说“线上跑过多步 ReAct”：真实模型 44 条记录里工具轨迹最大长度 1
`[N6]`；多步由确定性测试证明（`tests/evals/tool-arguments.test.js:403`）。政策首枪把“该不该调”从模型
手里拿走（两轮 286–288/288、0 条由通转败 `[N7]`），这是工程判断，不是模型能力。

**Q3 RAG 为什么有效，为什么在你这儿没赢？**
RAG 在这里的价值不是“更准”，是“证据可核查”：带 id、带来源、带适用条件与反例、版本可回查；
实时伤害另算，不拿经验句当数值证据。没赢是实测：四臂里最好只 +2.68pp 不显著，负例拒答 56.25%，
语义轮 9/14 < 11/14 `[N8][N9]`。**边界**：这是 2026-09-17 归档产物，今天脚本会抛
`未知检索策略 hybrid`，所以我说“归档可对账、今天不可复跑”，不说“随时可复现”。
作者自写查询集会高估，这点报告自己写了。下一步独立盲标 + 弃答阈值。

**Q4 RL 更新了什么？**
两条小而窄的实验，各有边界：① 干预策略的表格 Q-learning（何时开口），**模拟**对照：
规则策略 5.89 次/局 → Q-learning 在 **selectedSeed=71** 下 1.70 次/局（**三种子范围 1.70–2.32**），
但增量帮助 1.38→0.86（三种子 0.86–1.16），是注意力权衡 `[N12]`；② SmolLM2-135M 冻结骨干、
只训练两输出行（1152 参数）、REINFORCE，16 条留出题 **8/16→15/16**（三种子一致）`[N14]`。
**不是**训练 DeepSeek、不是训练敌方 AI、不是完整多步 Agentic RL（无 CUDA 后端 / cloud budget 未给）。
模拟收益不等于真人收益；干预数字引用必须带“模拟 + 种子 71”。

**Q5 怎么防过期建议？**
三层：① 每次局面变化 `invalidate()`：epoch+1、abort、清 pending/cache（`scheduler.js:4`），
任务发出前/返回后各查一次 epoch；② 交付前用 `stateToken` + `taskIsCurrent()` 再验对局 ID、
规则版本、TTL（`app.js:919`）；③ 客户端断连时服务端中止上游（`server/index.js:993`）。
语音/字幕也随状态取消，不排队播旧的。测试在 `tests/evals/slow-model.test.js`。
追问“浏览器禁用按钮够吗”→ 不够：取消传输和校验结果身份解决的是不同问题。

**Q6 怎么证明玩家进步了？**
现在证明不了。能测的是“区分提示下做对与无提示独立做对”：至少 3 次独立行动、跨 2 个局面/2 局、
