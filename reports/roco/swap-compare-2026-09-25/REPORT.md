# 换人对比：从「凭印象给建议」到**引擎对比 + 说清边界**（2026-09-25）

> 由来：上一轮报告里登记的缺口 —— 288 条任务集 `roster_constraint` 里 **12 条**
> 「第三只换成圆号鱼好不好？」**一次都没调** `compare_team_change`（提示里写明了也没咬住）。
> 产品路径上更没有这一类政策（`policyFor` 里没有它），玩家问「换谁更好」拿到的是**没有引擎计算**的意见。
> 本文件只写实测，包括**我自己一次被探针纠正的错误判断**。

## 1. 先做的三件事（都照既有架构：该不该查由代码判、怎么查由模型）

**① 政策**：`swapAsk`/`swapTarget` + `policyFor` 新增 `swap-compare`（`ROCO_SWAP_COMPARE` 默认开）。
认「(把|将)?第 N 只(换|替|改)(成|为|掉) X」；参数从页面名单现算（现在这队 + 换掉第 N 只）；
**对局上下文里不抢**（对局里"换"是把场上那只换下去，走战斗工具）。

**② 参数**：`team_before` = 页面那队，`team_after` = 换掉第 N 只（换入的 id 按**唯一名字**从名单里取，
重名/找不到/已经在队里/序号越界/没说序号 ⇒ **一律 fail closed**，不猜）。

**③ 本地校验收紧**：`compare_team_change` 原来**只查数量**、不查「只差一只」，于是一个注定 400 的请求
（差两只）会一路发到引擎。现在本地**先判掉**（等长 + 恰好差一只 + 各 3 只）。

## 2. 一次被探针当场纠正的错误判断（必须记）

我读 `service.py` 看到「`team_before` 与 `team_after` 长度必须相同（只做等量换人比较）」+「两支队伍应当
只差一只」，就判断本地那道「3 只」的校验过严，把它放宽到 2..6，好让**产品的六槽阵容**也能用。
产品路径探针立刻打回原形 —— 引擎回执是 `bad_request`：

```
"训练场评估按 3 只队伍进行；完整 6 只阵容在第 5 周扩展"
```

⇒ 真正的能力边界在 `team_mod` 里就是 3 只，**本地那道 3 只校验原本是对的**（它在出门前 fail closed）。
**已撤回放宽**，并把这次实测写进代码注释与判据（`tests/roco-swap-compare.test.js` ②）。
**教训**：读长度校验 ≠ 读能力；「先测量再改」要测到**端到端**，不能停在中间一层的代码。

## 3. 改后的产品路径实测（真服务 + 真模型，两套阵容各问一遍）

| 阵容 | 引擎 | 回答 | 依据行 | 工具回执 |
|---|---|---|---|---|
| **六只**（产品常见） | 不支持 | 「圆号鱼不错，但**六只阵容的换人对比引擎还没支持**，我没法拿数据替你判断。」 | 依据：你选的六只 · 你的名单 | `missing:true`（**不进引擎**） |
| **三只**（评测/训练场口径） | 支持 | 「圆号换上也行。」 | **依据：比了换人前后** · 你选的六只 · 你的名单 | `ok:true`，参数正确 |

六只那一行的重点在**依据行没有谎称"比过"** —— 见 §4。

## 4. 自查发现的第二个缺陷：活动行会把"没执行"说成"比过了"

六只阵容下政策仍会写一条「缺参回执」（`{missing:true}`）进 trace，而活动行原本把**工具名一律**翻成玩家话
⇒ 屏幕上会出现「依据：**比了换人前后**」，可实际上**什么都没算**。这比不显示更坏。
已修：`coachActivity` 跳过缺参回执（`result.missing === true`），并加判据
（缺参回执不许产出玩家话；**反证**：真执行过的回执必须照旧出词）。

同一条回执的措辞也分成了两种实话（否则会误导）：
- 阵容不是 3 只 ⇒「换人对比按 3 只队伍计算；你这套是 N 只，引擎暂不支持六只阵容的前后对比
  （引擎原文：完整 6 只阵容在第 5 周扩展）。**请如实说明这个边界，不要凭印象给换人建议。**」
- 阵容正好 3 只 ⇒ 缺的是**问句里的目标**：「要能确定"换掉第几只、换成哪一只"才能对比…」

## 5. 判据（`tests/roco-swap-compare.test.js`，6/6）

① 4 种问法都触发、参数在第 N 位、**参数能过本地校验**；② 合同 = 引擎能力（各 3 只收、**六只必拒**、
差两只/不等长/没换/重复/带路径全拒，说明里要写明六只尚不支持）；③ 六类 fail closed；
④ 对局里不抢（两种战斗上下文的键都测）；⑤ 开关两态；⑥ 边界回执两句话分开（六只引引擎原文、三只指向问句）。
活动行 **+1 条**（缺参回执不算"查过"）。
