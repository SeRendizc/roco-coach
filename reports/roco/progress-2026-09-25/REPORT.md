## 四、要你定口径的四件事（我把纠结在哪讲清，并给推荐）

### 1. `pet_id` / `term_id` 写法要不要**当能力修**？→ **我推荐不修**（保留名字接口）
- **它是什么**：agent 现在问引擎是**按名字**（`query_rules{kind:'pet',name:'喵喵'}`），引擎自己把名字解析成 id；
  另一条路是让模型直接写 `pet_id:'pet_000012'` / `term_id:'...'`。
- **为什么纠结**：如果"会写 id"算能力，那就得花配额训它背 622 个 id。
- **我推荐不修的理由**：① 这是**记忆**任务，不是 agent 能力（主线要的是"会用工具、会多步查证"）；
  ② 名字路已经量到 **0/40 → 40/40**（生产提示下全图鉴契约）；③ 模型编 id 的失败模式更坏
  （`pet_000999` 这种查不到，而名字写错引擎还能给候选）；④ 按本仓两层口径，id 属于 **dev 段**，
  不进玩家/模型接口。
- **不修的代价**：几乎没有（我们的脚本内部照常用 id）。

### 2. 「金标 vs 证据包冲突 4 条」（c01/c02/c10/c11）→ **我推荐改金标，不改模型**
- **它是什么**：49 例评测里，这 4 条的金标要求"**恰好查一次**"，可它们的答案**证据包里本来就有**：
  c01 当前血量/能量、c02 对方道具、c10 当前能量、c11 对手后备名单（`publicState` 顶层两侧 pets 全带）。
- **为什么纠结**：不查就被判"少调工具"，查了就是**为了指标做无用查询**（而"不该查却查了"是要压的指标）。
- **根因**：`publicState` 后来加字段了，**金标没回头更新** —— 不是"两种判定口径之争"。
- **推荐**：把这 4 条金标改成"包里有 ⇒ 不许再查"，并让"必要查证"的判据只认包里**没有**的东西
  （c03–c07 那类：指定回合原始事件、分支模拟、合法行动列表 —— 这些包里确实没有，现在也在查）。

### 3. 「阵容观察」→ 按你的口径改：**给推荐的下一个精灵**（不再靠"不许点名"堵嘴）
- 你说得对，我上轮纠结的东西本身就不该是主线：我想用"禁令"让模型别点到不在队里的名字，
  结果它两次都**整段拒答**（提示里的约束叠多了会把答案压没）——已经撤回。
- **改成能力侧**：阵容问题就让 agent 去查引擎（`team_gaps` / 名单 / 系别与六维 / 对手当前系别），
  **给出"下一只建议带谁 + 为什么"**，每个名字都来自回执（可回查）。这正是交付 2/3 的主线。
- 前提：这条推荐必须走引擎事实（不许我或模型自己编"这样更好"）。

### 4. 换人行那一格的红绿 → **推荐由引擎发一个字段**（我不替玩家挑算法）
- 现在是空白（`data-b3-rel="unknown"`，不画 ≠ 画"无影响"）。引擎对"换人"这个动作不发布任何相性字段，
  双属性精灵也没有唯一"攻击方属性"。
- **推荐**：引擎按它自己的口径在换人动作上发 `switch_multiplier`（比如"换上它、用它最好的本系技能打对面"），
  页面只显示。**在那之前不画**——比画一个我挑的算法诚实。
