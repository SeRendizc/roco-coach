# 六个真问题扫出来的三个缺陷（2026-09-25）

> 做法：拿**玩家真会问的 6 句话**打真服务 + 真模型（`gap-probe.mjs`，营地上下文带六槽阵容），
> 逐条看「它调了什么工具 / 依据行是什么 / 正文说了什么」。仓库里已经有的两处修复（术语、换人）
> 当回归对照。**先测量再改**，一个缺陷一处修法，每处都补判据与反证。

## 1. 探针结果（改前 → 改后）

| 问 | 改前 | 改后 |
|---|---|---|
| 喵喵学得到哪些技能？ | 没进工具循环 →「我这边没有喵喵的技能表」 | **调 `query_rules{kind:'learnset',name:'喵喵'}` → 列出 16 个技能** |
| 我这六只谁速度最快？ | 没进工具循环 →「我手头没有速度数值」 | 仍「证据里只有名字，没有速度数值」（**未修，见 §5**） |

| 第三只换成圆号鱼好不好？ | ✓（上轮修的） | ✓ 如实说六只阵容不支持 |
| **能量上限是几个豆？** | **答对了却被判成编造**：回退成模板「**我在。**」 | **「能量上限是6个豆。」** |
| 这个阵容打 PVP 有什么短板？ | 没进工具循环 →「先不瞎猜」 | 仍「阵容还没进过对局，看不出短板」（**未修，见 §5**） |

## 2. 缺陷 A：守卫把**答对的固定规则题**打成了模板

**机制**：`checkGroundedAnswer` 的「可追溯数字」集合只收**证据包里出现过的**数字，而
「能量上限 6」来自**系统提示里的规则表**。实测：`能量上限是 6 个豆` → `unsupported-number:6`
→ 硬回退 `packet.text`，而营地里那个模板是 `chatReply` 的通用句「我在。」。
**两头堵死**：49 例里的 `cat2`（固定规则）金标是"**不该调工具、直接答**"，守卫却判它编造。

**修法（只放松一处，且只发生在营地）**：`ruleConstantNumbers()` 从**规则表本体**（`RULES`/`ITEMS`）
取数；`answer.publicState` 存在时（对局中）**照旧只认证据包**。数字校验同时分两档：
`N%` 只认**在 `%` 语境里出现过**的数，其余走普通档。

**我在这处走错又收窄的一步（值得记）**：我一开始把整份**规则文案**（`rulesSections()`）也吞进白名单，
结果文案里的**宠物数值行**（「伏光貂（雷系）：生命 90 / 攻击 32…」）让一句凭空捏造的
「寂灭骨龙 120/180 血」蒙混过关 —— **两条既有判据**（`tests/roco-battle-context.test.js` ⑥、
名单那条 ②）当场把我判红。收窄成"只认 `RULES`/`ITEMS`"之后：
正确规则主张全过、`7/60/90%/999/120/180/88` 全拒、对局里连 `6` 也照样要求证据。**判据先红，才没有留下这个洞。**

## 3. 缺陷 B：学习表只认内部 id（玩家说不出 `pet_000001`）

**修法**（照 `kind=term` 那条同法）：引擎 `_answer_learnset` 接受 `name` ——
唯一名 ⇒ 用它的 `pet_id` 走原路；**重名 ⇒ 显式列候选**（这份规则集里 63 个名字是多只共用的：
化蝶 4 只、棋契陛下 8 只…），绝不挑一只；查不到 ⇒ 404；既没 id 也没名字 ⇒ 400。
合同放开 `learnset + name`；新增政策 `learnset-ask`（`ROCO_LEARNSET_LOOKUP` 默认开），
认「X学得到哪些技能 / 能学什么 / 可以学哪些招式」，**取不出名字就 fail closed**
（实测误判：「战斗中学得到技能吗？」会被解析成一只叫「战斗中」的精灵 ⇒ 加了很小的开头黑名单）。

## 4. 缺陷 C（顺带挖出的老 bug）：`CODEX_FIELD` 是非捕获组，那段分支**从来没生效过**

`codexTarget` 用 `m[2]` 判断问的是哪类字段，而 `CODEX_FIELD` 原来写成 `(?:…)` ⇒ `m[2]` 恒为 `undefined`
⇒「威力/能耗 → `kind:'skill'`」与这次的「学习表 → learnset」**都不可能命中**（典型的"期望值恒为假"）。
改成捕获组后：`喵喵的学习表` → `learnset`、`喵喵的威力` → `skill`、`喵喵的种族值` → `pet`。
判据里加了**结构钉 + 行为钉 + 探测器反证**（③）。

## 5. 没修的两条（如实留着）

| 问 | 为什么没修 |
|---|---|
| 我这六只谁速度最快？ | 引擎里能一次给出"真名+系别+六维+规范配招"的是 `kind:'roster'`，但那是**整份 48 只名单**；而 `evaluate_team` 按 3 只算。要答"六只里谁最快"，得先决定：给 48 只全名单让模型自己挑，还是新增一个"指定这几只"的查询。**这是设计选择，不该由我顺手定。** |
| 这个阵容打 PVP 有什么短板？ | 同上（阵容评估按 3 只算；六只的评估口径与"第 5 周扩展"那条是同一件事）。 |
