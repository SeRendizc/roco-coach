# 六只的六维进包：从「我手头没有速度数值」到「音速犬和皇家狮鹫，都是120」（2026-09-25）

> 接着上一轮的六问探针。上一轮结束时如实登记了两条"没修"的缺口：
> **「我这六只谁速度最快？」** 与 **「这个阵容打 PVP 有什么短板？」** —— 当时我把它当成"设计选择"。
> 这一轮先查了一件事，发现它其实**不是设计问题，是数据没送到**：引擎早就把六维发给页面了。

## 1. 关键事实：页面手里一直有六维

- 服务端 `/api/roco/pool` 的每一行都带 `stats`（`src/server/roco-service.js`：`stats:p.stats??null`）；
- 页面把它整行留在 `state.roster` / `state.rosterAll` 里（`state.roster = data.pets.filter(...)`）；
- 但 `coachLineup()` 只把 **名字与系别** 放进 `profile.lineup` ⇒ 模型只能回「我手头没有速度数值」。
- 六个数字（`{hp,atk,def,spa,spd,spe}`）加起来 **273 字节**。

⇒ 修法就是**把事实送全**（与之前 `lineup`/`pool_summary`/`roco_battle` 同一条路），**不是**替模型算结论。

## 2. 三处改动

| 处 | 改什么 |
|---|---|
| 客户端 `coachLineup()` | 每行加 `stats`：按名字找**唯一**那一行（`rosterRowByName`，重名返回 null）、**六个键齐全才带**（缺一就不带，不半真半假） |
| 服务端 `validateChat` | `lineup[].stats` **白名单六个键 + 有限数（0..9999）**；多一个键、非数、负数、不是对象一律 400 |
| 规划器提示（阵容问题） | 允许**就包里的系别与六维做观察**（「两只速度 120、其余偏慢」「缺能扛特攻的盾」），**禁止**胜率/优劣/克制结论；并如实说明引擎的阵容评估与换人对比只按 3 只算 |

第三处是顺带修的同类缺陷：**手里有事实却一律回"没数据、不硬猜"** —— 与上一轮修掉的「能量上限」那个 bug 同类。

## 3. 端到端证据（真页面，不是我喂数据）

`roco:coach-agent-acceptance` 改成走产品路径的 `?team=own-0001..0006` 预填六只，新增两条判据：

```
✓ 06-请求体带六维 — lineup 6 条，带齐六维的 6 条（例：铠甲虫 spe=75）
✓ 07-谁最快答得出来（且不是"没数据"） — 问「我这六只谁速度最快？」→ 音速犬和皇家狮鹫，都是120。
   （页面送来的最快：音速犬/皇家狮鹫 spe=120）
8/8 通过
```

判据 07 的**期望值从请求体自身算**（谁最快由页面真送来的六个 `spe` 决定），不写死名字 ——
所以它测的是"模型有没有用上真数据"，不是"有没有背下答案"。
**并列也测到了**：这六只里音速犬与皇家狮鹫同为 120，回答把两只都点了出来。

## 4. 六问探针的改后状态

| 问 | 结果 |
|---|---|
| 喵喵学得到哪些技能？ | ✓ `kind:'learnset',name:'喵喵'` → 16 个技能（上一轮修的） |
| **我这六只谁速度最快？** | ✓ **「音速犬和皇家狮鹫，都是120。」** |
| 「应对」这条术语… | ✓ 查术语表 + 三条候选 |
| 第三只换成圆号鱼好不好？ | ✓ 如实说六只阵容的对比引擎还不支持 |
| 能量上限是几个豆？ | ✓ 「能量上限是6个豆。」 |
| **这个阵容打 PVP 有什么短板？** | ✓ 「…速度线挺密，但缺能扛特攻的盾。」（就包里的六维做观察，不再是拒绝） |

**残留（如实记）**：最后那条的措辞会把**对话里提过的**名字带上（探针里上一问聊过「圆号鱼」，它就写成
「圆号鱼、音速犬这套」）。事实没错（观察来自六维），但读者可能误以为圆号鱼在队里。
要收紧就得再加一条"点名成员只许点 lineup 里真有的"——这一轮没做，留作候选。
