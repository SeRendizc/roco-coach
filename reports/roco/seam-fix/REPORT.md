## 一、结论（一句话）

**画框自己那条 1px 硬横线被压掉了**（框底那一行从 `#243444` 变成卡片底色 `#111c26`，
跨框底的一步从 **23.4** 亮度差变成 **0.0**），且**零几何位移**（画框/立绘/三列坐标逐位相同）。

## 三、改法（`src/client/battle-v3.css` 末尾追加，三行，全部只改颜色/叠加层）

```css
.b3-wrap .b3-spritebox{border-bottom-color:var(--b3-panel)}        /* ① 底边改卡片底色 */
.b3-wrap .b3-spritebox::after{                                     /* ② 暗角层在最后 34px 叠卡片底色 */
  background:
    linear-gradient(180deg,rgba(17,28,38,0) calc(100% - 34px),var(--b3-panel) 100%),
    radial-gradient(120% 90% at 50% 30%, rgba(0,0,0,0) 45%, rgba(0,0,0,.45) 100%);
}
.b3-wrap .b3-sprite{                                               /* ③ 立绘图底边 32px 渐隐 */
  -webkit-mask-image:linear-gradient(180deg,#000 calc(100% - 32px),rgba(0,0,0,0) 100%);
  mask-image:linear-gradient(180deg,#000 calc(100% - 32px),rgba(0,0,0,0) 100%);
}
```

**为什么底边不用 `transparent`**：透明会把画框自己的背景渐变底端 `rgb(15,22,29)` 露出来，
那仍是一条（更暗的）线；写成卡片底色才与下方同色。**为什么还要 ②**：暗角层会把框底色再压暗约 27%，
不盖住的话框底还是比卡片暗一档。**为什么 ③**：立绘素材的底边是「灰块切一刀」，渐隐后落进卡色里。

## 六、如实记档：**还有一条线不是画框的，是立绘素材自己画的**

y=690–697 那条「暗—亮—暗」是**素材里画的地面/底座边**（`data/roco/assets/pets/*.png` 自己带的），
不是 CSS 能「修」的东西。本次 32px 渐隐把它**削弱**了（45.0→37.7、66.1→45.9）但没有消掉：
再往上压就得把渐隐拉到 ~50px 以上，那会吃到精灵脚部的投影。
这是一条**取舍**，不是缺陷 —— 要彻底消掉它应该改素材（裁掉地面那条边）或把渐隐再拉长。
**本报告不声称「全部横线都没了」**：画框那条没了（已量化），素材那条变弱了（已量化）。

## 八、附：战斗区收窄（人类 2026-09-25 决策 2）—— 与立绘适配度的关系

见 `width.json`（同一采集器、同一状态）：

| 量 | 改前 | 改后（面板 1408） |
|---|---|---|
| 面板 | `x=0 w=1440`（整窗铺满） | `x=16 w=**1408**`（两侧各 16px，= 设计稿总宽） |
| 三列 | 232 / **914** / 232 | 232 / **882** / 232 |
| 立绘框 | 420×465 | **404**×465 |
| **立绘** | **347×463** | **347×463（没变小）** |
| 立绘占框宽 | 0.826 | **0.859** |

结论：立绘是**高度约束**的，横向收窄 32px **不会把立绘变小**，只把画框两侧那块深色留白收掉 ——
这正是「考虑立绘的适配程度」这条口径下的最优取法（再窄就开始吃左列四格与右列战报的可用宽度）。
