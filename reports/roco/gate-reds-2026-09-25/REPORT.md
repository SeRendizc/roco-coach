# 安静树门禁的 3 套红：性质、修法、验证（2026-09-25）

在**确认安静**（连查三次无写入）的树上跑完整 24 套门禁：`env` 修好后转绿，剩下 **3 套红**。
三套的性质完全不同，**没有一套是"改判据让它绿"**。

## 一、`retained-assets`（0s）——**不是独立红，是 `workshop-acceptance` 的连带**

它的 `pvp-gate` 资产证据就是 `reports/roco/workshop-acceptance/browser-workshop-acceptance.json`，
要求 `all_ok`。工坊那两条红 ⇒ 这份报告 `all_ok=false` ⇒ 资产自检直接判"现状本身就有问题"。
**工坊修好之后它自然绿了**（`RETAINED_EXIT=0`）。

## 二、`workshop-acceptance`（47/49）——两条**过时判据** + 一个**玩家可见的真缺陷**

1. **判据 37/38 过时（前提变了）**：它们去点 `.tw-about`（「看是哪几个 / 为什么」），
   而这个折叠头**只在有算不出来的轴时才渲染**；四轴改成三档判定后**五轴全部可算** ⇒
   那一整块不渲染。旧选择器还按 class 取，**撞上了另一个 `hidden` 的 `.tw-about`**
   （理论阵容框），于是量到"隐藏元素的 0 高度"与错位的箭头 —— 红得毫无意义。
   **修法**：给那个折叠头明确 `id="tw-missing-axes-box"`；判据改成**条件式** ——
   在就按原口径判（两态等高 ≤4px、箭头 ▸/▾），不在则要求"确实没有算不出来的轴"，
   否则才是真红；两条反证原样保留。
2. **真缺陷（玩家可见）**：`#tw-analysis-box`（理论阵容）在标记里写死 `hidden`，
   而代码只给它设 `.open = true` —— **给一个 `display:none` 的元素"展开"**，
   所以玩家**永远看不到理论阵容**。HEAD 里也一样（不是本轮的回归）。
   而判据读的是 DOM 内容（`data-tw-analysis`），所以**长期是绿的**
   ——「**判据读取点 ≠ 玩家真正看的像素**」的又一例。
   **修法**：有内容才显示（`hidden = !hasAnalysis`），并在判据 10 里加一条**像素断言**：
   有内容却不可见（hidden 或高度 0）必须判红 —— 配一条反证
   （把 `{count:1, box:{hidden:true,h:0}}` 喂进同一条判据必须报）。

**验证**：`判据 49/49 通过；反证 39/39 命中`（原来 47/49）。

## 三、`unit`（4 条）——两条是"永远不可能成立"的期望值

| # | 现象 | 性质与修法 |
|---|---|---|
| 1 | 10 个新判据文件"绿着但永远不会执行" | **守卫有效**：我这一天新增的判据没登记进 `test:unit`。已登记，重跑 **1160/1160** |
| 2 | 结构契约报 `tests/roco-model-wiring-honesty.test.js -> ./local-model.js` 不存在 | **误报**：那是**夹具字符串**里的合成 import。夹具改成**真实路径** `../src/coach/local-model.js`（更贴近它要模拟的接法） |
| 3 | 27B 判据要求 `referenced.length >= 3`，实际只能到 2 | **期望值恒为假**：`repoFiles()` **排除了判据自己**（SELF），那句"面板 + 两条判据"永远凑不齐。改成"面板必须在结果里 + 至少还有一条判据"（比原来更难蒙混） |
| 4 | 必红反证「走推理子进程脚本」没被认成调用路径 | **判据真缺口**：`INFERENCE_ENTRY` 跑在**屏蔽字符串之后**的代码上，而子进程接线的入口（`serve_mlx.py`、`--model`）恰恰住在字符串里 ⇒ 真这么接它认不出来。补一条对**原文**（跳过纯注释行）的入口匹配 |

**验证**：`tests/roco-model-wiring-honesty.test.js` 4/4；`npm run test:unit` **1160/1160 通过**。

## 四、这一天的红里，"期望值恒为假"出现了三次

`env` 的 `forbidden_kinds == ("item","escape","反证故意改错")`、27B 的 `>= 3`、
以及工坊 37/38 的"无条件前提"。**共同点**：判据**看起来在守，其实永远不会红/永远红**，
而它们全都靠"真跑一次门禁"才暴露。这条经验值得记住：**判据本身也要有"它会不会红"的证据**
（本仓已有的做法是必红反证；这三处恰恰是反证**没覆盖到判据自己**的地方）。
