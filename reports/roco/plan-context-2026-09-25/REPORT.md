# 引擎的规划（军师浮条那一份）进教练上下文（2026-09-25）

**一句话**：六宠对局里引擎已经把这一手算好了（推荐 / 主要应对 / 预期 / 最坏 / 边际量 /
伤害预览），页面把它画在**军师浮条**上；教练聊天**一点都拿不到**。
这一轮把它接上，并且**过期的一份都不许进**。

## 一、真机 A/B（同一句话）

| | 回答 |
|---|---|
| **不带 plan** | 「这手我这边给不了结论，**安静档不说战术**。要不你打完再把想法丢过来，我陪你复盘。」 |
| **带 plan** | 「这回合**引擎算的是翅刃**，预估伤害够高。」 |

## 二、**纠正**：那不是语气门，是模型在"我有没有这份数据"上乱说（已修）

上一版报告把 3 次里的 2 次拒答归因到「聊天的语气门（register）」——**这个归因是错的**。
把记忆状态分开量（零记录 / 1 局记录 / 连败 2 局）之后：**三种状态都能答出引擎结论**，
说明语气门并没有挡住这件事。真正的现象是**同一句话连跑 6 次的抖动**：

| 改前（6 次） |  |
|---|---|
| 引用引擎结论 | **4/6** |
| 说「我不冒充引擎 / 我这边没有能支撑的记录」 | **2/6** ← 手里其实有规划 |

这是"**声称自己没有手里明明有的数据**"，与 C6.100 那条 `denied-available-receipt` 同一类。
修法沿用仓库的老办法（与 roco-service 的「对手是示例阵容」同款）：规划进包时**附一条来源说明** ——
只讲「这份数据是什么、来自引擎、可以引用」，**不含任何结论或数字**（结论只在 `rocoPlan` 本体里）。
加性：只有真的送了规划才出现（营地/三宠那两条老路一字不变）。

**改后（同样 6 次）：引用引擎结论 6/6、硬拒答 0/6**，并且第 6 次是这样的：

> 「引擎推荐这手「翅刃」，24 个分支都跑过，预估收益 0.62、最坏 0.28，推荐稳定。
>  但主要防着对手换芽角鹿上场。**不过我是陪练不是军师，这手怎么打要你自己定。**」

——**又给信息、又不越位**，这才是想要的行为。

## 三、改动（加性，第三件同类接线）

| 层 | 改动 |
|---|---|
| 客户端 `roco.js` | 新增 `coachRocoPlan()`：从 `state.plan` 裁一份**紧凑**快照（推荐/主要应对/预期/最坏/边际量/分支数/伤害预览/风险），**复用页面自己的 `rocoPlanFreshness()`** 判新鲜度 —— 过期或没有版本号**一份都不送**；拿不到就不加这个字段 |
| 客户端 | 战况快照补上 `state_version`（没有它就没法做跨字段对齐） |
| 服务端 `index.js` | `validateChat` 加性校验 `context.roco_plan`（state_version 必需、名字类字段裁长、数字类必须有限、damage_preview.samples ≤8 且每条要有 label…），并**跨字段对齐**：`roco_plan.state_version` 与 `roco_battle.state_version` 不一致 ⇒ 400 并**点名两边的版本** |
| 运行时 `runtime.js` | `context.roco_plan` ⇒ `packet.rocoPlan`（不带则不出现）；事实守卫的可追溯数字集合一并加入 `plan`（与 `rocoBattle`/`roster` **同一个坑**，这次同时做掉） |

## 四、判据

`tests/roco-plan-context.test.js` **7/7**：
① 加性校验（10 种畸形逐条 400）；② **跨字段对齐**（版本不一致必须拒，并点名 6/7）；
③ 进包（带则原样、不带则键不存在）；④ 守卫认得规划里的数字（反证：不带规划时 `unsupported-number`）；
⑤ 结构性（必须复用 `rocoPlanFreshness().usable`、拿不到就不加字段、战况要带 `state_version`）；
⑥ **来源说明**（带规划时有且只有一条、点明来自引擎、**不含数字**；不带规划时不许出现）；
外加必红反证（版本一致时必须放行）。相关判据合计 **73/73** 绿。

**踩到的测试坑（记一笔）**：判据辅助函数用 `battle = BATTLE` 默认参数，
而调用方写 `bodyWith(plan, undefined)` 想表达"不带战况"—— JS 里**显式传 `undefined` 照样触发默认值**，
于是"无战况"那一路悄悄变成了"有战况"。改用 `null` 表示"不带"，并在注释里写清原因。

## 五、边界

- 只送**新鲜**的规划：`rocoPlanFreshness()` 要求 plan 与 view 的 `state_version` 都存在且相等，
  否则整条丢弃（页面已有这条判定，这一轮只是复用）。
- 规划里的**风险/伤害**是引擎按公开面算的估值，不是胜率；判据只保证"能被引用"，不保证措辞。
- 这一轮**没有**动聊天的语气门 —— 而且第二节纠正了：那本来就不是语气门的问题。
