# 「评一下我这队」现在真的走引擎了（2026-09-25 续）

**一句话**：上一轮让小芽**看得见**你选的六只；这一轮让它能把其中三只**交给引擎评估**，
并且在"你只说了'我这队'但选中超过三只"时**明确反问要哪三只**，而不是替你挑。

## 一、三态实测（真机，同一份 lineup）

| 说法 | 结果 |
|---|---|
| 「帮我评一下**铠甲虫、音速犬、仪式巨像**这三只」 | `evaluate_team({"team":["pet_000012","pet_000062","pet_000100"]})` · 引用回执作答（连跑 3 次：**3/3 调用、0/3 否认**） |
| 「帮我评一下**我这队**」（选中 6 只） | **确定性反问**：「你这 6 只是：铠甲虫、音速犬、仪式巨像、化蝶、皇家狮鹫、雪影娃娃。要评的话得先点三只 —— 直接说三个名字就行。」（不走模型，`locked`） |
| 「帮我评一下**我这队**」（正好选中 3 只） | `evaluate_team(...)` · 「这队职责挺全，输出、承伤、控制、回复、驱散、增益都有…只是被 9 种属性克制」 |

## 二、名字 → 物种 id：只认唯一匹配

工作台公开层**只给名字/系别**（物种 id 在 dev 段，不越层去拿）。
页面用自己手上的名单（`state.roster` / `state.rosterAll`，行里有 `pet_id` + `name`）按名字对一次，
**只在唯一匹配时**才补 id：图鉴里 **62 个名字是重名的**（一个名字对应多个物种）、
名单里 48 只自身也有一个重名（「棋契陛下」）—— 这些一律**不带 id**。

没有 id 的后果是**如实的能力边界**：教练仍能说"你这六只是谁、属性怎么样"，
但**不能**把它们交给引擎评估（`teamAsk` 直接返回 `null`，不拿猜的 id 去评估）。

## 三、踩到的两个坑（都是我自己引入的）

1. **两支打架**：新加的「反问」分支用 `这三只` 当信号，而"帮我评一下 A、B、C 这三只"里
   也有「这三只」⇒ **点名三只被反问截胡**（工具一次都没调）。
   修法：抽出共用的 `namedTargets()`，**已经点名三只时反问分支必须让位给评估**
   （判据 ④c 反方向都钉了）。
2. **回执有结论、正文却说"评不了"**：实测抓到一次 —— 工具调成功、回执里是完整评估，
   正文却写「我暂时评不了…不想瞎编给你误导」。这是**一句假话**，玩家会直接读成"小芽不行"。
   修法：一致性守卫新增一条 `denied-available-receipt:evaluate_team` ——
   **只在回执真的成功**、且问的正是阵容评估时才判；三个反方向用例都钉住不许误伤
   （正常引用回执 / 说别的事的否定 / 回执本身失败时说"评不了"是实话）。

## 五、边界

- 六只（或四只、五只）时**不评**，只反问：引擎的 `evaluate_team` 按三只算，
  替玩家挑三只就是替他做决定。要评六只需要另做"六宠模式"的评估口径（另一件事）。
- 「反问」是**确定性短回答**（不调模型）：它只是把玩家已经给的名单念清楚 + 说明为什么要三只，
  不含结论、不含数值，所以不存在编造空间。
- 名单来自客户端 profile（与教练上下文其余部分同等信任级别）。
