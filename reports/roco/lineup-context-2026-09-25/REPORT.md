# 小芽把你**没选的候选池**当成"你的队伍"报了出来（2026-09-25）

**一句话**：问「我这六只都有谁？属性搭配怎么样？」时，改前它自信地回答
「**你带的六只是：喵喵、水蓝蓝、火花、寂灭骨龙、魔翼狮、草头鸭**」——
那 12 只是**候选池的前 12 个**，「你这六只」在里面纯属巧合的错觉。
这比「我手头没数据」更糟：**是一句听起来很确定的错话**。

## 一、真机 A/B（同一句话，只改 payload）

| | 回答 |
|---|---|
| **不带 `lineup`**（页面现在的行为） | 「你带的六只是：喵喵、水蓝蓝、火花、寂灭骨龙、魔翼狮、草头鸭。不过属性数据里都标着"未知"，我这边没法判断搭配好坏。」 |
| **带 `lineup`** | 「你的六只是：铠甲虫、雷震娃娃、皇家狮鹫、潮甲龟、芽角鹿、化蝶。属性覆盖虫、冰幽、翼、水、草，搭配挺均衡。」 |

## 二、根因

`coachCampContext()` 送的是 `profile.pets = (候选池 rows).slice(0, 12)` ——
**候选池**，而"玩家当前选的那六只"存在**六槽工作台**里（`state.teamWorkshop`），
从来没进过教练上下文。模型手上只有一堆候选，于是把候选当成了队伍。

## 三、改动（加性）

| 层 | 改动 |
|---|---|
| 客户端 `roco.js` | 新增 `coachLineup()`：从**工作台回执的公开层** `state.teamWorkshop.payload.player.slots` 取 `state==='filled'` 的槽位 → `{name, types}`；**公开层没有物种 id 就不写 id**（id 在 dev 段，不越层）；没有回执时整条不发 ⇒ `profile.lineup` |
| 服务端 `index.js` | `validateChat` 加性校验：1..6 条、每条是对象且 **id 与 name 至少有一个**、name ≤24、types ≤2 且每项 ≤8 字；畸形一律 400「阵容名单无效」 |
| 运行时 `runtime.js` | `context.profile.lineup` ⇒ `packet.lineup`（**不带则不出现**）；事实守卫的可追溯集合一并加入 `lineup`（防上一轮那种"引用真数据被判凭空"） |

## 四、判据

`tests/roco-lineup-context.test.js` **4/4**：
① 加性校验（**只有名字也要放行** —— 公开层不给 id；9 种畸形逐条 400）；
② 进包（带则原样、不带则键不存在）；
③ **结构性**：只从 `state.teamWorkshop?.payload?.player?.slots` 取、只取 `filled`、
源码里不许出现去 `dev` 段取 id 的写法；
外加必红反证（不带 lineup 时空数组不再被这条规则拒绝）。

## 五、边界与下一步

- `lineup` 只带**公开层的名字/系别**（没有物种 id、没有种族值）。所以
  「评一下我这队」还**不能**直接走引擎 —— 需要先把六槽的"实例 → 物种 id"在服务端解析出来
  （`own-XXXX → pet_xxxxxx`），才能交给 `evaluate_team`。那是下一步。
- **残留风险**：玩家**没选过队伍**时页面不发 `lineup`，模型仍可能把候选池读成"你的队伍"。
  可选的缓解（本轮**没做**，避免再动 49 例的口径）：给候选池加一条与
  「对手是示例阵容」同款的说明。等这轮改动量完再评估。
- 候选池那 12 只本身也只是**池子里的前 12 条**，不是"你的全部"；面板要显示"你的"，
  仍以盒子页/工作台为准。
