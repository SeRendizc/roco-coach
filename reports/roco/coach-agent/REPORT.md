# 玩家路径验收：小芽在**真实页面**里真的去查了引擎（2026-09-25）

**一句话**：前几轮的接线都是用 HTTP 探针验的，而**玩家看的是页面**。
这一份走完整链路：产品页 `roco.html` → `#say-input` → `/api/coach` → 模型 + 工具
→ 回复渲染进 `#say-reply`，并**抓页面真正发出的请求体**做交叉核对。

## 二、跑法

```bash
npm run roco:coach-agent-acceptance      # 或 node scripts/roco/browser-coach-agent-acceptance.mjs
```

- **需要联网 + 钥匙串里的 `pet-coach-deepseek`**：拿不到 key 就退出码 2 ——
  不许把它跑成一个"没有模型也通过"的假验收。
- **不属于 24 套门禁**：那 24 套全部离线、不需要密钥（我查过）；这一份属于 `eval-live` 那一族。
  所以给了它一个 npm 入口，免得又变成"写了但没人跑"的脚本。
- 脚本里显式打开 `ROCO_CODEX_LOOKUP=1` / `ROCO_TEAM_LOOKUP=1`，与**正在跑的产品实例**对齐；
  关掉这两条能力时 `01` 会红 —— 那是"默认关"的**可见后果**，不是脚本坏了。

## 三、写这一份踩到的三个坑（都留在注释里）

1. **时序**：`say()` 会**先**渲染离线兜底（`source=offline`）**再**用模型回答覆盖。
   只等"文本变了"会抓到兜底那句，并让**下一问读到上一问的答案**（第一次跑就是这么错的）。
   正确条件：等到 `data-roco-companion-source === 'model'`。
2. **`server.close()` 不会关 keep-alive 的空闲连接** ⇒ 打印完结论后进程不退。先 `closeAllConnections()`。
3. **连到 Chrome 的 WebSocket 句柄**会让事件循环一直活着 ⇒ 必须显式 `ws.close()`；
   再加一个 4 分钟看门狗，超过就把已有结果打出来按失败退出（**不许静默挂死**）。

## 四、边界

- 只覆盖**两问**（图鉴事实、名单总数）——它证的是"玩家路径通"，不是全量回归；
  战况/规划/阵容那几条的浏览器验收还没做（HTTP 探针 + 结构判据已覆盖）。
- 截图与逐项证据：`reports/roco/coach-agent/{coach-agent.png,acceptance.json}`。
