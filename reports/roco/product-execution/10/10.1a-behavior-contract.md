## 1. 落点与保留（裁决 Q1 的落地，含读数）

**落点：`<repo>/tmp/roco-sessions/`**（运行时目录，按需创建）。

| 候选 | `git check-ignore` 读数 | 结论 |
|---|---|---|
| `output/roco/sessions/` | **空**（未忽略；`output/` 还有 43 个被跟踪文件） | ✗ 会让快照出现在 `git status` 里 ⇒ 违反「不许进版本库」 |
| `tmp/roco-sessions/` | `.gitignore:6:tmp/`（命中） | ✅ **采用** |
| `reports/roco/product-execution/10/` | 空（未忽略，只放人类证据） | ✗ 快照是机器产物，不进证据目录 |

- 允许用环境变量 `ROCO_SESSION_DIR` 覆盖（隔离副本/判据用；默认值永远是上面的路径）。
- **不进 `data/**`**（Q1 裁决：`data/**` 是被 git 跟踪的真实数据，**只读**）；也**不得进版本库**
  （故落点必须落在一个被 `.gitignore` 忽略的目录里 —— 上表的 check-ignore 读数就是这条的判据）。
- 文件名：`<battle_id>.json`（`battle_id` 由服务端生成，形如 `s<计数>-<8 位随机>`；只允许 `[A-Za-z0-9_-]`，拒绝其它字符 ⇒ 防路径穿越）。
- **写入原子**：同目录 `.<battle_id>.json.tmp-<pid>-<rand>` → `fsync(file)` → `rename(tmp, final)` →（POSIX 尽力）`fsync(dir)`。
  任何时刻磁盘上要么是旧快照、要么是新快照，**没有半写**。
- **保留策略**（只在"明确结束/被替换之后"触发清理）：
  - 进行中（`active`）快照 **永不清理**（无论多少份、无论多久）；
  - 已结束（`ended`）快照：最多保留 **20** 份，且只保留最近 **24h** 的；超出者（时间更早或排名更后）删除；
  - `retired` 快照与 `ended` 同规（属"已结束"一类）；
  - 清理**必须**留下可核对读数：返回 `{kept, dropped:[{battle_id, reason}]}`。

## 2. 一局的生命周期（状态机）

```
              startBattle                      结束（result != null）
   （无） ───────────────▶ active ─────────────────────────▶ ended
                             │  ▲                              │
        用户选"开新局"/被新局替换│  │ 水合成功（三校验通过）        │ 24h/超过 20 份
                             ▼  │                              ▼
                          retired ◀── 显式放弃/替换          被清理（磁盘删除）
                             │
        水合失败（三校验任一不符）⇒ 不装回引擎，标 stale（只读审计，可重开）
```

| 状态 | 语义 | 能否被当"当前局" |
|---|---|---|
| `active` | 进行中（未出终局结果） | ✅ 是（**必须**经用户确认才水合，见 §5） |
| `ended` | 已有终局结果 | ❌ 否（可复盘，不能出招） |
| `retired` | 用户明确放弃 / 被新局替换 | ❌ 否（**永久**；02 红线：绝不当本局） |
| `stale`（判定，不是落盘字段） | 快照存在但 `match_id`/`rules_version`/`state_version` 与当前引擎上下文不符 | ❌ 否（fail closed，提示后只允许重开） |

```json
  "last_receipt": { "decision_id": "d-…", "state_version": 12, "response": "…原始回执（Q5 幂等要用）…" }

```

字段纪律：

- `state` **逐字保存**引擎给的那一份（不许裁剪、不许"只存公开字段"——那样就续不上）。
- `match_id`/`rules_version`/`state_version` 三者是**水合校验键**（Q3），缺一不可 ⇒ 缺就 fail closed。
- `last_receipt` 只保留**最近一次**已结算回执（Q5 幂等）；`decision_id` 与 `state_version` 成对。
- 任何字段缺失/类型不对：读取方**不猜**，按 `stale` 处理并把原因写成大白话（§7）。

## 5. 禁止沉默清空（红线清单，逐条可判）

- **I1（本项第一红线）** 任何"这一局没了"的路径（清理/退役/水合失败/版本不符/引擎不可用）都必须产生
  **玩家可见**的说明，并且服务端有可核对的事实（快照 `status` 或错误 `error_type`）。
  **判据**：为每条路径各写一条断言：响应/界面里必须出现 §7 对应文案；把文案删掉 ⇒ 红。
- **I2** 渲染出来的 `view` 必须对应用户**确认过**的 `battle_id`；`retired`/`ended`/`stale` 快照
  **不得**被当作当前局（02 红线：不许显示上一局当本局）。**判据**：喂一个 retired 快照 ⇒ 页面必须显示"无当前局"。
- **I3** 水合 fail closed：`match_id`/`rules_version`/`state_version` 任一不符 ⇒ 不装引擎（Q3）。
  **判据**：三个字段各做一次"改坏"变异 ⇒ 三次都必须拒绝水合且给 §7-③ 文案。
- **I4** 写盘原子：任意时刻磁盘上只有旧或新，无半写（Q1）。**判据**：tmp 写入后不 rename ⇒
  目录里读不到该 `battle_id` 的有效快照（旧的那份仍在）；用 fake-fs 注入中断 ⇒ 读回旧值。
- **I5** 幂等：同（`decision_id`,`state_version`）⇒ 同回执、状态不变（Q5）。**判据**：连续两次同键请求 ⇒
  第二次回执**逐字等于**第一次，且引擎调用次数不增；变异：把幂等表关掉 ⇒ 第二次会推进 ⇒ 红。
- **I6** 版本显示：`ruleset` 不一致（fail closed）与 `runtimeVersion` 不一致（仅提示）的提示里
  **都要同时出现两边值**（Q6）。**判据**：文案里出现 `old` 与 `new` 两个值；只写一个 ⇒ 红。

## 9. 诚实边界

1. 本步**零代码改动**；§6 文案是"逐字落地用"的规格，10.1-b/c 落地时会引用本文件的 id（①②③…）以免两处漂。
2. §4 的 E9/E10 只定义**方向**（ruleset fail closed / runtimeVersion 仅提示），具体比较在哪一层做（桥 or 服务）
   由 10.5 定，本步不预设实现位置。
3. 「`decision_id` 复用」在**不改 Python 侧**（写域禁止动 `roco/**`）的前提下，幂等表只能建在 Node 服务侧
   （`roco-service.js`）——这是本契约对 Q5 的落地边界，10.2 落地时若发现 Python 侧也需要，先回报。
4. 快照里存的是引擎私有 `state`（含 seed 等未公开信息）：**只在运行时目录**，不进库、不进报告、不进日志。
