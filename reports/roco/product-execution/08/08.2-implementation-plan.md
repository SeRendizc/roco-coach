### 1.2 未核验标注（D-24 Q3：只给档位 + 区间，不给单点确定数）

- **不给单点**：伤害/承伤一律 `{min,max}`；速度只给档位 id；能量只给「够/不够/差几点」的算术。
- **每个数都带三件**：`verified`（bool）· `basis`（一句话，可复算）· `source`（`文件:行` 或引擎字段）。
- **文案层**：`formula_verified:false` ⇒ 玩家可见句必须带「估/大概」字样（先例：`coach-advice.js:628`「伤害来自引擎**未核验**的公式…措辞必须带『估』」）。
- **缺输入**：`opponent` 缺失 ⇒ 承伤 `verdict:'unknown'` + `why` 点名「没有对手面板」，**不给 0、不给猜测**（先例：`team-compare.mjs` 的 fail-closed）。

### 1.3 判据 + 两向变异

| 判据 | 正 | 反 | 两向变异 |
|---|---|---|---|
| 区间不是点估计 | `damage.a.range` 是 `{min,max}` 且 `min<=max` | 任何 `value` 单点出现在伤害/承伤行 ⇒ 红 | **把区间换成点估计 ⇒ 必红**（判据本体） |
| 未核验必须显式 | 每行 `verified` 是布尔；`verified===false` 时正文含「估」 | 缺 `verified` 字段 ⇒ 红 | 删掉 `verified` ⇒ 红 |

## 2 · S3 可撤销与偏好（U1–U6）

### 2.1 一次调整 = 一条可撤销记录（U1/G07）

现状：三套记录各自一步 —— 个体培养 `individuals.js:512 canUndo`/`:532 undoLastRefresh`（含 `:517 lastHistoryOf`）、
阵容 `team-workshop.js:195 TEAM_CONFIG_KEY` 的 `{current,previous}`、配招 `loadouts.v2`（S1）。
**设计**：新增一层**变更日志**（本机键 `roco.workshop.changes.v1`），每条 = 一次「应用/调整」的**指针集合**：
```js
{ schema:'roco-change/v1', id, at,
  parts:[{kind:'loadout'|'teamconfig'|'individual', target:'own-0001'|'pet_000004', before, after}],
  scope:'one_step' }
```
- 撤销 = **按 parts 逐条回装**（不重算、不猜）；`before` 存的是**原值**，不是差分；
- 只留一步（与既有口径一致：`teamconfig` 只留一步、个体回滚只退一步），且**撤销本身也进日志**（人类 2026-09-30 口径）；
- ⚠ 是否允许新增这个键 ⇒ **需 Lead 裁决**（见 §6-③）；若不允许，退路是把三处 `before` 合并进 `teamconfig` 的 `previous`（会撑大现有形状、并有 08 残留②的标签口径问题）。

### 2.2 不覆盖玩家偏好（U3/G05）

- `memory.goal ∈ {稳健,速攻}`（`memory.js:21-24`、`services/index.js:424` 校验）**只影响排序**，不改玩家显式选择：
  与 `locked`/`must_include`（RC-301 硬约束）、`favourites_only`、`preference`（brief/detailed）**同级并列**，优先级写在返回里（`applied_preferences: ['goal=速攻']`）。
- 教练承诺的接线落点：`runtime.js:2299`（「培养时我会优先比较输出和先手」）⇒ `runtime.js:491` 的 `adviceFor({priority})`
  改为 `priority = priorityFromGoal(memory.goal) ?? wantedStats(question)`，**goal 为 null 时落回问句**（不许猜）。
- 判据：`goal='稳健'` 与 `'速攻'` 下同一只的建议排序**不同**且与文案一致；`goal=null` ⇒ 与今天逐字相同（零回归）。

### 2.3 「目标培养」不得当唯一正确答案（U4/R9）

新增显式声明（字段级，不只在文案里）：
```js
{ recommended: {...}, not_the_only_answer: true,
  alternatives: [{direction:'speed', why:'…', tradeoff:'…'}, …],   // ≥2 条
  why_not_decisive: '面板差在这里，但对手面板未知 ⇒ 不替你定方向' }
```
**判据**：`not_the_only_answer===true` **且** `alternatives.length>=2` **且** 正文不出现「就该/必须/唯一」一族；
正文必须含「还有别的方向」的**可读句子**（不只是一行 JSON）。两向变异：把 `alternatives` 清空 ⇒ 必红；把 `not_the_only_answer` 挪进注释 ⇒ 必红（字段必须在返回值里）。
