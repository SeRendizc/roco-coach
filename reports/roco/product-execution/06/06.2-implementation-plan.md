     `D31-number-precision.md` §5 #5/#6）。⇒ 本项不再是 Q3 第一步的阻塞。

   「锚点之后的变化不改 `decisions[]`」在**集合层面**仍会变（换锚点=换条目）。建议锚点按 **at-decision 证据量**
   选（营地那支已经有先例：`keyDecisionOf` 按事前 gap 选，判据 `tests/coach.test.js:268-272` 明写「不是事后结果最惨的那一回合」），

```js
                  opponent: {active, hp, max_hp, energy, living_count},
                  legal: [{kind,label,skill_id,item_id,target_index}],
                  unknowns: ['opponent_bench_identity', 'speed_tie_policy', …] },
      chosen: {kind, skill_id, item_id, target_index},
      grade: {kind:'judgement-error'|'execution-error'|'knowledge-gap'|'reasonable-bad-outcome'|'undetermined',
              basis:'at_decision', is_probability:false, evidence_ids:[…]},
      evidence: [{id, text, basis:'at_decision'|'after_the_fact'}],
    }
  ],
  narrative: {                       // 加性；整局事实（允许用锚点之后的信息）
    basis: 'after_the_fact',
    items: [{id, text, basis:'after_the_fact'}],   // 例：第一次减员、最重一击、补位次数
  },
}
```

`turn ≥ 该 decision.turn` 的结算事件；`narrative` 反过来**必须**带 `basis:'after_the_fact'`（机器可检）。
正文由两者拼，但**拼装点在 `reviewMatch` 内**（硬约束 B1/B2）。
