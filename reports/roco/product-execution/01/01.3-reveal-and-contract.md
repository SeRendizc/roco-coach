## 2 · 契约字段（01.2）

### 2.1 口径（为什么是派生，不是存进 `GameState`）

- **`match_id` = 公开开局事实的确定性派生**：`ruleset_id + ruleset_config_id + 己方队伍`。
  三条「不吃」各有理由：不吃 `seed`（公开面必须与真实 seed 无关）、不吃**对手队伍**
  （那等于把对手六只写成一个可枚举的哈希 —— 12 选 6 只有 924 种）、不吃随机源
  （回放/反序列化会变成另一个 id）。
- **`rules_version` = `<ruleset_id>/<ruleset_config_id>`**；规则**数据**快照由回执信封既有的
  `snapshot_fingerprint` 钉死，两者合起来才说得清「当时按哪份规则算的」。
- **`decision_id` = `<match_id>:v<state_version>`**：`state_version` 是既有钉子
  （「这条事实对应哪个状态」），不新造计数器。
- **`event_seq` = 事件在 `state.events` 里的 0-based 追加序号**：`state_version` 的唯一写入点
  是 `_bump`（每追加一条 +1），实测恒等于 `len(state.events)` ⇒ 第 `i` 条事件的序号就是 `i`。
  `env.event_seq_of` **当场校验**这条不变式：绕过 `_bump` 直接 append ⇒ 抛错，而不是给错的序号。

### 2.2 可检索的一行（Lead 要求写进证据）

> **`observation_for` 不带 `match_id`/`rules_version`/`decision_id` 的理由**：`state.history`
> 存的是 `pre_observation_hash`，在观察载荷里加常量键会让 `test_turn_order_fail_closed` 的
> history 指纹整批改钉，而那一枚测的是「引擎默认路径没变」；信封身份要的是 UI / 教练 / 回放，
> 它们走公开面与回执，观察里**已有** `state_version` 这个钉子。
> 判据：`test_public_planner.py::TestObservationContractFields::test_observation_payload_does_not_carry_envelope_identity`。

## 3 · 开局预览（01.3）

### 3.1 事件原文（真跑 `service.battle_new({"opening_preview": true, …})`）

```json
{"kind": "opening_roster_revealed", "turn": 1, "evidence": ["3010"], "seq": 0,
 "detail": {"source": "opening_preview", "viewer": "player", "revealed_side": "enemy",
   "roster": [{"slot": 0, "pet_id": "pet_000417", "name": "圆号鱼"},
              {"slot": 1, "pet_id": "pet_000112", "name": "雪影娃娃"},
              {"slot": 2, "pet_id": "pet_000062", "name": "音速犬"}]},
 "text": "开局预览：对方的 圆号鱼、雪影娃娃、音速犬 亮明了（共 3 只）。"}
```

- **只有实际展示字段**：位次 / 物种 id / 名字。断言 hp / max_hp / energy / loadout / skill_ /
  panel / talent / nature / stats **都不在**事件里（`test_preview_event_carries_only_what_the_preview_shows`）。
- **同源两处**：`state.events` 里这一条 = 回执 `opening_reveal` 那一条（同一对象 + `seq` + `text`）。
- **重复登记抛错**（`开局预览已经记录过`）：两条预览事件会让「哪一份展示过」有歧义。
- 发出层由调用方决定（`battle_new` 的 `opening_preview`）：页面有没有弹预览层只有页面知道，
  引擎替它猜就是把「没展示」说成「展示了」。

### 3.2 三个公开面读同一份事实（`schema.revealed_facts` 是唯一实现）

| 亮明来源 | 记什么 | 落到哪里 |
|---|---|---|
| `opening_roster_revealed` | 预览展示过的成员 | 后备行带 `pet_id`+来源；`revealed.opponent_roster` |
| `switch` / `replacement`（对手侧） | 换上场的那一只（**换下去后仍留在名单里**） | 同上，`revealed_via` = 事件 kind |
| 带 `(side, skill_id)` 的其它事件 | 那一招真的打出去了 | `revealed.opponent_skills` |

**`action_cancelled` 不算「已出招」**：那一手没有结算，把它算成公开技能会把「本来想出、但没出成」
说成「他用过」。

**开局就在场上的那只不进 `opponent_roster`**：它的身份本来就在 `opponent.field` 里
（血条与名字画在屏幕上）——列进名单会让「无预览时也有阵容」看起来成立。

## 4 · 01.6 反例

### 4.1 A：固定公开史，只改隐藏真值 ⇒ 公开输入逐字段相同

（三次快照/三回合，逐字比较）。**只比玩家这一侧**：对手自己的血/能量对**它自己**不是隐藏信息
（`own_pet` 给面板），改它必然改到对侧视角 —— 那不是泄漏。

| 改的隐藏真值 | 判据 | 结果 |
|---|---|---|
| 对手**真实配招**（换掉整局不会用到的那一招） | `test_hidden_loadout_change_leaves_every_public_input_identical` | 三次快照 JSON **全同** |
| 对手**后备**血量/能量/异常/印记 | `test_hidden_bench_resources_leave_every_public_input_identical` | 全同 |
| 对手**隐藏个体面板**（`panel`） | `test_hidden_individual_panel_never_reaches_the_public_inputs` | 规划协议 + 观察**逐字节相同**；注入的六个数一个都不在 UI 里 |
| 真实 seed（既有判据） | `test_match_id_ignores_the_real_seed` + 既有 `test_public_state_is_identical_across_internal_seeds` | 全同 |

> **U1 仍然 `blocked:needs_injection_entry`**：引擎**没有**对局内注入对手个体的入口
> （`reset(individuals=…)` 只按**玩家**队伍位次解析，实测对手侧 `panel` 恒为 `{}`）。
> 上表第三条**不是**一个入口，而是直接改隐藏真值字段，用来证明公开面不读它 ——
> 不猜、也不静默跳过。**已知连带影响**（如实断言）：`battle_uses_panel_scale` 是「本局有人带快照」
> 的全局展示口径，注入后 UI 的 `stats_source` 由 `species-race` 变 `species-panel`
> （那是**物种面板**，不是个体真值）。
