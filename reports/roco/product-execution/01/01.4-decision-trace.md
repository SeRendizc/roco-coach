## 2 · `history` / `event_seq` / `decision_id` 三者的**确切**关系

```
decision_id(决策点)        = <match_id> : v<state_version>          ← 引擎派生（env.decision_id_of）
event_seq(第 i 条事件)     = i                                     ← state.events 的 0-based 下标
history[k] 记录的是「第 k 次决策**结算完之后**」的一行：
    history[k].state_version = 该回合结束后的事件总数
    history[k].events        = 该回合的事件（按发生顺序）
    history[k].pre_observation_hash = 决策**前**那份 observation_for 的哈希（16 位十六进制）
⇒ 反推该决策点的版本：
    version_before = history[k].state_version - len(history[k].events)
    decision_id    = <match_id> : v{version_before}
```

**实测**：上表三回合的反推都等于真实值（`all_derived_versions_match = true`）。

**注意（这是一处缺口）**：`history` 行里**没有** `match_id` / `decision_id` 字段
（`decision_id_is_derivable_not_recorded = true`）。链接是**可推导**的，不是**已记录**的 ——
要用它的人必须自己拿 `match_id` 去拼；这一步目前没有任何判据守着（§3 第 2 条）。

## 3 · 暂时做不到的边界（照实写，不粉饰）

| # | 边界 | 具体是什么 | 影响 |
|---|---|---|---|
| 1 | `history` 只存**哈希**，不存观察载荷 | `pre_observation_hash` = `_obs_hash(observation_for(...))[:16]`，载荷本身没落盘 | 回放能证明「同一条观察序列」，但**不能**从记录里恢复当时的公开面内容；要恢复必须重放重算 |
| 2 | `history` 里没有 `match_id` / `decision_id` | 见 §2 | 「同一 decision_id 的 UI/工具/回放对照」今天是**推导出来的**，不是记录里直接读出来的；跨局混记录时没有任何字段能拦住（Node 侧靠 session 的 `battle_id` + 回执 `match_id` 守卫顶住，见 `01.3-reveal-and-contract.md` §6） |
| 3 | **自由动作不进 `history`** | `step_free`（PVP 魔法 / 背包物品）明确不写 joint history（`env.py:1083` 注释：「那不是一回合」） | 自由动作那一刻的观察**不在** `history` 序列里；`observation_trace` 同样少这一条 ⇒ 01.4 的「同一观察序列」在自由动作上是**断的**。这是既有设计（不占行动≠一回合），本轮**没有改**，如实登记 |
| 4 | 浏览器一跳没有读数 | 前端预览层 / 「已见阵容」入口属分计划 02（`src/client/roco.js` 不在 01 写域） | 本文的「UI」= `env.ui_public_view` 这一层 + Node `publicView` 白名单；**不是**页面 DOM |
| 5 | Node session 不存 `history` | `sessions` 只存 `state` + `match_id/state_version/rules_version`（01.2 起的四元组） | 服务端能按 `state_version` 对齐规划与战况，但**不能**从 session 里直接读「上一次决策的观察哈希」——要读得走 state 里的 `history` |
| 6 | `MatchRecord` 没有 `match_id` | `record_fields` 里没有它（`record_has_match_id_field = false`） | 「这一份回放记录属于哪一局」只能靠 `seed + team_a/team_b + snapshot_fingerprint` 反推，**不是** `match_id`。这是 01.2 契约尚未铺到 `MatchRecord` 的缺口 |
