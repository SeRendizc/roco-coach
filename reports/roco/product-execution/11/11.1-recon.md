## 2. 断点清单（每条给证据）

### P1（最硬）不带 `state_version` 的会改状态请求**照样 200 并推进**
- 证据：隔离实例实测 `POST /api/roco/battle/advance {battle_id, auto:true}`（**无** `state_version`）⇒ `HTTP 200 ok=true sv 5→10 turn 2→3`；
  对照：同一条请求**带**旧版本 ⇒ `409 stale_state`。
- 代码：`src/server/roco-service.js:2451-2452`「只在调用方**明确带了**版本时检查（老客户端不带 ⇒ 行为不变）」。
- 影响：真人试用时任何脚本/旧页面/重试都能重复结算；这正是 10 的 **Q4**（已裁决 fail closed），**10 未开工** ⇒ **今天仍是敞口**。

### P2 刷新/崩溃即丢局
- 证据：`src/client/roco.js:72-104`（`battleId`/`view` 只在内存；全仓 `setItem` 无 battle 键）；
  `roco-service.js:1958/2010`（`sessions` Map + `stop()` 清空）+ `:78 IDLE_STOP_MS=5min`。
- 影响：试用者"刷新一下"= 这局没了，且服务端会话成为孤儿。10 的 R1/R3 **未落地**。

### P3 两档规则版本混用，必须按 `rules_version` 隔离
- 证据：练习局 `rules_version=roco-world-s4-2026-09-10/legacy_sim_v1`；六宠局（`mobile_s4_candidate_v3`）走另一档
  （对照 `roco-service.js:2291-2292` 只在 v3 下注入 `STANDARD_PVP_UNVERIFIED_OVERRIDES`）。
- 影响：跨局记忆（`xiaoya-memory-v1`）、建议、复盘若不分档，会把练习局经验带进候选规则局（对照 10.4「版本绑定回放」）。

### P4 `/api/coach` 没有服务端新鲜度硬闸
- 证据：`index.js:945-949` 只用 `stateToken` 做**缓存身份**；缺 `stateToken` 时"不进缓存、不合并"但**仍会作答**（本轮实测：无 token 也 200）。
- 影响：页面侧有 `rocoPlanFreshness`/`rocoHintStale` 闸，服务端没有；脚本调用方可以拿旧局面要建议。

### P5 `state_version` 是**事件计数**，不是回合号（可理解性）
- 证据：一手行动 `state_version 0→5`（5 条事件）、六宠局 `1→6`；`roco/src/roco_env/env.py:832` 每次 `_bump` +1，
  `:4167-4175` 断言 `state_version == len(events)`。
- 影响：玩家界面 `roco.js:901` 写「本局状态版本 5」——一跳 5 会让外行以为"打了 5 回合"（11.4 的可理解性项）。

### P6 注释引用已陈旧的判据文件
- 证据：`src/client/roco.js:353`「反证（三条，写在 `tests/roco-memory-merge.test.js`）」，但该文件**不存在**
  （`Get-ChildItem tests -Filter '*memory*'` 只有 `roco-memory-three-classes.test.js`）；合并行为实际覆盖在
  `tests/roco-xiaoya-context.test.js:1278` 附近。

### P7 共享树上有一条红是**他人 WIP**，不是链路断裂
- 证据：共享树 `node --test tests/roco-box-loadout.test.js` ⇒ **16 pass / 1 fail**（`③e 保存要把这四个写进共用记录…`，
  `AssertionError: 共用记录里要有 pet_000012 → 玩家挑的四个（实际 {}）`）；
  **同一判据在隔离副本(HEAD `45fa2270`)** ⇒ **17 pass / 0 fail（exit 0）**。
- 团队事实：`git status` 里 `src/client/loadout-store.js` 被标记为 modified（他人 05 的在飞改动）。
- 结论：候选必须**钉 commit**；取证一律在副本上做（这正是 11.6 的口径）。

### P8 物种级 / 实例级 id 两套并存
- 证据：`/api/roco/roster` 返回 542 行**物种级**（`pet_id`）；盒子/工坊走**实例级**（`own-XXXX`）；
  开局 `battle/new` 两种都收（`resolveBattleTeamIds`，本轮用 roster 的 `pet_id` 开局成功）。
- 影响：跨页传 id 的地方（配队→开局→复盘→记忆）要一直说清"这是哪一种"，否则容易把"我有 48 只"说成"542 只"（
  `index.js:234-243` 的 `pool_summary` 注释里已有一次真实错话记录）。
