## 4 · 必做反例①：同一公开伤害由两种个体配置都能解释 ⇒ 两者都保留（真引擎读数）

探针（`probe-03.3-engine.py`，exit 0）：
1. 六宠 PVP 真开一局，推进到**对手打出伤害**那一回合 —— 公开伤害 **319**（`skill_000340`，第 2 回合）；
2. 在同一回合、同一动作下**只换对手的个体面板**重放（`copy.deepcopy` 状态 + `battle_advance`，引擎真结算）：

```
基准重放（物种面板）            = 318
匹配配置（spa+4/spd-4 / spa-4/spd+4 / spd+6 / hp+10 / def+4 / def-4 / spa+8/spd-8）
                              = 318 318 318 318 318 318 318   ← 7 种配置都解释得通
敏感配置（atk+1 / atk+2 / atk+4） = 320 321 325                ← 对照：改攻击的确实变了
```

⇒ 「同一公开伤害由两种个体配置都能解释」**在真引擎上成立**，而且这个相等**不是恒等**（敏感组证明）。
Node 侧把 7 种配置作为情景注入 ⇒ 更新结果 `multi_solution: true`、**7 个情景全保留**、每个带来源与假设标记、
候选写明「未核实：哪一种是真身」，**该候选没有被排除**。
反向控制：把它声明成 `exhaustive:true` 且只给一套「一条都不相容」的情景 ⇒ 这时才排除，且排除理由带伤害读数的证据 ID。

**保真度如实登记**：重放的基准配置得 **318**，而实战那一手是 **319**（差 1 点，疑为面板经序列化/反序列化往返的
浮点精度差）。所以反例**不去复现实战那一个数字**，而是在**同一条重放管线内**比较两种配置（两者都是引擎真结算）；
注入情景的伤害区间按这个 ±1 的保真度写成 `[318, 319]`，来源写在情景行里。原始读数见
`raw-03.3-engine.json#counterexample.replay_fidelity`。

## 5 · 缺口#1（F-03-2 清单第 2 条）：白名单逐项覆盖 + 两向变异 red-proof

**原判据**：只查「每组非空 + 隐藏清单含 moves」，而注释声称「每一项都必须出现在上面用到的字段里」⇒ 注释与判据不一致。
**现在**（`03.3-缺口#1` 用例）两向可计算：
① 夹具/适配器真的用到的键 **⊆** 白名单；② 白名单每一项要么被用到、要么在
`PUBLIC_FACT_FIELDS_OPTIONAL` 里**点名**（`species_id` 别名 / `revealed_event_seq` / `source` 等，各带理由）；
③ 白名单与隐藏清单的交集**按组**判（`hp/max_hp/energy` 在「场上那只」公开、在「已亮明的后备行」隐藏 —— 跨组取交集会判错口径）。
