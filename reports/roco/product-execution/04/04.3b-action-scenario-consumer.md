### 2.1 真数据集成（03b 真产出 → 真引擎）

`p04-43b-rows.mjs`（真 view `raw-03.3-view-pvp.json` + 真 catalog/skillPool）⇒ `p04-43b-engine.py`：

```
03b counts: {"stay":4,"switch":5,"observed":7,"hypothesis":2}      ← 与 03b 报告一致
engine: 接受全部 9 条（battle_new 200 / 无 400）
  engine_scenario_ids = [stay:attack:pet_000007:skill_000340, stay:defense:pet_000007:skill_000286,
                         stay:pool:pet_000239, stay:pool:pet_000242,
                         switch:pet_000008:slot1 … switch:pet_000012:slot5]
  engine_enumerated = 3   actions = [防御, 换上第2位, 换上第3位]
  engine_unavailable = 逐条（枚举不出的技能 / 位次 / 整条情景）
  dropped_by_engine = []      recommended = 抓挠      coverage_detail.numerator = 4 / 4
```

**读数怎么解释**（⚠ 下面两个数是**本例读数**，不是稳定属性）：这一份 03b view 来自**另一局**留档，
与本探针的公开面不是同一局面，所以大部分技能/位次对不上 ⇒ 引擎如实报 `unavailable`（不是失败，是「不假装能算」）。

| 读数 | 本例（探针局面：喵喵队 vs 圆号鱼队） | verifier 复跑（局面不同） |
|---|---|---|
| `engine_enumerated` | 3（`防御` / `换上第2位` / `换上第3位`） | 4（多一个「仙人掌刺击」） |
| `dropped_by_engine` | `[]` | 2（换上第4/5位在束宽外） |

**这两个数依赖探针局面，不许当基线引用**。**结论级的一致**才是重点（两种局面都一样）：
全部行被引擎**接受、无 400**；**池情景零分支**；每条算不出来的都**逐条进 `unavailable`**；
`coverage_detail.by_seed` 分子分母如实（本例 4/4）。

**池情景（`stay:pool:*`，`slots: []`）没有产生任何分支** —— 因为重建状态里对手场上那只不是池候选，
引擎只枚举**当前场上那只**的合法动作。⇒ 04.2 的 **P3 残留**（用可学池替换规范配招假设）没做之前，
池情景只能作为「假设已登记、暂不展开」，这正是 03b 把它标 `learnable_pool_hypothesis` 的意义。
（verifier 复核：「P3 翻转面三处一致」——引擎侧「不假装能算」+ 消费侧原样带出 + `limitations` 点名。）
