## 2 · 修法（最小 + 按契约）

`src/coach/toolbox.js` 的 `safeObject` 段新增：

```js
const CONTRACT_STRING_KEYS=new Map([
 ['rulesversion',/^[A-Za-z0-9][A-Za-z0-9._-]{0,63}\/[A-Za-z0-9][A-Za-z0-9._-]{0,63}$/],
 ['rulesetid',   /^[A-Za-z0-9][A-Za-z0-9._-]{0,79}$/],
 ['matchid',     /^[A-Za-z0-9][A-Za-z0-9._-]{0,79}$/],
 ['decisionid',  /^[A-Za-z0-9][A-Za-z0-9._:-]{0,79}$/],   // <match_id>:v<state_version>
]);
function contractStringOk(normalized,value){
 const pattern=CONTRACT_STRING_KEYS.get(normalized);
 if(!pattern)return null;                 // 不是契约键 ⇒ 交给通用规则
 if(!/[\\/]/.test(value))return null;     // 不含分隔符 ⇒ 也交给通用规则（不新增拒绝面）
 return pattern.test(value)&&!value.includes('..');
}
```

**四条纪律（逐条都有判据）**：① 只白名单这**四个键**（其余照旧 fail closed）；
② 值必须匹配**各自格式**且不含 `..`；③ 通用规则（穿越防护）**不放宽** —— 非白名单字段含 `/` 照旧拒；
④ 白名单**只影响字符串叶子**，字节/深度/隐藏键/危险键的守卫一条不动。

> **一次自纠**：第一版把契约闸写成「格式不符即拒」，结果 `rules_version:'rv-1'`（既有夹具的短串）
> 被误拒 ⇒ 单测 **8 红**。改成「**只有带分隔符的值才走契约闸**」后 21/21 绿。
> 这也说明：白名单的职责是「放行合法含 `/` 的形式」，**不是新增拒绝面**。

## 4 · C-1 改钉（bench 行键期望过期）

**原断言逐字留档**：
```js
assert.deepEqual(Object.keys(entry).sort(), ['fainted', 'pet_id', 'slot'],
  '对手后备只应有位次/id/是否倒下；血量与配招是隐藏信息');
```
**独立运行时报据**：`actual = ['fainted','slot']` / `expected = ['fainted','pet_id','slot']`（见 §1 失败原文）。

**为什么是改钉不是改产品**：01.3（2026-09-30）起「**未亮明的后备不给身份**」是正确行为
（`env._bench_public_row` 只在有亮明事件时带 `pet_id`；`docs/roco/executive/01-PLAN.md:38`
「预览发生前不许提前泄漏阵容」）。原断言写在 01.3 之前，把「总会带 id」当成契约。

**最小修订**：`fainted` + `slot` **必选**；`pet_id` 只在亮明时**允许**；隐藏键（`hp`/`max_hp`/`energy`/
`loadouts`/`loadout`/`moveset`）**一律禁止**。
**反向控制（同一条判据里）**：拿真公开面**种一个 `hp:999` 的副本** ⇒ 同一把尺子必须抛
`不许带 hp` —— 证明放宽后**仍然抓得住泄漏**（不是把断言改成永真）。

## 6 · 归因与建议（给 STATE）

1. 这是**真缺陷**，且**只能靠真端到端读数发现**：单元测试里 `rules_version` 是短串（无 `/`），
   永远测不到；不设 `ROCO_PYTHON` 时那 5 条 e2e 全 skip，也测不到。
   ⇒ 建议（Lead 已定）：**每个工具都必须有一条真端到端调用读数**。
2. 安全守卫的「含 `/` 即路径」是**粗粒度**规则：它对路径类字段是对的，对**契约字段**是错的。
   本次只按「键 + 格式」开了四个已知字段；**若将来再加带分隔符的契约字段，必须同样按格式登记**
   （不许把通用规则放宽）。
3. `safeObject` 的这套白名单**不影响**隐藏信息与路径穿越防护（⑩ 里逐条钉住）。
