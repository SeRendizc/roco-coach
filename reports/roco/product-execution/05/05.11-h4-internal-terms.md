## 2 · H4-2/3：默认规则集 id 收敛到一处来源

### 2.1 改法（只动两个文件）

| 文件 | 改前 | 改后 |
|---|---|---|
| `src/client/roco.html:767` | `<code id="about-ruleset">roco-world-s4-2026-09-10</code>` | `<code id="about-ruleset">正在读取…</code>`（+ 一段说明注释） |
| `src/client/roco.js`（import 段） | —— | 新增 `import {RULESET_ID} from './type-affinity.data.js';` |
| `src/client/roco.js`（`MODE_MIRROR`） | `engine: {team_size: 3, ruleset_id: 'roco-world-s4-2026-09-10'},` | `engine: {team_size: 3, ruleset_id: RULESET_ID},` |

**为什么引用 `type-affinity.data.js` 的 `RULESET_ID`**：那个文件是**生成产物** ——
`scripts/roco/build-client-type-affinity.mjs` 从冻结真值 `data/roco/normalized/<ruleset>/types.json` 生成，
文件头逐字写着来源、sha256 与 ruleset_id；它本来就在页面模块图里（`roco.js → type-affinity.js → type-affinity.data.js`），
所以**没有新增模块、没有新增体积**。
**为什么模板连"默认值"都不留**：留一个默认值只会在两份不同步时**冒充**「这一局的规则快照」，
而这一格在验收里是必须等于引擎回执的那一格（`rulesetProblems`）。首屏给「正在读取…」，拿到 view 后由 JS 填真值。

**真渲染证据**（隔离实例、端口 0、`GET /roco.html`、收尾关闭）：

```
{"http":200,"bytes":45967,"aboutRulesetInner":"正在读取…","hasLiteralId":false}
```

⇒ 服务端**原样发出**的首屏 HTML 里，那一格是占位，**整个 HTML 里已经没有那个 id 的字面量**。

### 2.2 新增判据（`tests/roco-battle-panel-static.test.js` ⑥）

「⑥ 默认规则集 id 只许一处来源：模板不写死、页面脚本只引用生成的常量」——
它与该文件既有的 ①②（模板里不许写死设计稿的克制标记）**同一族**：模板写死的值看起来像真的，其实是 draft。
判据四条：模板那一格不含 id 且非空 · 页面脚本里**没有**该 id 的字面量 · import 的正是 `type-affinity.data.js` 的 `RULESET_ID` · `MODE_MIRROR` 引用它。**外加两条探测器反向自证**（对"写死模板 / 第二份字面量"必须为真）。

## 3 · 「真渲染」是怎么取的（口径）

`tests/roco-dev-drawer.test.js` 的新用例沿用本仓既有约定（`roco-page-ux` / `roco-standard-pvp-battle` 的抽法）：
从 `src/client/roco.js` **真源码**里把 `aboutVersion.textContent = …;` 那一行抠出来，
在 `new Function('view', …)` 里执行 ⇒ 得到的就是页面**真的会写进 `#about-ruleset` 的字符串**。
⚠ 抠之前**先剥注释**：那一行的旧写法按改钉规矩逐字留档在注释里，不剥就会先匹配到注释里的旧句
（这正是"判据不能把留档当成代码"那条纪律）。剥法与该文件既有的 `EXPERIENCE_SRC.replace(/\/\/[^\n]*/g,'')` 同款。
