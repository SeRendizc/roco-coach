## 1 · 契约定义（供 04.3 读侧 / 服务端 / 客户端共同引用）

### 1.1 区间对象

```
Range = {
  min:   number,   // 必填，有限数
  max:   number,   // 必填，有限数
  mean?: number,   // 可选，有限数（引擎只在 expected / first_second_margin 上给）
  scale?: string,  // 可选，非空字符串（量纲声明，例如 'one-ply-value'）
  note?:  string,  // 可选，非空字符串（人读说明，例如「不是胜率」）
}
```

**`min`/`max` 缺一即非法**（不是「补 0」「补 max」）——半截区间一律不搬、不猜。

### 1.3 三种存在状态（页面投影的 `plan_capabilities`）

`plan_capabilities` 对白名单里**除自己以外**的每个字段给一个值：

| 值 | 含义 | 对投影的要求 |
|---|---|---|
| `present` | 源回执里有这一项，且形状合规 ⇒ 已按契约搬进投影 | 键必须真的在投影里 |
| `absent` | 源回执里**没有**这一项（不是 `false`/`0`/空） | 键**不出现**；不许伪造 |
| `invalid` | 源回执里有，但形状不合本契约 ⇒ **不搬、不猜** | 键**不出现**；不许补形状 |

> 「拿不到」与「拿到了且是否定」是**两种可区分的状态**：`is_probability` 缺失 ⇒ `absent`；
> 引擎哪天真的写了 `is_probability:false` ⇒ 键出现、值为 `false`、标 `present`。判据钉了这两向（§4 ④）。

### 1.4 服务端接受规则（`validateChat`）

`number`（历史标量写法，兼容阶梯）**或** `Range` ⇒ 放行；
字符串 / 数组 / 布尔 / 缺 `min` 或缺 `max` 的对象 ⇒ `400 本回合规划无效：<字段>`。
**这不是把校验放宽成不校验** —— 非法形的反例仍在判据里（§4 ⑦，变异 M2/M4）。
**`null` = 「引擎没给这一项」**（Lead 裁决③，与 `undefined` 同等放行）。
适用范围是 `damage_preview` 里那些**页面回执恒写 `?? null`** 的可选字段：
`reason`（`src/server/roco-service.js:2979`）· `min`/`max`（`:2980-2981`）· `best_label`（`:2982`）· `foe_hp`（`:2985`）。
⚠ 只放行 `null`：对象 / 数组 / 数字 / 布尔**仍然 400**（判据 ⑨，变异 M5/M6 双向钉住）。
⚠ 现状边界（本次**不改**）：`reason: ''`（空串）是合法字符串 ⇒ 照旧放行。
⚠ **超出裁决③字面范围的一处**：裁决只点名 `reason`，我把同一原则一并用到 `best_label`/`min`/`max`/`foe_hp`
