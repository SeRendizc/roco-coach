# 换招（配招）真的能用了 —— 玩家路径 15/15（2026-09-25）

**一句话**：人类从第 2 轮就点名的「**配招这个你得修好**」，服务端早就接进引擎了，
但**客户端一直没有入口**。这一轮把入口做完，并**在真实页面里**验到
「我选的四个 → 请求体 → **引擎回执里那一只带的就是这四个**」。

## 一、玩家路径验收（`npm run roco:loadout-acceptance`，10/10）

```

✓ 01-选满六只         六个槽位里填上了 6 个（用模块自带的 ?team= 预填）
✓ 02-换招入口存在且可点
✓ 03-读到学习表并画出可选项   可选项 48 个（引擎学习表：原生/血脉/技能石）
✓ 04-能选出四个不同的技能     已选 skill_000645 / 000286 / 000633 / 000648
✓ 05-保存后卡片显示"你选的"   换招 你选的：蛰针、防御、飞断、尾后针   ← 显示**名字**不是 id
✓ 06-开局成功
```

## 二、路上修掉的四个缺陷（三个是"看起来做了、其实没生效"）

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | **`GET /api/roco/loadout/options` 路由漏了** | 服务方法与导出都在，请求落到通用 POST 分发 ⇒「仅支持 POST」，界面永远读不到学习表 |
| 2 | 客户端以为模块里有全局 `render()` | `ReferenceError: render is not defined`（模块只有 `renderTeam`/`renderAnalysis`，第 1393 行的局部重画用的就是这两个） |
| 3 | 保存后读不回来：`loadoutOf()` 用 `slot.species_id` 当键，而保存用的是**解析出来的**物种 id | 保存成功、卡片仍显示"引擎规范配招"，开局也不带 loadouts（**两把不同的钥匙**） |
| 4 | 主线程按 `slot.species_id` 过滤队伍 | 那个键不存在 ⇒ loadouts 被整批滤掉 |

## 三、一次被架构判据拦下的错误（值得单独记）

我最初的方案是让**服务端在 `player.slots[]` 里补 `species_id`**（页面要用它判"持有"、并把配招按物种交给引擎）。
`tests/roco-workshop.test.js` 的「**两层分界**」判据当场判红：

> `player` 段里没有工程键、没有 id 形状的展示值（id 属于 `dev` 段）。

**那条规则是对的**：我把它回退了，改成**页面按名字在持有名单里唯一匹配**解析物种
（图鉴里 62 个重名 + 名单自身的「棋契陛下」一律**不猜**，对不上就不给换招入口）。
判据 ① 现在钉的就是这条口径：`player` 段一个工程键都不许有 + 名字索引必须删掉重名 + 主线程走同一条解析。

## 四、顺带修掉一个状态码缺陷

`startBattle` 原来把**任何**引擎失败都映射成 **502**，而开局失败几乎都是**请求数据的问题**
（引擎的 `validate_team` 逐条判：队伍规模、配招里学不到的技能……）。那会让页面把
「这一招它学不到」显示成「规则服务出问题了」。现在与同族的 `advanceBattle` 对齐：
`unsupported_effect → 422`，其余 `→ 400`。（真的服务不可用在上游 `ensure()` 已经是 503。）

## 五、判据

`tests/roco-loadout-ui.test.js` **5/5**：
① 公开层不带工程键 + 名字唯一匹配（含"重名必须删掉"）；
② 换招路由存在、是 **GET**、且排在 CSRF 网关之前；
③ 引擎真的按换招开局（公开视图里的 `loadouts` 就是那四个）；
④ 非法配招被**引擎**拒（400，fail closed，不是这一层说了算）；
⑤ 客户端四条硬约束（只在持有的槽位给入口、恰好四个才保存、随 `emit` 交出去、开局按队伍过滤）。

相关套件：`roco-loadout-ui` + `roco-workshop` + `roco-page-ux` + `roco-box` = **84/84 通过**。
浏览器验收 `scripts/roco/browser-loadout-acceptance.mjs`（npm 入口 `roco:loadout-acceptance`）。

## 六、边界

- 只有**持有**的槽位有换招入口：按需推算的物种没有可核验的学习表，不给入口（如实的能力边界）。
- 重名物种（名字对不上唯一物种）**不给**换招入口 —— 页面上会少一个按钮，而不是把配招交给错的那一只。
- 保存的是 `{物种 id: [四个技能 id]}`，合法性**由引擎判**（这一层不判技能池）。
- 这份验收要联网（模型不参与，但开局要走真引擎）+ 本机 Chrome；不属于 24 套离线门禁。

# 补记：**每个技能都对准那只精灵**（人类 2026-09-25：「拿不准就去查」）

## 一、改成"去查"，不再靠页面猜

原来的实现是：页面按**名字**在持有名单里唯一匹配 → 得到物种 id → 拿它去查学习表。
按人类口径改成**去问引擎**：

1. 页面优先拿**持有实例 id**（`own-XXXX`，盒子里的那一只）→ `GET /api/roco/loadout/options?pet=own-XXXX`；
2. **服务端**用引擎的 `resolveBattleTeamIds` 把实例解析成物种（页面不猜）；
3. 换招保存的键 = **引擎回执里的 `pet_id`**（"这份学习表属于哪一只"的唯一证据），
   页面解析出的物种只用来找入口；
4. 引擎回的 `pet_id` 与页面解析不一致时，**如实记** `data-tw-loadout-mismatch=yes`（判据/验收读它）。

界面上还**把这份池子属于哪一只写在脸上**：「铠甲虫 学得到 48 个技能（按你盒子里的那只查的）」。

## 二、逐只对齐的真机证据（当时验收 14/14；现为 15/15，见第四节）

| 槽位 | 物种（引擎回执） | 可学技能数 |
|---|---|---|
| 第 1 只 铠甲虫 | `pet_000012` | **48** |
| 第 2 只 音速犬 | `pet_000062` | **44** |

```
✓ 05b-第二只也读得到自己的池子   音速犬 学得到 44 个技能（按你盒子里的那只查的）
✓ 05c-两只的物种不同（不是同一份池子）  第一只 for=pet_000012 / 第二只 for=pet_000062
✓ 05d-引擎回的物种与页面解析一致       data-tw-loadout-mismatch=no（via=instance）
✓ 05e-两只的池子分别按只给          第一只「铠甲虫 48 个」/ 第二只「音速犬 44 个」
```

`via=instance` 说明走的就是"拿实例去问引擎"这条路；**两只的数量不同**（48 / 44）说明池子是按只给的，
不是一份共用的清单。再加原有的 09（**引擎回执里那一只带的就是我选的四个**），
整条链上"技能 ↔ 精灵"的每一次对应都有机器证据。

## 三、判据

`tests/roco-loadout-ui.test.js` **6/6**，新增 ⑥：
按**持有实例**查 → 每条技能必须有 `skill_\\d+` 的 id 与名字 → **不同精灵的学习表必须能区分开**（数量/内容）
→ 页面必须优先按实例查、键必须用引擎回的 `pet_id`、不一致必须如实记录。
验收脚本 `browser-loadout-acceptance.mjs` 从 10 项扩到 **14 项**。

## 四、六只全量对齐（15/15）＋ 把这条路径挂进门禁

人类的原话是「**每个技能都要对准那个精灵**哈 你要拿不准就去查」。上面那节只量了**两只** ——
两只不同不足以排除"其余四个槽位共用一份池子"或"第 3 只开始串味"。现在**逐槽位**（0…5）打开换招，
每只都记下引擎回的 `pet_id` 与可学技能数，并断言六只的组合各不相同：

| 槽位 | 物种 | 引擎 `pet_id` | 可学技能 |
|---|---|---|---|
| 1 | 铠甲虫 | `pet_000012` | 48 |
| 2 | 音速犬 | `pet_000062` | 44 |
| 3 | 仪式巨像 | `pet_000100` | 54 |
| 4 | 雪影娃娃 | `pet_000112` | 50 |
| 5 | 皇家狮鹫 | `pet_000118` | 48 |
| 6 | 化蝶 | `pet_000124` | 49 |

```
✓ 05f-六个槽位逐只对齐（各对各的池子） — 逐槽位：铠甲虫 学得到 48 个=pet_000012/48个 | 音速犬 学得到 44 个=pet_000062/44个
  | 仪式巨像 学得到 54=pet_000100/54个 | 雪影娃娃 学得到 50=pet_000112/50个 | 皇家狮鹫 学得到 48=pet_000118/48个 | 化蝶 学得到 49 个技=pet_000124/49个
15/15 通过
```

判据 `05f` 的口径：`perSlot.length === 6`（六个槽位都真的读到了池子）＋ 六组 `(pet_id, 数量)`
**去重后 ≥5**（留一个位置给"两只恰好同物种同数量"的合法情形）＋ 逐槽位 `mismatch ≠ yes`
（引擎裁决的物种与页面解析不许对不上）。**注意 5 号槽位是 48 个、与 1 号槽位同数量但 `pet_id` 不同** ——
判据按 `pet_id:数量` 去重而不是只按数量，正是为了不被这种巧合骗过。

**同时把这条路径挂进门禁**：`loadout-acceptance` 加进 `verify-release.mjs` 的套件清单（24 → **25 套**），
理由写在套件的 `why` 里 —— 这是人类从第 2 轮点名、又在 2026-09-25 追加口径的能力，
不该只靠"有人记得手动跑一次"。判据少了就会红，而不是悄悄退化。
