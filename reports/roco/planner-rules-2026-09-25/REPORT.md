# 生产 planner 提示接上「按名字查图鉴」：实测（2026-09-25）

> 起因（人类点名的第二条交付「agent 真的会用工具」）：agent 臂在 622 只图鉴上 **0/120 → 120/120**，
> 靠的是 `AGENT_TOOL_SYSTEM` 里那两条规则；而**生产发出去的提示里没有它们** ——
> 玩家问图鉴时一直是**代码侧** `codexFactAsk` 在兜（关键词命中就由代码强制调 `query_rules`），
> agent 自己不会查。这一份只写实测数字与结论，不写过程。

## 0. 先把「生产提示」变成可以被测评引用的东西

`src/server/index.js` 里那段提示原来是**一行拼接字面量**。后果有两个：测评只能"再抄一份"
（`scripts/roco/agent-trajectories.mjs` 与 `src/coach/shadow-tools.js` 之间就正是"两份拷贝"的关系），
以及**提示词没法钉摘要**（谁顺手改通顺一句都不会被发现）。

现在搬到 `src/coach/planner-prompt.js`，测评用 `--arm deepseek_product` **引用生产那一份**：

- `PLANNER_PROMPT_DIGEST` = `fbdcff00…`、`PLANNER_PROMPT_CHARS` = **404**（`rules:'off'` 时）。
- **搬运没改行为**是机械证明过的：把改动时删掉的那几段字面量拼回来，与模块 off 档
  **逐字节相同**（404 字、摘要一致），判据 ① 把这两颗钉子常驻。
- 教训：抽取脚本一开始读的是 `git show HEAD:src/server/index.js` —— 那是**旧提交**（478 行、
  提示还在 382 行、没有 `SUFFICIENCY_RULE`）。按它抽会生成一份**过时提示**，而编译、判据、
  验收全都不报错。改成读工作区文件。**"拿旧提交当生产代码"与"看起来做了其实没生效"同形。**

## 1. 图鉴能力（契约 B：按名字查一次即算通过）

命令：`--arm deepseek_product --pool catalog --contract B --limit 40`（同一切片、同一模型、只切口径）

| 口径 | 通过 | 行为 |
|---|---|---|
| `off`（当时的出厂默认） | **0/40** | **一次都不调**（判据原文：`没有调用应当调用的工具 query_rules`） |
| `catalog`（末尾追加两条规则） | **40/40** | 每条都调 `query_rules{"kind":"pet","name":"喵喵"}` |

**最小改动就够**：只把两条规则**追加在原提示末尾**（原提示与工具词表一个字不动）即可。

**试过但没采纳的两版**（不做没有证据的改动）：① 把规则**前置**到最前面并写明"覆盖后面的
「默认是停止」"；② 连**工具词表**一起换成 roco 那套、撤掉「不得要求其他工具。」。
两版与最小版在**契约 A** 上表现完全一样（都是 1 次按名字的调用、0/40），**分不出差别**，所以不采纳。

## 2. 契约 A 为什么四类臂都是 0（与我自己的两次误读）

契约 A 要的是「先按名字查 id、**再用 pet_id 查事实**」的**两步**，最多 3 次调用；
本轮四条臂都只有第一步。已发布记录里本来就写着：`deepseek_agent` / **契约 A = 0/120**、
/ **契约 B = 120/120**（`reports/roco/catalog-scale-2026-09-25/REPORT.md`）。

**两次必须记下来的误读**（都是我读产物读错了，不是模型的问题）：

1. 我用 `(row.tool_calls||[]).length` 统计调用次数，而产物里的字段叫 **`trace`** ——
   于是四条臂都被我读成"40 条一次都不调、全部 stop"，并据此推断"末尾追加压不过「默认是停止」"、
   "工具词表是拦路虎"。**这两个结论都没有证据**，是我拿错键算出来的。
2. 由此我一度以为"对照组也 0/40 ⇒ 环境/密钥坏了"。真实情况是：**该臂在契约 A 上本来就该是 0**
   （记录写着 0/120），而它在契约 B 上是 40/40。

**规矩（这一轮学到的）**：读数之前先把产物字段名打出来核对；对照臂的结果**要拿已发布数字比**，
不能只看"是不是 0"。

同一份代码、同一个服务，只切 `ROCO_PLANNER_RULES`（云臂 deepseek-flash，49 例各跑一次、0 报错）：

| **调用次数正确率** | 0.571 | **0.633** | **+0.061** |

## 4. 结论（按实测翻的默认）

**默认从 `off` 翻成 `catalog`**，显式 `ROCO_PLANNER_RULES=off` 仍然**干净地关掉**
（判据钉着 off 档与搬运前逐字节相同）。依据是上面两处实测同时成立：
图鉴能力 0/40 → 40/40，而 49 例上「不该查却查了」**一点没涨**、有据回答率没掉。

**未知值回落出厂默认**（而不是像 `judgeMode()` 那样回落 `off`）：这个开关是用来**关掉一项能力**的，
回落 `off` 意味着一个拼写错误会**悄悄拿走**玩家已经看得见的能力；回落默认最多是多带一段提示。
判据 ④ 同时钉住三件事：不设变量 = `catalog`、显式 `off` = 搬运前那一份、未知值 = 出厂默认。

**判据**：`tests/roco-planner-prompt.test.js` **7/7**（含三条必红反证：假工具名必须被抓住、
显式 off 必须回到原字符串、出厂默认与 off 必须是两份不同的提示）。
**产物**（都在本目录下，随报告一起存档）：`B-off.json`、`B-catalog.json`、`B-append.json`
（契约 B 三条臂的完整回执）、`eval-summary-off.json`、`eval-summary-catalog.json` 与
`eval-raw-off.json`、`eval-raw-catalog.json`（49 例两档的原始回执）；
`reports/roco/shadow-replay-slice40-deepseek_product.json`（契约 A 切片，含当时的臂身份；
产物名带 `-slice40` 是 2026-09-25 新加的防覆盖规则 —— 在那之前，一次 `--limit 5` 的冒烟跑
会把已发布的 442 条参考臂产物覆盖掉）。
